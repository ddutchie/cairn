# v0.6.1 — Idea Flow improvements

## What's new

### Features

**Group node**

A new `group` node type renders a resizable, colour-coded container on the canvas. Double-click a group to rename it and pick from five accent colours (blue, purple, green, orange, red). Groups are also available to the AI via `create_idea_flow_node` with `type: "group"`.

**Drag-based group membership**

Dragging a node onto a group automatically nests it — the node snaps to a position relative to the group and moves with it, constrained to stay within the group's bounds. Dragging a node out of a group removes it from the group and places it at exactly the canvas position where you released it. Membership is also re-evaluated when a group is resized: nodes that fall inside the new bounds are added; nodes outside are released. The smallest enclosing group wins when multiple groups overlap.

**Auto-layout — Arrange button + `layout_idea_flow` MCP tool**

A new **Arrange** button in the canvas toolbar runs a Dagre left-to-right graph layout across all nodes, persists the new positions, and fits the viewport. Useful after building a canvas manually or via AI when nodes have piled up.

The same logic is available as a new MCP/AI tool `layout_idea_flow` (supports `direction: "LR" | "TB"`). The AI system prompt now instructs the model to call this after bulk-creating nodes.

**URL metadata fetch**

The URL node edit modal now has a **Fetch** button next to the URL field. Clicking it fetches the page's Open Graph title and description from the main process (no CORS restrictions) and populates the fields automatically. The URL node also shows a "Double-click to add URL" hint when empty.

**Promote idea → task**

Each idea node now shows a small task icon button. Clicking it creates a board task from the idea's title and body (placed in the first non-done column), replaces the idea node with a `task_ref` node at the same position, and rewires all connected edges to the new node.

### Fixes

**Undo/redo — history no longer cleared on own writes**

All user-initiated DB writes (board, notes, Idea Flow) now mark themselves via `ownWriteGuard`. The `db:changed` listener in the app shell checks this guard before clearing the history stack, so the WAL poller firing after a move, drag, or delete no longer silently wipes undo history. Previously, actions like moving a card between columns appeared to have no undo because the history was cleared within ~1 second by the next WAL poll event.

**Undo/redo — group delete now restores group and all children**

Deleting a group node previously pushed one undo command per node (group + each child as separate steps). The group was also missing its dimensions and children were missing their `parentId` on restore, so undo produced a wrong-sized empty group. Now a single compound command captures the entire deletion atomically: undo recreates the group with correct size, then recreates each child with their relative positions and group membership. A `JSON.parse/stringify` deep-clone strips non-serializable React Flow internal properties before passing node data over the IPC bridge.

**Undo/redo — node drag position corrected on ungroup**

Dragging a node out of a group snapped it to the wrong canvas position. React Flow reports `node.position` in parent-relative coordinates when `parentId` is still set, even after `extent` is lifted. Fixed by reading `internals.positionAbsolute` from the React Flow internal node store, which is always in canvas space.

**Undo/redo — node falsely re-captured by group after drag**

After dragging a node outside a group, the canvas silently re-nested it on the next drag. `computeGroupAssignments` skipped emitting a change when both the old and new `parentId` were `null` (the dragged node's `parentId` had been cleared in the snapshot), so the cleared `parentId` was never written back to React state. Fixed with a `forcedNodeId` parameter that always applies the cleared membership even when the computed assignment produces no change.

**AI Summary node — recursive graph traversal**

The Generate button now walks the entire connected subgraph transitively, not just direct neighbours. Previously, if you connected an AI Summary node to "Part C" which was itself fed by "Part A", "Part B", and "Test Idea", only Part C's own content was collected — the upstream nodes were invisible to the summariser.

The handler now does a full BFS from the summary node in both edge directions, collecting every reachable idea, note_ref, task_ref, and url node in the connected component. Other `ai_summary` nodes in the graph are skipped during traversal (they're peers, not source content) so chained summaries don't cause circular references.

**AI Summary node — no edit modal on creation**

Adding an `ai_summary` node from the Add Node menu or context menu no longer opens the edit modal. The node is a generator — its content is produced by the AI, not typed by the user. Double-clicking it also continues to be a no-op (unchanged from v0.6.0).

**task_ref deep link**

The external link button on a task reference node now opens the board *and* scrolls to the specific card, rather than just switching to the board view.

### Changes

- Undo/redo coverage expanded across all app areas:
  - **Board:** column create, rename, delete (cards recovered), reorder; card reorder within column; card restore from archive; card move to project
  - **Notes:** restore from archive; link note to task
  - **Idea Flow:** node drag (position + group membership); group resize; auto-layout (Arrange); promote idea → task (full reversal)
- `layout_idea_flow` added to the MCP tools list in Settings
- OpenCode dev config (`opencode.json`) now points to the local build bundle (`node dist-mcp/mcp-server.bundle.js`) instead of the installed app binary, so `npm run compile` is sufficient to pick up changes during development
