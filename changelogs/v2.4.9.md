## What's new

The AI assistant can now find task cards by meaning, not just exact keywords.

### New

- **Semantic search over tasks.** Semantic (embedding-based) search previously covered only notes. It now covers **task cards** too: a conceptual query like "what's blocking the login work" can surface a card titled "Auth token refresh bug" even with no shared words. A new `search_tasks_semantic` tool is available to the AI assistant and MCP clients, mirroring `search_notes_semantic`. Cards are embedded (title + description) into a dedicated on-device index, kept current automatically as you create or edit cards, and included in a full re-index from Settings → Embeddings.
- **Tasks now appear in the Knowledge Graph's semantic links.** The graph's meaning-based ("semantic") connections previously joined notes to notes only. They now span tasks too — so you'll see **task↔task** links between related cards and **note↔task** links connecting a note to a card about the same topic. These use the same semantic edge type (toggle it in the graph's edge filters) and are recomputed automatically when you create or edit a card.
- **See your codebase's architecture.** The Agent view has a new **Architecture** tab that visualises the codebase index the coding agent builds. It shows headline stats (files, symbols, references), a breakdown of symbols by kind (classes, functions, methods, interfaces…), and the indexed files — expand any file to see its symbols, and click a symbol to see its signature, docstring and call graph (what it calls, and what references it). A **Reindex** button rebuilds the index on demand. Switch to **Graph** view for an interactive, zoomable file-dependency diagram (nodes are files sized by symbol count, arrows point from a file to the files it references); click a node to see its symbols. When you're editing, a contextual **Architecture panel** on the right of the editor shows the open file's symbols and each one's callers/callees — collapsible so it doesn't crowd your code.

### Under the hood

- Task-card embeddings live in a separate `task_embeddings` table (parallel to `note_embeddings`) rather than a shared table — the notes index has a foreign key + composite key to `notes`, so reusing it for cards would have required a risky table rebuild. The notes pipeline is untouched. Cards are ranked over the whole workspace corpus and sliced afterward (never a per-batch cut), and reindexed on card save so recent cards are always findable.
- Knowledge-graph semantic edges now pool note and card section vectors into one corpus in `computeSemanticRelationships`, so task↔task and note↔task pairs fall out of the same all-pairs pass — no new edge type or renderer changes needed (card nodes already exist; graph pass-6 only checks both endpoints are present). Card save triggers a scoped semantic recompute, mirroring note save.

### Fixes

- **Archived tasks no longer appear in semantic search.** Archiving a card (including "archive all done") now removes its embeddings and its cached graph relationships, and semantic task results are additionally filtered to live cards — so a completed/archived task can't resurface in meaning-based search or linger in the knowledge graph. Restoring a card re-indexes it so it becomes findable again.
- **A changed embedding model now re-indexes tasks too.** The "reindex needed" check previously only looked at note embeddings; it now also flags a mismatch in task embeddings, so switching models correctly prompts a full re-index of both.
- **The AI assistant can actually run semantic task search.** The `search_tasks_semantic` tool was registered but the desktop chat dispatcher didn't route it, so calls errored as "unknown tool" — now wired up alongside `search_notes_semantic`.
- **Search palette filters are easier to tell apart.** The search overlay's filter row mixed two different kinds of filter in identical-looking pills — content type (All / Notes / Tasks) and project scope (your project names). They're now visually distinct: content-type stays as rounded pills under a "Type" label, and project filters are squarer, surface-filled chips under a "Project" label, separated by a divider — so it's clear they're two independent axes.
- **Semantic search works again from the standalone MCP server.** External agents connecting through `cairn-mcp` (which runs on its own Node runtime with no Electron) hit an "Electron failed to install correctly" error when calling `search_notes_semantic` / `search_tasks_semantic`. The embeddings-settings cache module was statically importing `electron`, which throws outside the app; it now resolves the settings path without Electron (falling back to the same workspace scan the MCP server already uses), so semantic search runs whether Cairn is open or not.
- **Folders that differ only in capitalisation are now merged.** Notes filed under, say, `Mobile` and `mobile` (or `Mobile/AI` and `mobile/ai`) were showing up as two separate folders in the notes sidebar. They now collapse into a single folder, matching case-insensitively — the first casing seen becomes the displayed name. The AI assistant's `list_folders` tool dedupes the same way, so it no longer reports the same folder twice.
- **Agent view resize handles are clearer.** The divider above the terminal panel had an invisible grab strip that let file-tree text bleed across the border line; both the terminal and file-tree resize handles are now solid strips with a centred line that brightens to the accent colour on hover, so it's obvious where to grab and nothing renders in the gap.
- **The codebase indexer no longer indexes build output.** The indexer only skipped a fixed list of folder names, so it walked into `dist-app` (the packaged `.app` bundle with thousands of minified JS files) and other `dist-*` output dirs, polluting the index. It now skips any `dist`/`dist-*` folder, macOS `.app`/`.framework` bundles, and a wider set of build/cache dirs (`coverage`, `.turbo`, `__pycache__`, `Pods`, etc.). Reindex from the new Architecture tab to clear out any already-indexed build files.
- **Cleaner symbols in the Architecture view.** Language keywords and built-in type names (`function`, `return`, `string`, `boolean`, `type`…) were being extracted as symbols, so they appeared as bogus entries and as fake "calls / uses" in the call graph. They're now filtered out, both as symbols and as reference targets. A symbol's signature panel also no longer clips its first/last line.
- **Far fewer false connections in the Architecture graph.** The indexer counted any identifier that merely shared a name with a symbol as a "call" — including property accesses, local variables, single-letter names and even the test global `it` — which exploded the dependency graph into a hairball. It now only records a reference when a name is actually *called* (`name(`), skips 1–2 character names, and skips generated/vendored/minified files (e.g. the bundled `mermaid-assets.ts`, `*.min.js`, `*.bundle.js`, `*.d.ts`, and anything marked `@generated`). The file-dependency graph now only draws an edge when the target name is defined in exactly one file, so an ambiguous name can't fan out to every file that happens to define it. On this repo that cut graph edges by ~80%.
