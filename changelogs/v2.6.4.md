## What's new

### Features

- **Slack's MCP server now connects.** Slack's remote MCP server (`https://mcp.slack.com/mcp`) forbids dynamic client registration, so it previously failed as soon as you tried to sign in. The MCP OAuth form now has optional *Client ID* and *Redirect URI* fields for servers that need a pre-registered app — paste the public client id of your Slack app and register the fixed `http://127.0.0.1:<port>/callback` redirect URL in Slack's OAuth settings. No client secret is needed (public PKCE, the same flow Anthropic's Slack integration uses). Existing public-PKCE/DCR servers (Canva, Figma, …) are unchanged.
- **Guided setup for pre-registered-app connectors.** Servers whose provider forbids dynamic registration (like Slack) now carry a "requires a pre-registered app" flag. Installing Slack from Browse Community marks it automatically: the form surfaces the Client ID / Redirect URI fields, and the "Sign in" button routes you to them instead of failing with an opaque *incompatible auth server* error. Custom HTTP services get the same Client ID / Redirect URI fields for pre-registered OAuth providers.

### Fixes

- **Tool calls no longer fail when the model drops a comma between arguments.** When an AI call to a tool like `create_page` (Confluence) or `ensure_note` produced *nearly*-valid argument JSON — most commonly a missing `,` between two properties, which surfaced as `Expected "," or "}" after property value in JSON` — the call failed and the model retried. Cairn now repairs a missing comma wherever a completed value is directly followed by the next key or element (covering string, number, boolean, and nested object/array values), then falls back to the same tolerant JSON parser used by the Vercel AI SDK and pi for any remaining structural slip such as a dropped `:`. As before, only *provably lossless* repairs are applied — decoded content always round-trips byte-for-byte, and genuinely broken JSON still surfaces a clear error rather than running with empty or guessed arguments.
- **A cut-off AI reply can no longer execute a half-built tool call.** If the model hits its output-token limit mid-call, the streamed arguments can be truncated in a way that still parses as valid JSON (e.g. `{"title": "…"}` when the model meant to pass more fields). Tool calls from a turn that ended with `finish_reason: "length"` are now never executed: the tool chip is shown as failed and the model is asked to re-issue with complete arguments.
- **The Tool Builder now honours Max output tokens = Auto.** It used to send a fixed 2048-token cap that could truncate long tool definitions mid-build. It now follows the same Auto semantics as the rest of the app: Auto sends no cap so the model finishes naturally, and a manual Max output tokens value is respected.
