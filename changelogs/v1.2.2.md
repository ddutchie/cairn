# v1.2.2

## What's new

### Features

- **Plan task list** — when the agent runs in Execute Mode from an approved plan, a collapsible task-list bar now appears above the chat input showing every `- [ ]` / `- [x]` item from the PRD's `## Tasks` section. A thin progress bar fills as tasks are completed. The panel defaults to collapsed (showing "N of M tasks completed" with an up-chevron) and expands upward to reveal the full list, matching the pattern used by other coding agents.

- **Live task check-off** — the execute-mode agent is now instructed to call `patch_note` immediately after finishing each task, replacing `- [ ]` with `- [x]` in the PRD note. A new `pi-agent:note-updated` IPC event fires from the main process after every note-write tool (`ensure_note`, `update_note`, `patch_note`, `append_to_note`) and delivers the fresh note content to the renderer so the task list updates in real time without waiting for a full DB sync cycle.

- **Bottom terminal pane** — a docked interactive shell pane now appears at the bottom of Agent View whenever the project has a code directory set. It spawns the user's login shell (`$SHELL` / `cmd.exe`) directly in the project's `codeDirectory` via a new `agent:spawnShell` IPC channel. Supports multiple tabs (labelled "Shell 1", "Shell 2", …), per-tab close buttons, a `+` button to open additional shells, and a drag handle to resize the pane height (80–600 px). Inactive tabs are CSS-hidden so scroll history is preserved. Reuses the existing `agent:input` / `agent:resize` / `agent:data` / `agent:exit` IPC channels — no new Electron-side streaming infrastructure required.

- **Agent empty state** — when no Cairn Agent session is loaded the right pane now shows a proper empty state: a Bot icon, a context-aware subtitle (explains when no code directory is set), an accent "New session" CTA button, and a list of up to 5 recent sessions with relative timestamps for one-click resume.

### Fixes

- **Tool chips stuck as spinners after step boundary** — `finalisePiMessage` closed the streaming message (`isStreaming → false`) but left any tool chips that were still `running: true` frozen as spinners. Fixed by forcing all `running` chips to `running: false` when the message is finalised, covering the case where `onStep` fires before the corresponding `onTool end` event.

- **Agent message text overflow** — long identifiers, file paths, and inline code in assistant messages overflowed the bubble container instead of wrapping. Fixed by adding `min-w-0 overflow-hidden` to the content bubble div, `break-words` to `<p>` and `<li>` elements in `MarkdownContent`, and `break-all` to inline `<code>` spans.

- **Agent empty state hidden** — the empty state rendered inside a `hidden` div because `pinnedIsActive` is `false` when no session is loaded. Removed the `hidden` conditional from the no-session branch — the branch is already guarded by `!persistentSession`.

- **Bottom terminal spawning two shells on startup** — React StrictMode's double-invoke of `useEffect` called `spawnShell()` twice before the first async call resolved. Fixed with a `spawnStarted` ref guard (same pattern as `initStarted` in `SessionMount`).

### Changes

- `agent:spawnShell` IPC channel added — spawns the user's login shell in a given `cwd`; reuses the existing PTY session map so all existing `agent:*` input/output channels work unchanged.
- `pi-agent:note-updated` IPC event added — fired from both `pi-agent:prompt` and `pi-agent:approve-plan` handlers after any note-write tool completes successfully; payload is `{ sessionId, noteId, content }`.
- `electron.piAgent.onNoteUpdated` preload bridge added.
- `electron.agent.spawnShell(cwd)` preload bridge added.
- Execute-mode system prompt updated: new step **3 — "Check off plan tasks as you complete them"** instructs the agent to `patch_note` the PRD after each task. Steps 4 and 5 renumbered from 3 and 4.
- `AgentView` layout changed from a flat horizontal flex to a vertical flex column — three-pane row on top, bottom terminal below with a `cursor-row-resize` horizontal divider between them.
- `TerminalManager.fitAll()` is not called for the bottom terminal — it owns its own `ResizeObserver` for refits, keeping the existing agent terminal fit path clean.

### Tool consolidation (LLM context reduction)

Reduced the MCP and chat tool surface from 47 MCP tools down to 32 (−15 net) by eliminating redundant tools and merging related operations:

- **Deleted 10 tools (phase 1):** `resolve_project`, `get_project_summary`, `list_recent_activity`, `list_notes`, `list_tasks`, `create_note`, `update_note`, `import_note_from_file`, `move_note`, `update_task_status` — replaced by `search_notes` / `search_tasks` (empty query = list all) and `update_task`
- **Merged 6 tools → 2 (phase 2):**
  - `archive_task` + `restore_task` → `update_task { archived: true/false }`
  - `block_task` + `unblock_task` → `update_task { blockedBy } / { unblockFrom }`
  - `create_project` + `update_project` → `upsert_project` (no `projectId` = create, `projectId` present = update)
- **Token savings** (gpt-tokenizer cl100k_base, tools + system prompt):

| Surface | Before | After | Saved |
|---------|--------|-------|-------|
| Execute (pi-agent) | 4,090 | 3,770 | −8.0% |
| Plan (pi-agent) | 2,154 | 2,059 | −4.4% |
| Chat | 5,102 | 4,328 | −15.2% |
| MCP | 3,623 | 3,000 | −17.2% |

- README, CONTRIBUTING, and cairn-site docs updated to reflect the new tool surface.
