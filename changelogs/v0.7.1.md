# v0.7.1 — Chat fix

## What's fixed

**AI chat — messages no longer disappear mid-conversation**

Sending a message could cause the conversation to reset in two ways: the user message would vanish as soon as it was sent, and the entire chat would clear again once the AI finished responding.

The root cause was in `hydrateFromElectron` — the function called on every `db:changed` event to keep the UI in sync with the SQLite database. That function was overwriting `chatMessages` and `chatThreads` from the database snapshot on every call, including during an active chat session. The SQLite snapshot has never included chat data (chat lives in `localStorage`), so every hydration replaced the in-memory message list with an empty array.

The trigger was the MCP WAL poller, which fires `db:changed` roughly once per second whenever the database file changes. Any AI tool call (reading context, creating a task, updating a note) modifies the database, which trips the poller, which hydrated and cleared chat state — while the conversation was still in progress.

Fixed by removing chat state from snapshot hydration entirely. `chatThreads` and `chatMessages` are managed directly by the store and persisted to `localStorage`; they are never owned by the SQLite snapshot and should not be touched by it.
