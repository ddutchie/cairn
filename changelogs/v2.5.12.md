## Fixes

- **Linking a note to a task can no longer delete the note.** `link_note_to_task` (and any metadata-only note write) rewrote the note's `.md` and, on a case-insensitive filesystem (macOS/Windows default), could misclassify the rewrite as a *move* and then delete the file it had just written — tombstoning the note. The trigger was a case-only difference between the note's stored folder/title and its on-disk path (e.g. a note filed under `Research` whose `.md` actually lives in a `research/` directory): the recomputed target path differed only in case, so `writeNoteFile` took the relocation branch and unlinked the "old" path — which is the same inode as the new one. `writeNoteFile` now compares the two paths by real file identity (resolving case + symlinks) instead of an exact string match, so a case-only difference is treated as an in-place rewrite. Same-location writes are also now done in place (durable: back up, truncate-in-place keeping the inode, `fsync`, restore on failure) rather than via temp-file + rename, so they emit only a `change` event and never race the cross-process file-watcher into deleting the row. Added regression tests for the case-only-folder scenario, in-place inode stability, crash-safety restore, and genuine relocations.
