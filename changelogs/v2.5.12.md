## Fixes

- **Linking a note to a task can no longer delete the note.** `link_note_to_task` (and any metadata-only note write) rewrote the note's `.md` via a temp-file + rename even when the file wasn't moving. A rename-over-an-existing-file swaps the file's inode, which the file-watcher (a separate process) sees as an `unlink` of the note's own path — and because that event is delivered asynchronously, it could arrive after the MCP write-lock had already been released, so the watcher tombstoned the note's row. `writeNoteFile` now writes **in place** whenever the resolved path is unchanged, emitting only a `change` event (never an `unlink`); the atomic temp-file + rename dance is kept solely for genuine relocations (a title or folder change). Added regression tests asserting an unchanged-path write keeps the same inode and a title change still relocates + cleans up the old file.
