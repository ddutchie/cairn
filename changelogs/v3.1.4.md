## What's new in Cairn 3.1.4

### Changed

- **The API protocol picker shows what your provider offers.** Once a provider's URL and model are set, the picker checks Chat Completions, Responses and Anthropic Messages for that model and labels each option ("available", "not for this model", "not offered"). The check sends requests the server rejects before generating anything (at most one token on a lenient server). If the chosen API isn't available, one click switches to one that is. For OpenCode the picker shows "Automatic" and which API the current model uses, because OpenCode serves each model over a single API.

### Fixed

- **Tool chips no longer claim a note was updated when it was only read.** After the tool consolidation, reads through the new `get_item` tool fell through to a generic fallback and rendered chips like "Updated note" for notes the AI merely opened. Read chips correctly say "Read note" / "Read task" again, and the same gap is closed for the other consolidated tools — deleting a note chips "Deleted note" instead of "Updated note", for example.
- **OpenCode models that need a different API now work.** OpenCode serves each model over exactly one API, and answered anything else with "Model does not support this protocol". Cairn now picks the API per model from models.dev, so models like muse-spark, GPT, Grok, Claude, Qwen, MiniMax and Gemini work on an OpenCode provider set to Chat Completions. Gemini models use Google's API, which the agent runtime gains through a small patch (`patches/@deepseek-ai+dsh-llm-pi-ai`); on OpenCode Go they're routed to its inference host, the only one that serves them.
- **Reasoning models on the Responses API no longer fail on their first turn.** With reasoning left on the default, Cairn sent `reasoning_effort: "none"`, which models such as muse-spark reject. It now sends no effort, so the model uses its own default.
