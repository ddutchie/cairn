## What's new in Cairn 3.0.3

### Added

- **Durable subagents you can talk to.** A new `delegate` tool starts background subagents that stay around as continuable conversations instead of one-shot runs (`electron/cordis/cordis-context.ts:139`). The model can send them follow-up work with `send_message`, interrupt a stuck turn with `interrupt_agent`, and find them with `list_agents` — and so can you: the chat and coding headers gain a subagent catalog showing each child's label, mode, and live activity, with a per-child message box and Stop button (`src/components/conversation/SubagentCatalogAction.tsx:1`, `electron/cordis/subagent-control.ts:1`, `subagent:list|interrupt|message` IPC). Messaging needs the parent session live (chat threads qualify; coding sessions only mid-turn) and otherwise says so instead of hanging. New delegations ask once as EXEC-class tools with no standing grant (`shared/agent/tool-risk.ts:77`).
- **Background jobs for agents.** The runtime now mounts the job registry and `job_output` / `job_list` / `job_kill` tools (`electron/cordis/cordis-context.ts:131`), so `run_in_background` delegation actually works (both one-shot jobs and continuable children failed without a controller before). Job reads are approval-free; killing asks once.
- **Background jobs are visible now.** The coding pane gains a jobs dock above the composer showing live status, elapsed time, and outcome for every background job, with a Stop button that kills through the ownership fence (`session:job-kill` IPC, `src/components/agent/AgentJobsDock.tsx:1`, `electron/cordis/jobs-bridge.ts:1`). Previously completions only reached the model inbox.
- **Tool chips use the tools' own labels.** Chip titles now come from each dsh tool's `presentCall` view (bash shows the command, jobs show "Read output from background job X") instead of the hand-mapped humanizer, which remains as fallback for Cairn's own tools and old transcripts (`electron/cordis/run-cordis-loop.ts:43`, `src/components/conversation/ConversationToolCall.tsx:95`). dsh bumps improve labels for free.
- **Session goals with a header chip.** The runtime mounts the dsh goal stack (service + `get_goal`/`create_goal`/`update_goal` tools + `/goal` command + automatic goal-round driver, `electron/cordis/cordis-context.ts:289`). The coding pane shows a compact goal chip above the composer with the objective, phase, and round count (`src/components/agent/AgentGoalChip.tsx:1`); it hides when no goal is set and expands blocker detail on blocked goals.
- **Thumbs ratings + notes on assistant messages.** Every assistant bubble (chat and coding) gains thumbs up/down and a note popover backed by dsh's durable per-message feedback sidecar (`session:feedback` IPC, `src/components/conversation/MessageFeedbackControl.tsx:1`, `electron/cordis/message-feedback.ts:1`). Ratings survive restarts and never enter model history. A log-only `/feedback <text>` command records session-level remarks via the existing command palette.
- **Opt-in session reminders.** Agent Settings gains a "Session reminders" toggle (default OFF, needs an app restart) that mounts the dsh schedule overlay: the model gets `schedule_create`/`schedule_list`/`schedule_delete` tools and the chat header shows a read-only alarm pill with the active reminder count (`src/components/conversation/SchedulePill.tsx:1`, `electron/cordis/schedule-read.ts:1`). Delivery is session-local and this does not replace Cairn's background heartbeat.
- **Terminal result cards for shell tools.** Completed bash/pwsh chips now render the tool-authored `presentResult` view — captured output with an exit-status pill — instead of raw text, in both panes and on replayed history (`electron/cordis/cordis-context.ts:resolveToolResultView`, `src/components/conversation/ConversationToolCall.tsx:1`).
- **Session stats from upstream.** The stats line reads dsh's `sessionStats` projection unit (new `dsh-session-stats` dep, snapshot-first with fold fallback) instead of the parallel port; per-turn breakdown stays local.
- **Permission preset switcher.** The coding header gains a preset select driven by the `permissions` projection, executing `/permission <preset>` through the existing command path (`src/components/agent/AgentPermissionSelect.tsx:1`, `electron/cordis/permissions-bridge.ts:1`).
- **Jobs + goals in chat, subagent tree view.** The chat pane shows the jobs dock and goal chip when its session has background work or an objective (`src/components/conversation/ConversationSessionStatus.tsx:1`); the subagent catalog gains a Direct/Tree scope toggle backed by `listDescendants` (new `scope` param on `subagent:list`).
- **Community runtimes go dsh-native (invisible by default).** Skill discovery now includes a dsh filesystem backend behind the existing provider, and Claude/Codex hooks run on dsh interception seams when configured (`~/.config/cairn/hooks/`). An env-gated MCP spike (`CAIRN_DSH_MCP_SPIKE`) routes one connector through `dsh-mcp-client` behind the identical tool/approval surface, with per-turn parity verification and automatic fallback (`electron/cordis/mcp-dsh-bridge.ts:1`, `hooks-bridge.ts:1`). No UI or behavior changes unless enabled.
- **Persistent terminal sessions for the coding agent.** The model gets `terminal_open`/`send`/`read`/`signal`/`close`/`list` over the existing node-pty backend (shared session table with the AgentView terminal), so REPL state and long compiles survive across tool calls; background sends flow into the jobs dock (`electron/cordis/terminal-backend.ts:1`). Process control is EXEC-class one-off approval like bash; reads and listing are approval-free.
- **First-party LSP navigation.** The coding stack mounts the dsh LSP seam with a stdio provider (TypeScript/JavaScript via PATH auto-detect, lazy per-workspace servers that die with the turn) and a read-only `lsp` tool for definition/references/implementation/hover (`electron/cordis/cordis-lsp.ts:1`). Missing binary fails closed with a clear message; other languages report unavailable.

### Changed

- **Agent runtime tracks dsh `0.1.2-rc.1`.** All `@deepseek-ai/*` packages move `0.1.1-rc.2` → `0.1.2-rc.1` (`package.json:59`, `cordis` stays `4.0.2`); upstream removed `dsh-tool-subagent-report` (replaced by bidirectional `send_message`) and session reads moved to `seq`/`eventAt()`/`snapshotEvents()`. Turn-end teardown is now awaited so back-to-back turns can't collide on re-registration (`electron/cordis/session-runtime.ts:34`, `session-runner.ts:98`). The user-questions bridge follows upstream's provider-to-waterfall change (`electron/cordis/cairn-plugins.ts:396`).

### Fixed

- **LLM requests now identify as Cairn.** The DSH chat/agent loop (`dsh-llm`/`dsh-llm-pi-ai`) previously sent `User-Agent: deepseek-harness/...`; it now sends `cairn/<version> (+https://github.com/ddutchie/cairn)` via a shared `APP_IDENTITY` mutation (`electron/cordis/session-runtime.ts:11`, `electron/lib/cairn-identity.ts:1`). Direct one-shot calls (`electron/lib/llm.ts:272`, `electron/lib/llm-transport.ts:159`) also carry the same header, so providers and gateways can attribute traffic to Cairn.

### Fixed

- **Image attachments reach the model again.** The upstream attachment backend requires real `sharp` (stubbed repo-wide), so every admission failed and images were silently dropped from all turns. Cairn's sharp-free store is back with upstream-aligned limits, and the model answers image questions again (`electron/cordis/cairn-attachment-store.ts:1`, `electron/cordis/cordis-context.ts:129`).
- **Unified rail hover states.** In the Dock sidebar the expanded `Views` list (`src/components/layout/shells/DockSidebar.tsx:403`) gave `Overview`/`Notes` (`font-medium` + `hover:bg-[var(--surface-2)]`) a different hover than `Board`/`Calendar`/`Flow`/`Agent` (`text-xs` + `hover:text` only). The collapsed rail (`src/components/layout/shells/DockSidebar.tsx:222`) had no hover at all for the main views. All six views now share `font-medium` + `hover:text-[var(--text-primary)] hover:bg-[var(--surface-2)]` expanded and `hover:text hover:bg` in the collapsed dock. The Studio sidebar (`src/components/layout/shells/StudioSidebar.tsx:112`) was also missing `hover:text-[var(--text-secondary)]` on `Notes`/`Board`/workspace tools — now unified.
