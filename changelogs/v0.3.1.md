## What's new

### Chat rendering fixes

- **Tables** — GFM tables now render with proper borders, padding, and alternating row background. Previously rendered as raw unstyled HTML.
- **Ordered lists** — `1. 2. 3.` lists now render with decimal numbering instead of bullet points. The hardcoded `•` override was incorrectly applied to all list types.
- **Headings** — `#` and `##` are now rendered as proper heading elements instead of `<p>` tags, fixing potential invalid HTML nesting.

### Chat reliability fixes

- **Tool crash recovery** — if a tool call throws an unexpected error (e.g. a bad ID, a SQLite constraint), the error is now caught and returned to the model as a tool result instead of propagating through IPC as a generic "Something went wrong" message. The AI can now respond gracefully rather than the whole conversation failing.
- **`update_note` with deleted note** — previously crashed with an unhandled exception if the note ID no longer existed. Now returns `{ error: "Note not found" }` to the model.
- **`update_task_status` with bad IDs** — previously crashed if the card or target column didn't exist. Now validates both before writing.
- **Duplicate task order on bulk create** — when the AI created multiple tasks in the same column in a single round, all got the same `order` value because the count was read from a stale snapshot. Now reads the live count from SQLite per call.

### Chat UX

- **Suggested prompts** — now correctly disabled while a message is in flight or before the thread is initialised, preventing double-sends.
- **Round-limit message** — when the AI exhausts its step budget, the message now says "Any actions taken so far have been saved — check your board and notes" rather than implying nothing happened.
- **`get_active_context` includes recent tasks** — the active context tool now returns up to 5 tasks per column alongside recent notes, eliminating the extra `list_tasks` round-trip that most task-related queries previously required.

### Performance

- **Snapshot removed from IPC payload** — the renderer was serialising the entire store state (potentially hundreds of KB) and sending it over IPC on every chat message. The main process always discards it in favour of a fresh SQLite read. It is no longer sent.
