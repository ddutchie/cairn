## Fixes

- **Gateway `provider:` prefixes and word-suffixed model ids now resolve their real context window.** The models.dev context-window lookup normalizes proxy/gateway model ids before matching, but two id shapes fell through: a leading `provider:` prefix (e.g. `merge:deepseek-v4-flash` or `merge:gpt-5.6-luna`) was mistaken for the model name, and the trailing version-tag stripper (`-v\d+.*`) was greedy — it swallowed everything after `-vN`, collapsing `deepseek-v4-flash` to `deepseek`. Cairn now strips a leading `provider:` prefix first (whether or not the id also has a `/` path), and only strips a *pure* trailing version tag (`-v1`, `-v1:0`) so descriptive suffixes like `-flash` and `-luna` survive. Added unit tests for `normalizeId` covering these cases.

- **Community connector fallback glyphs stay legible on both themes.** When a community connector or provider has no brand logo, Cairn draws a generic fallback glyph (a plug for services/providers, the MCP mark for MCP servers). It was tinted with the entry's `brandColor`, so a near-black or near-white brand colour made the glyph vanish against the card on one theme. The fallback glyph now uses a theme-safe colour; the brand colour still tints real logos and the card background.

## Features

- **Browse and install community AI providers.** A new **Browse Community** button in **Settings → AI & Chat** (OpenAI-compatible provider) installs ready-made provider presets from the cairn-community catalog with one click — you just enter your API key, which is stored in your OS keychain (never in the database or synced). Each preset ships an endpoint base URL and a default model, so there's no more copy-pasting gateway URLs. Installed providers are added to your shared provider list (used by both AI Chat and the coding agent); pick one in the provider switcher to use it. Community providers live in a **separate `providers.json` manifest** from the tools/commands catalog, are fetched cache-first (instant/offline, background-revalidated), and re-installing a preset reuses the existing entry (matched by community id or name) instead of duplicating it. Both the base URL and default model are validated as safe HTTPS values before install.
