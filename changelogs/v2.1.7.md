## What's new

### Features

- **Splash screen with boot sequence**: New `BootSplash` window shown immediately on launch while the main window is created hidden (`show: false`). A multi-step boot sequence runs before the main interface appears: (1) auto-updater check, (2) workspace migrations, (3) embeddings reindex, (4) notes sync, (5) semantic relationship computation. Each step reports live progress (label + detail + percent) to the splash UI. The main window only shows after the renderer has painted and a minimum 3-second display time has elapsed. Migration and reindex modals previously shown inside the app are now handled during boot — removed from `page.tsx`.

- **Auto-updater with live download progress**: The boot sequence checks for updates *before* the main window opens, so a known-broken build can heal itself via auto-update without ever loading the crashing renderer code. When an update is found, the 172 MB download shows live progress on the splash: `84.3 / 172.9 MB (12.4 MB/s)` with a moving progress bar (15–95% range). After download completes, `quitAndInstall()` restarts the app automatically. Timeout is 300s (5 min) for slow connections; on timeout or network failure, the boot continues with the existing version rather than leaving the user stuck.

- **Unified runtime architecture**: Replaced the separate embeddings-server and llama-server child processes with a single `runtime-server` process spawned by Electron on boot. The runtime-server hosts both adapters behind one HTTP API on a single port: embeddings run in-process via `@huggingface/transformers` + `onnxruntime-node`, while the LLM adapter spawns and proxies to `llama-server` as a grandchild. A new adapter interface (`RuntimeAdapter` / `ModelManagingAdapter` in `electron/runtime/adapters/types.ts`) makes future runtimes (e.g. MLX on Apple Silicon) a drop-in addition with zero Electron or IPC changes. The MCP server auto-discovers the runtime via `runtime-port.json` (with pid liveness check to reject stale ports) and can self-spawn the runtime in dev mode when Cairn isn't running.

- **Runtime auto-start on boot**: `boot-sequence.ts` calls `runtime.ensureStarted()` when embeddings are enabled, so the unified runtime is ready for search and semantic features immediately on launch — no lazy-start latency on the first search.

- **SHA256 model verification**: Every model download (LLM GGUFs and embedding ONNX) streams to a `.tmp` file, verifies against the HuggingFace LFS SHA256 checksum, then atomically renames on success. A `manifest.json` per models directory tracks `status`, `downloadProgress`, `verifiedAt`, and `error` per entry. `migrateManifest()` runs on every runtime startup, marking stale entries and backfilling `verifiedAt` for pre-existing files. `verifyOnDisk()` is called from `listModels` / `isModelInstalled` so a corrupted file is detected before inference, not during.

### Changes

- **`runtime:*` IPC channel namespace**: New unified IPC surface in `electron/ipc/runtime-handlers.ts` with full preload API (`window.electron.runtime.{onProgress, embeddings.*, llm.*}`): model install/remove/setDefault, status probes, progress streaming, LLM binary install/clearInactive/setDefault. Legacy `embeddings:*` / `llama:*` channels retained for DB-touching operations (reindex, search, projections, recompute).

- **`defaultEmbed` routes through the unified runtime**: `electron/embeddings/service.ts` now calls `runtime.embed()` instead of the legacy embeddings-server client, so every embedding inference in the app goes through the single runtime port automatically.

- **MCP `search_notes_semantic` uses the runtime**: The MCP tool now embeds queries via `embedViaRuntime()` in `electron/runtime/port-discovery.ts`, with graceful self-spawn fallback in dev mode. SIGTERM/SIGINT handlers in `mcp-server.ts` call `disposeSpawnedRuntime()` for clean shutdown.

- **UI migrated to `runtime:*` channels**: `AISettings.tsx`, `EmbeddingsSettings.tsx`, `StepEmbeddings.tsx`, `onboarding/index.tsx`, `ReindexModal.tsx`, `search-panel.tsx`, and `SemanticMapCanvas.tsx` all use the new `window.electron.runtime.*` API. Enabling embeddings in settings now calls `runtime.embeddings.ensureStarted()` instead of just saving settings.

- **Packaged app ships runtime dependencies**: `electron-builder.yml` now ships `@huggingface/transformers`, `onnxruntime-common`, `sharp` (stub), and `umap-js` inside the app asar, with `onnxruntime-node` unpacked from asar (via `asarUnpack`) so its native `.node` binding can load. The runtime-server bundle (`dist-electron/runtime-server.bundle.js`) runs as an `ELECTRON_RUN_AS_NODE=1` child of the Electron binary, so no separate Node.js runtime is needed. Updated `electron/bundle-guard.test.ts` with a `RUNTIME_SHIPPED` classification that verifies these packages are present in `electron-builder.yml` but never leak into `main.js` requires. `scripts/build.js` now builds `runtime-server.bundle.js` as part of the standard compile step.

## Baseline (packaged macOS app, M5 Pro, 64 GB RAM)

| State | Pre-Refactor (v2.1.6) | Post-Refactor (v2.1.7) | Delta |
|-------|----------------------|------------------------|-------|
| Idle | 719 MB | 877 MB | +158 MB |
| Embeddings active | 921 MB | 967 MB | +46 MB |
| LLM + embeddings active | 8,917 MB | 8,892 MB | −25 MB |

Idle overhead is the always-on runtime-server process (103 MB). Both-active is 25 MB *less* than pre-refactor because the unified process is more memory-efficient than separate embeddings + LLM processes. See `scripts/runtime-baselines/` for raw captures.
