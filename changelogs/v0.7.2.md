# v0.7.2 — Tool schema refactor, audit fixes + token optimisation

## What's new

**Zod single source of truth for all 43 tool schemas**

All tool definitions are now authored once in `electron/lib/tool-schemas.ts` using Zod, and derived automatically for both the AI chat function-calling array (`TOOLS`) and the MCP server tool registration. The previous setup had ~45 KB of hand-written JSON Schema duplicated across two files, with a lossy `buildZodShape()` conversion in between that silently turned `array` and `boolean` types into `{}` (unknown) on the wire.

Affected fields that were previously broken for MCP clients: `tagIds`, `isPinned`, `cardIds`, `nodeTypes`, `edgeTypes`. These now correctly advertise as `array`/`boolean` in the MCP schema.

## What's fixed

**Missing fields on tool handlers**

Several tools accepted parameters in their schema that were never wired through to the database:

- `ensure_note` — now respects `tagIds` and `isPinned` on both create and update paths (MCP + chat)
- `import_note_from_file` — now applies `tagIds` to the created note (MCP + chat)
- `update_project` — `icon` is now applied via the SQL UPDATE in the MCP handler (was already wired in chat-executor)
- `create_note` / `create_task` — `tagIds` on creation now correctly stored in both handlers

**`z.record(z.unknown())` replaced with `z.object({}).passthrough()`**

Zod v4's `toJSONSchema` cannot convert `z.record(z.unknown())`. The three schema fields using this type (`create_idea_flow_node.data`, `create_idea_flow_node.edges`, `update_idea_flow_node.data`) are now `z.object({}).passthrough()`, which serialises correctly and is semantically equivalent for free-form objects. This also fixes the tool parity test suite which was crashing on import.

**`create_note` in `queries.ts` accepts `isPinned`**

The `createNote` helper now accepts an optional `isPinned` field, making it consistent with `updateNote` and enabling `ensure_note` to set pin state on newly created notes.

## Token optimisation — 30% reduction per request

Every AI message now sends ~2,300 fewer tokens, dropping from ~7,656 to ~5,370 tokens per request.

**System prompt: 6,016 → 1,282 chars (−79%)**

The large inline reference sections (Dashboard API docs, Idea Flow node-type rules and group conventions, Knowledge Graph edge-type list) have been removed from the system prompt and moved into two new on-demand tools. The AI calls these only when it actually needs them, rather than paying for them on every single request.

**Two new reference tools**

- `get_dashboard_constants` — returns the full `window.cairn` helper API: available functions, return shapes, and usage rules for building dashboard HTML. Call before writing `create_dashboard`.
- `get_idea_flow_rules` — returns node type data shapes, positioning conventions, and group rules for the Idea Flow canvas. Call before creating nodes if unfamiliar.

Both tools are available in chat and via MCP.

**Tool descriptions and parameter hints trimmed**

Redundant boilerplate was removed across all 45 tool definitions:

- "Get existing IDs from get_active_context or get_cairn_context" repeated on 8+ parameters → replaced with short parenthetical "(from get_active_context)" on the shared `tagIds` field only
- "ISO date string e.g. 2026-05-01, or empty string to clear" → "ISO date e.g. 2026-05-01, or empty to clear"
- Full hex colour palette list removed from `color` parameter description
- Per-tool `workspaceId` descriptions stripped (system prompt already covers this)
- Tool descriptions shortened across the board (~20–30% each)
