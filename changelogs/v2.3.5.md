## What's new

The **Knowledge Graph** is faster and easier to read. The Force view has been rebuilt on a raw D3 canvas with cluster outlines, and the Radial view is now a **drill-down sunburst** that stays smooth even on large workspaces. Click any tag or item to spotlight everything related to it.

### Features

- **Force graph — canvas rendering with cluster hulls**: The force-directed Knowledge Graph now renders on a raw D3 canvas instead of the previous SVG/library renderer, so it stays responsive on large graphs. Each project's members are wrapped in a soft convex-hull outline (toggleable via the **Hulls** control, remembered between sessions), with a glow/focus-dim treatment when a node is selected.
- **Radial view — drill-down sunburst**: The Radial layout is now a canvas sunburst: Workspace at the centre, projects and a shared **Tags** branch around it, and notes / cards on the outer ring. Click a branch to drill in (the rings expand to fill the wheel with readable labels) and click the hub or the breadcrumb to zoom back out — all smoothly animated in both directions.
- **Click to spotlight connections**: Clicking a **tag** highlights every note and card carrying that tag; clicking any other item highlights everything linked to it (note-card links, wikilinks, co-mentions, …). The selected item is filled in the accent colour with a glow and a high-contrast ring so it stands out clearly, its connections stay bright, and everything else dims to let the relationships pop. Clicking back clears the spotlight.
- **Pass an API key to the AI Tool Builder securely**: The "Build a tool with AI" modal now has an optional API-key field (with a configurable header name, defaulting to `x-api-key`). The key is used only to authenticate live probes during that session — the AI never sees the value (it writes an `<API_KEY>` placeholder), and the real key is stored in your OS keychain when the tool is saved. This lets the builder reach a real `2xx` response on APIs that require auth even for a first request.

### Changes

- **Graph toolbar scoped per layout**: Controls that only apply to the Force view (label mode, semantic-similarity slider, auto-links toggle, edge-type legend) are now hidden in the Radial view, which has no cross-edges or label modes. The project filter, spacing slider, search, and node-type legend remain available in both.
- **Zoom controls use the app tooltip**: The Force view's zoom-in / zoom-out / fit buttons now use the standard Cairn tooltip (with a clearer "Fit all" label) instead of the native browser title.
- **"Build with AI" applies to all tools**: The button was previously tucked inside the MCP Servers section, which made it look MCP-only. It's now a prominent banner at the top of the Tools settings, with copy that makes clear it can build either a custom HTTP service or an MCP server.

### Fixes

- **Force graph frames correctly on open**: The graph could briefly sit in the top-left and then settle off-centre on first open. It now auto-fits the whole graph to the viewport while the simulation settles and once more when it comes to rest, and it stops auto-fitting the moment you pan or zoom.
- **No artifacts when switching theme**: Toggling light / dark (or an OS theme change while on "system") left stale-coloured pixels on the graph canvases. Both the Force and Radial canvases now repaint with the new palette as soon as the theme changes.
- **Selected node contrast (Radial)**: The spotlighted node was hard to distinguish from its connections. It's now filled with the accent colour and labelled / ringed in the accent foreground colour, meeting WCAG AA contrast in both light and dark themes.
- **Tool builder no longer falsely reports "No API key configured"**: When using a local AI endpoint (Ollama, LM Studio, or any `localhost` server) with a non-`localllm` provider, the builder incorrectly demanded an API key — even though chat worked fine. It now treats local endpoints as keyless, matching the chat and agent behaviour.
- **Tool builder endpoint 404 fixed**: If your AI base URL ended in `/v1`, the builder produced a doubled `/v1/v1/chat/completions` path and failed with a 404. It now normalises the base URL the same way chat does.
- **"Test connection" works on APIs that require a body**: Testing a custom HTTP service used to send an empty `{}` body, which APIs with required fields (e.g. a `/search` endpoint needing a `query`) rejected with a 400. The test now synthesises a realistic request from the tool's parameter schema (filling required fields and any field with a default/example).
- **Tool arguments are coerced to their declared types**: Some models emit numbers and booleans as quoted strings (e.g. `"10"` instead of `10`), which strict APIs reject with a 400. Custom HTTP service calls now coerce arguments to the JSON types declared in the tool definition before sending the request.
- **Tool builder recognises more auth and error signals**: The probe step now treats HTTP `402 Payment Required` as "needs a credential" (in addition to 401/403), and the builder is guided to fix the request body and re-probe on a `400` rather than giving up — so it converges on a working tool more often.
