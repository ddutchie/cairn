## What's new

### Added

- **Paste a writing style directly.** In Settings → Writing Style you can now skip the guided questionnaire entirely: hit **Paste a style directly** and drop in a style guide you already have (or had another AI write). A one-click **Copy prompt** button gives you a ready-made prompt for ChatGPT/Claude etc. that produces a guide in Cairn's canonical 12-section format, so the pasted result is immediately usable by chat and the coding agent. Pasting writes the guide verbatim (no LLM call needed), and the same view lets you **Optimize** it into the canonical format or **Generate a cheat sheet** before saving.

- **A "set up your writing style" prompt appears when the AI can't match your voice.** When chat, the coding agent, or a drafting subagent calls `get_user_writing_style` and no writing style is configured yet, a chip appears under the tool call with a **Set up writing style** button that pops the setup modal directly — so you know why the draft doesn't sound like you yet and can fix it in one click.

### Fixed

- **Clicking the notification bell now toggles the popup.** It used to only ever open: clicking the bell while the popup was open fired the popup's outside-click close and its own open at the same time, so it looked stuck open. The bell (title bar and sidebar) is now a proper toggle, mirroring the sync button beside it.

- **Writing-style wizard usage now shows up as "Writing style" in the Usage view.** The streaming generation path (the default in the guided wizard) previously recorded no usage row at all — it's now attributed with the `writing-style` source like the one-shot fallback, instead of being missing or bucketed under Chat.

- **Dropdowns behave properly inside modals and popovers.** Two related Radix quirks fixed at the root:
  - A `Select`/dropdown open inside a dialog is portaled to the page root, which Radix treats as "outside" the dialog — so interacting with it used to dismiss the whole modal. Dropdowns now opt into the same `data-dialog-portal` escape hatch the date/time pickers use, so clicking inside an open dropdown keeps the modal open.
  - Dropdowns were **modal** by default (a Radix default), which disables pointer events and traps focus on everything outside the menu — so with a dropdown open inside a dialog (e.g. the context picker in the Writing Style wizard) or a popover (the provider & model picker), the surrounding content was frozen: toggling the dropdown's own trigger could even pass the click through to the overlay and close the whole modal. All dropdowns are now non-modal, so clicking the trigger again dismisses just the dropdown and the host dialog/popover stays interactive.
