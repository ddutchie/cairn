## What's new

### Features
- **Heartbeat automations (foundation).** Cairn now ships the scheduling engine for background agent tasks: a main-process heartbeat scheduler that polls a durable `automations` table and fires due runs while the app is open. Includes cron / "every N unit" / "once" schedules with timezone-aware next-run calculation, run-once catch-up on launch, skip-on-overlap (a slow run never stacks), and per-run history in a new `automation_runs` table. Runs execute through the data-only knowledge-work agent (no bash / file edits), and completion is surfaced through the existing in-app notifications.
- **Automations view.** A dedicated Automations section (sidebar) lets you create, edit, run now, enable/disable, and delete scheduled automations — instructions, schedule, project scope, timezone, and an optional run cap. Cards show the project scope, latest run status with a live running indicator (current tool + animated bar), and any notes/cards a run produced, each navigable.
- **Friendly schedule builder.** No cron required: pick Interval / Daily / Weekly (toggle any days of the week) / Monthly / Once with a date picker and time, with a live "next run" preview. Advanced cron remains available for power users.
- **Community automation recipes.** The New Automation dialog offers "Start from a community recipe" — browse the cairn-community automations catalog (separate `automations.json`), pick a recipe, and it pre-fills the form (name, instructions, schedule, approval mode) for you to tweak and save. Recipes are data-only (no shell).
- **In-app notification center.** A sidebar Notifications entry (bell + live unread badge) opens a notification center listing recent activity — automation completions, approvals, and MCP writes — with per-item dismiss and "Mark all read". Unread is now persisted (no longer auto-cleared on focus), and notifications surface in-app while focused instead of only as OS toasts when unfocused. A title-bar bell sits next to the sync status for quick access. Notifications are pruned automatically (30 days / newest 1000 kept) so the table doesn't grow unbounded.
- **Durable approval inbox (foundation).** A persisted human-attention queue that backs approve/deny for background runs — resolve-once, idempotent per run+tool+args, fail-closed expiry sweep. UI + runner integration land in a follow-up.
- **Approve/deny for automations.** Automations can now run in "Ask" mode: each write action parks a durable approval item and the run waits for your approve/deny decision (read-only tools always run). Auto mode (default) keeps writes flowing. Resolution is surfaced over IPC ready for the inbox UI.
