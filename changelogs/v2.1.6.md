## What's new

### Fixes

- **Embeddings server crashed loading pruned model after the v2.1.4 model swap**: `pruneOrphanedModels()` reset `default-model.json` when detecting the unsupported Nomic id, but never touched the renderer-facing cache (`ai-settings-cache.json`). Every IPC handler (`reindex`, `search`, `recomputeProjections`, `projections`, `needsReindex`) sourced its model id from `settings.modelId ?? getDefaultModelId() ?? EMBED_MODEL_ID` — preferring the stale cached `nomic-ai/nomic-embed-text-v1.5` over the corrected default. The renderer forwarded `nomic` in every call, and the embeddings server tried to load the just-pruned onnx files, failing with `Load model ... File doesn't exist`. Fixed by adding `resolveEmbeddingModelId()` in `electron/embeddings/client.ts`, which validates each candidate against `SUPPORTED_EMBEDDING_MODELS` before use, and a `resolveModelId()` wrapper in `embeddings-handlers.ts` that **self-heals** the cache: when the cached id diverges from a still-supported model, the corrected value is written back to both `ai-settings-cache.json` and `default-model.json`, so the renderer never sees the stale id again. Replaced all five stale-fallback call sites.
- **Reindex modal only appeared on the second launch** (downstream consequence of the above): first launch saw cache=nomic + DB=nomic → no mismatch → modal hidden; after the session pruned/partially-reindexed, the DB held mixed models → second launch showed the modal. With self-heal now running on the very first `embeddings:needsReindex` IPC call, `settings.modelId` is corrected before the SQL query, so `WHERE model != bge-small` correctly returns the stale nomic rows and the modal shows on first launch as intended.
- **Embeddings model showed as "not downloaded" forever** (Install button always visible): `modelFilesPresent()` in `electron/embeddings/manifest.ts` gated "installed" status on `config.json` existing at the model root, but `pipeline.ts` only calls `AutoTokenizer.from_pretrained()`, which fetches tokenizer files (`tokenizer.json`, `tokenizer_config.json`) and the onnx model — `config.json` (the model architecture file) is never downloaded. Changed the presence check to require only what the pipeline actually loads: `tokenizer.json` + `onnx/*.onnx`. The stale `manifest.json` `not_downloaded` entry self-heals on the next `getEmbeddingModelsManifest()` call.

### Tests

- **Bundle-guard drift checks** (`electron/bundle-guard.test.ts`): added 5 new tests beyond the existing 4. The allowlist is now classified into four lifecycle groups — `RUNTIME_PROVIDED` (electron), `OPTIONAL_TRANSITIVE` (esprima), `SUBPROCESS_ONLY` (transformers/onnxruntime — used only by the embeddings worker), `SHIPPED_NATIVE` (better-sqlite3/node-pty). Drift checks verify: (a) every `--external` flag in `package.json` is in the allowlist; (b) every `SHIPPED_NATIVE` external actually ships in `electron-builder.yml`; (c) `SUBPROCESS_ONLY` packages don't leak into `electron-builder.yml` (no wasted space in main app); (d) `SUBPROCESS_ONLY` packages don't appear in the main bundle's `require()` list; (e) no allowlist entry is silently duplicated across groups. Verified all three classes of regression are detected via synthetic injections.
- **Embeddings model resolver tests** (`electron/embeddings/client.test.ts`, new): 6 tests covering `resolveEmbeddingModelId()` — supported candidate selection, skipping over unsupported ids, falling back to default when all candidates are stale, preferring explicit supported args over stale cached ids, and short-circuiting on the first valid value.
- **Pre-release gate** (`scripts/pre-release-check.sh`, new): runs clean-tree check → `npm run compile` → `npm run type-check:all` → `npm run lint` → `npm test` → explicit bundle-guard re-run → `npm run test:e2e` (unless `--skip-e2e`). Wired into `scripts/release.sh` so `npm version` can't proceed on a broken build. Failures exit non-zero with a clear `✗ pre-release check FAILED` message.

### Workflow

- **`npm test` now runs `npm run compile` first** so `electron/bundle-guard.test.ts` actually executes against a fresh bundle (previously the test silently skipped via `it.skipIf(!fs.existsSync(...))` when bundles were absent — the v2.1.4 regression shipped because CI ran `npm test` without `npm run compile`). Added `npm run test:bundle` for running just the guard tests and kept `npm run test:fast` (vitest only) for tight dev loops.
- **PR template checklist** updated: clarification that `npm test` now compiles first, plus a new item requiring allowlist groups in `electron/bundle-guard.test.ts` to be updated whenever a `--external:<pkg>` flag is added/removed from the `compile` script (and, if `SHIPPED_NATIVE`, the package must be shipped via `electron-builder.yml`).
