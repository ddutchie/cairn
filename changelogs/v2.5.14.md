## Fixes

- **Linking a note to a task no longer deletes the note in the packaged app.** The previous fix was correct in the source bundle but broke once packaged into the standalone `cairn-mcp` binary: the pkg runtime's `fs.realpathSync.native` does not canonicalise filename case on macOS, so a note whose stored folder casing differed from its on-disk directory (e.g. `Research` vs `research/`) was still misread as a *move* and its file unlinked. Same-file detection now uses the file's device + inode identity (`fs.statSync`), which the real OS resolves correctly under both plain Node and the packaged binary — so a case-only difference is treated as an in-place rewrite and the note is preserved.
- **The MCP server binary no longer crashes on startup.** The packaged `cairn-mcp` resolved its `better-sqlite3` native addon to a path inside pkg's virtual `/snapshot` filesystem, which `fs.existsSync` reports as present but cannot actually be loaded — so under some build conditions the binary crashed the moment it opened the database. The arch-matched native binding now ships as a real file next to the executable and is loaded from there, so the standalone MCP server starts reliably (including when run with the app closed).
- **Intel (x86_64) Macs now get the correct MCP binary.** The path Cairn hands to external agents (opencode, Claude Desktop, etc.) in onboarding and Settings was hardcoded to the Apple-Silicon binary on *all* Macs, so Intel Macs were pointed at an arm64 executable that couldn't run. Each Mac build now ships a single, correctly-named `cairn-mcp` binary for its own architecture.

## Under the hood

- **Each per-arch build ships only its own architecture's native binaries.** macOS/Windows produce separate arm64 and x64 packages, but every app was bundling *both* arches' native artifacts (the desktop SQLite bindings, both standalone MCP binaries, node-pty prebuilds) — the other arch was dead weight (the arm64 mac app carried the ~84 MB x64 MCP binary for nothing). A new `afterPack` step strips the non-target architecture from each package, so downloads are smaller and contain only what runs.

## Under the hood

- **New release gate: `npm run smoke-test:mcp`.** The release workflow now boots the actual built `cairn-mcp` binary on each platform, links a note to a task in a throwaway workspace that reproduces the folder-case mismatch, and fails the build if the note's file is deleted or relocated. This closes the gap that let the bug ship — a fix can be correct in unit tests (plain Node) yet broken once packaged by pkg, and only a test against the real binary catches it.
