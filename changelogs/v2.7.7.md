## What's new

### Changed

- **The context-usage ring is now one shared implementation.** Cairn's context ring and the `dsh-context-ring` community plugin were converging on two copies of the same donut; Cairn now renders the ring from the shared package (`dsh-context-ring/react`) and projects it into all its usual spots (chat header, sub-agent blocks, coding-agent pane), supplying its own richer breakdown categories and fill-level colour. The plugin stays a first-class dsh community plugin — the same component powers the dsh web shell — so there's one ring to maintain and share.
- **Plugins can be updated in place.** The Plugins settings page now has an Update button on installed plugins: it re-fetches the plugin from its original source (the GitHub repo or local folder it was installed from) and rebuilds the entry, preserving its enabled/disabled state — no need to uninstall and re-add to pull the latest version.

- **The coding agent now runs on the new Cordis engine by default.** The agent that edits your files, runs commands, and works through plans has been ported onto Cairn's next-generation runtime, matching the chat engine. Everything you already rely on carries over — plan mode, per-tool approvals, the repeated-action safety pause, skills, image attachments, automatic context compaction, and on-device local models — with resumable sessions and cleaner streaming. This is now the only engine: chat, the coding agent, automations, writing-style, and all one-shot AI helpers route through it.
- **A QA end-to-end suite now boots the real desktop app and exercises every AI loop.** `npm run test:e2e:electron` (with `CORDIS_LIVE=1 CORDIS_DUMMY_KEY=local` and the model bridge running) launches the actual Electron app against an isolated throwaway profile and drives chat ("summarize this project"), the coding agent, and heartbeat automations end-to-end through the real IPC and renderer — confirming the Cordis engine works in the shipped app, not just at the unit level. `CAIRN_USER_DATA_DIR` lets the harness redirect the app's data folder so your real workspace is never touched.
- **Updated the underlying agent runtime (dsh) to the latest release.** Cairn tracks the dsh engine closely; this pulls in the newest agent, session, tools, and attachment packages and adds the skill-registry package, keeping us current with upstream fixes and the plugin ecosystem.
- **Plan mode is now dsh-native.** The coding agent's plan mode is driven by the runtime's own plan-mode controller — the plan policy guidance, the `exit_plan_mode` review flow, and the `/plan` command come from dsh itself. Toggling plan mode now executes the real `/plan` command through the runtime's command registry, so the flip is recorded in the session log (a resumed session keeps its mode), and the UI reflects the authoritative state even when it changes mid-turn. Cairn's custom read-only tool guard was removed to match upstream behavior exactly; as packages evolve, plan mode tracks dsh directly.
- **Cairn commands now live in the runtime's command registry.** `/compact` is registered alongside plugin commands (`/plan`, …) with one shared implementation, and a generic executor lets any surface run registry commands on a session's resumed agent. The command palette now merges these registry commands (executable, logged) above the built-in prompt templates and your custom commands — one namespace for built-ins, plugins, user-defined, and community commands.
- **Skills are now fully driven by the runtime.** Your SKILL.md skills (project `.cairn/skills/` and friends) and skills shipped by installed plugins are merged into one catalog with standard precedence rules. dsh's skill tool owns delivery — it injects the `<available_skills>` list on each step and republishes it when it changes, so a new skill appears automatically, and a `/<name>` message invokes one directly. Chat and the coding agent share the same catalog, and there's a single `skill` tool.

### Fixed

- **The agent settings "Assembled System Prompt" now shows what the agent actually receives.** It previously previewed the legacy prompt builder; it now assembles the real runtime prompt from the dsh SystemPrompt service — the full text, a per-section breakdown (each expandable to its literal text), and the live skills and tool lists, so you can see exactly how Cairn's identity, persona, skills, and tools compose the model input. The old "Discovered Skills" section (and its static `pi-agent:preview-prompt` IPC) was removed — skills are now listed from the shared SkillRegistry in the same view.

- **Chat and coding-agent history is now read straight from the session log, so conversations survive reload cleanly.** Both surfaces rebuild their transcript from the engine's own append-only session log instead of a second copy in the database — the same source the agent resumes from. This ends the duplicated/ghost bubbles, the empty "runtime context" bubble, user messages and tool calls disappearing on reload, and tool chips that stayed spinning after the tool had finished. The legacy database copies of chat and agent messages are no longer written and are purged on launch.
- **Sub-agent traces are replayed correctly after reload.** A conversation that delegated to sub-agents now shows each sub-agent's own block — its instruction/prompt, its tool calls with their outputs, and its findings — reconstructed from the sub-agent's session, attached to the turn that dispatched it. Sub-agent tool calls no longer leak into the main conversation as stray chips.
- **`/compact` works in both chat and the coding agent, and the summary persists.** Compaction now runs through the engine's own compaction (rewriting the session into a summary node) rather than a side transcript, so the compacted history is the real session state — it renders immediately and survives reopening the app. Fixed a crash where a repeated turn could abort the loop with "a user-questions provider is already registered", and fixed one-shot AI helpers (compact summary, commit messages, PR descriptions) that were silently returning empty text on the new engine.
- **Mermaid nodes with light fills are readable again in dark mode.** Diagrams that pin their own fill colours (LLM-generated charts often pick light pastels) rendered white text on a light background, because mermaid's label colour follows the theme. The contrast pass that already fixed subgraph labels now covers regular nodes too — it measures each node's fill and flips the label to a contrasting dark or light colour unless the diagram author set a label colour of their own.
- **Image attachments reach the model again after the runtime update.** The updated agent runtime changed how images are prepared for a model request; Cairn's attachment store now implements the new request-image contract, so pasting or attaching an image to chat or the coding agent works as before (the model sees the image instead of the turn erroring out).
- **"Always allow this command" actually works now.** The approval card's standing-grant button for bash commands was accepted but never honoured — every identical command re-prompted as if only "Allow once" had been clicked. Granted commands are now remembered per agent session (exact command match, whitespace-insensitive), so a workflow you've approved stops nagging without widening the door to different commands.
- **"Always allow this tool" now outlives the current prompt.** Tool grants previously expired at the end of the turn that created them — the next message re-asked for everything. Grants now stick for the lifetime of the agent session and are cleared when you clear or close it.
- **Loop protection now covers approved-and-denied work too.** The repeat-detection guard sits ahead of the approval gate in the tool pipeline, so a model stuck retrying the same write or shell command trips the "repeating the same action" pause even while per-call approvals are enabled — previously that combination silently disabled loop detection.
- **Approval responses are session-scoped.** An approve/deny event can only resolve a confirmation belonging to its own agent session, eliminating a cross-session race between concurrent runs, and pending confirmations are cleaned up when a session is cleared or closed.

- **A tool approval can no longer be lost to a reload.** If you reload the window (or reopen your agent session) while the agent is paused waiting for an approval, the confirm card now reappears — Cairn re-pulls outstanding asks from the engine instead of relying on the original notification, so the run can always be answered rather than silently stuck.
- **Unanswered approvals, loop pauses, and question forms now time out safely.** An interactive prompt left unanswered for 10 minutes settles fail-closed (the step is cancelled or halted with a clear reason) instead of blocking the agent forever; the expired card retires itself. Answering in time works exactly as before.

- **Approval cards now describe every tool correctly.** The risk label, scope note, and "always allow" options on a confirmation card come from the same source of truth the engine's approval gate uses, so they can no longer disagree with what actually gets asked: file-editor and todo tools now correctly offer session grants, Cairn note/task deletes are no longer presented as harmless reads, and brand-new unknown tools default to the conservative write treatment.

- **The agent's approval policy is now recorded truthfully in the session log.** With auto-approve on, sessions now log "approval policy: never" (and "ask" when confirmations are enabled) using the engine's own durable policy record — so the audit trail, session resume, and the model's own understanding of what it may do all match the setting you chose, instead of always claiming approvals were required.

- **Loop protection is now engine-native and covers headless runs.** The repeat-detection guard ships as the first bundled plugin on the new host-confirmation seam: its pause renders through the standard approval card (risk badge, argument preview), and automations without a human channel fail closed — a stuck run halts deterministically instead of spinning.
- **Permission presets are live.** The agent runtime now mounts the engine's permission-preset service, adding the `/permission` command in coding sessions plus durable per-session preset records alongside the sandbox and approval knobs.
- **Legacy transcript storage is fully retired.** The pre-engine SQLite message tables are dropped on startup and every remaining read fallback removed — chat and agent history load exclusively from the session log. Conversations from before the engine cutover no longer attempt to load (they were already empty); the database gets structurally lighter.

- **Automation script tools register again.** A schema-shape mismatch made the automation-only tools (`run_script`, `write_run_file`, `deliver_file`) fail to register on the new engine — silently, so script-based automations would have lost those tools at run time. The tool bridge now accepts both parameter shapes; caught by the new live approval-pipeline validation suite.

- **Approval cards work inside sub-agent traces too.** A confirmation whose chip lives in an expanded sub-agent block now renders and retires correctly instead of silently doing nothing — the store walks nested transcripts and tool-end patches clear the card there as well.
- **Extracted and consumed the standalone `dsh-context-ring` open-source plugin.** Prompt composition folding, token provenance, and cache savings calculations now run through the modular `dsh-context-ring` package, verified with DeepSeek Harness upstream standards and community plugin settings installation.
- **Fixed note and task reference chip rendering across streaming and replay.** In session replay, `tool-result` message blocks (carrying `source.kind: "tool"`) are now parsed before filtering model-injected context, correctly restoring tool outputs, `cairnRef`, and clickable note/task chips across thread reloads.




- **Fixed phantom empty message bubbles from in-flight session replay.** `collapseDerivedToMessages` no longer synthesizes an empty assistant placeholder message for mid-turn carryover tool calls, preventing in-progress tool chips from rendering simultaneously in the message history and the live streaming footer.

- **Fixed clean session unmount when clearing a chat thread.** `dropChatAgentForThread` now disposes the outer agent handle as well as the inner context session, guaranteeing clearing a chat completely wipes in-memory agent instances and remounts a clean session from scratch on the next turn.




- **New: the Context Ring — see whose thinking is in your agent's context.** The agent panel now shows a small provenance badge after each run: which models produced reasoning this session, how much of it is present, and whether it will round-trip natively or degrade to plain text (with per-block counts when envelopes were lost). Built as a durable engine projection, so it replays correctly across resume.
- **Dynamic workspace runtime context.** The engine now registers a dynamic context provider (`cairn:workspace-context`) that projects the active project, focused task, active Kanban column, open note, and git branch into native runtime snapshots for the model.
- **Token telemetry and in-session checklists survive reload.** Token breakdown gauges, ContextRing metrics, and in-flight agent todo lists are now folded directly from the durable DSH session log on resume and reload, rather than relying on ephemeral in-memory state.
- **Eliminated periodic background hiccups and main-thread stalls.** Replaced synchronous `statSync` file checks and frequent idle SQLite queries in the MCP notification poller with non-blocking async checks, removed redundant 3-second renderer notification interval in favor of push events, relaxed automation run count polling to 15 seconds, cached sync-folder state to prevent recurring disk queries on background timers, guarded refresh hydrations so chat session history, AI/agent configs, and keychain migrations are only loaded on cold start or workspace switches instead of re-reading and serializing all settings on every background event, added structural equality guards to `useSyncStatus` external store listeners to eliminate periodic 5s root re-renders, and added equality guards to GitView polling to prevent redundant component re-renders when repository status is unchanged.

### Fixed (pre-merge review pass)

- **Your chat and coding-agent history from 2.7.6 no longer vanishes on upgrade.** The pre-Cordis SQLite tables (`chat_messages`, `pi_agent_messages`, `pi_agent_llm_history`, `approval_items`) used to be dropped at boot with no export, no warning, and no way back — the sidebar still listed every historical thread while each one clicked through to empty, indistinguishable from data corruption. The retirement now runs as a proper migration (v49) that first archives every populated row to `<workspacePath>/.cairn/archive/2.7.7/<table>-<timestamp>.ndjson` and only then drops the tables. Runs exactly once per DB via `PRAGMA user_version` — workspace switching can no longer defeat it either.
- **The coding agent's bash is now sandboxed.** The previous build mounted the unconfined `dsh-bash-local` executor even in "workspace-write" mode, so an approved bash call ran with the app's full user privileges anywhere on disk. Cairn now mounts `dsh-bash-sandbox` (Seatbelt on macOS, Landlock on Linux, ACL restricted-token on Windows) so `workspace-write` / `read-only` sessions are actually confined; `danger-full-access` falls through to the same unconfined behaviour as before.
- **Auto-approve is now OFF by default.** A fresh install used to hand the coding agent full unattended reach — bash, write, edit, delete_note, delete_project — with no prompt shown, which combined with any prompt-injection reaching the agent (a crafted README, an MCP tool result, a community automation recipe) was arbitrary code execution as the user with no UI. Approvals are on by default; users can opt into per-session auto-approve from Agent Settings.
- **"Always allow this command" no longer trusts the renderer for what it's granting.** The bash standing-grant text is now read from the trusted `tools/pre-execute` args stash main-side — a compromised renderer / UI plugin can no longer echo a different command back over IPC to earn a wildcard grant. Grants are recorded against what dsh will actually execute.
- **Approving a tool call needs proof you saw the ask.** `pi-agent:respond-tool` now requires a per-ask nonce minted main-side and delivered in the original approval event. A renderer-side script that only saw the callId broadcast can no longer auto-approve pending asks — the buttons echo the nonce from the card they're mounted in, and mismatches fail closed.
- **The "Develop" automation persona is a scoped coding agent again.** The pre-Cordis loop restricted this persona to file tools only (no bash, no Cairn data tools) via an `AUTOMATION_DEV_TOOLS` whitelist that was silently dropped in the Cordis port — a Develop session was inadvertently a fully-privileged coding agent with bash and every Cairn data tool. The restriction is restored: the persona sees no Cairn data tools, and bash + subprocess-local + shell-env + tool-bash are not mounted for that role.
- **The chat agent can't delete your projects any more.** Chat has no per-tool approval gate (approvals are a coding-agent-only concept), so `delete_note` / `delete_task` / `delete_project` are simply not registered on the chat context. Non-destructive writes and every read tool are unaffected.
- **Plan mode now surfaces the plan for review.** The v2.7.7 changelog said plan approval flowed through dsh's `exit_plan_mode`, but the review card came through blank and unapprovable — Cairn's question provider dropped the `detail` / `options` / `intent` fields dsh carries the plan on. Fixed the wire contract, added a specialised PlanReviewCard (matching dsh's web-UI takeover: Approve / Keep planning / Discuss), and rewrote the plan-mode system prompt to instruct the model to call `exit_plan_mode(plan)` when the plan is ready. The plan is persisted to `pi_agent_sessions.plan_content` (migration v50) so execute-mode carries it forward on the next turn. Reload mid-review re-hydrates the card from a new pending-question registry — a review can't be lost to a page refresh any more.
- **Sub-agent traces in the coding pane are wired up.** Sub-agent delegations used to be invisible during a live coding turn (they only reappeared on reload from session-log replay) because the pane subscribed to `pi-agent:*` events with a `${sessionId}:sub:` prefix that nothing ever emitted, and its `finalisePiSubagentMessage` action was subscribed but never called. Sub-agent events now come through the shared `chat:subagent*` bus with a `parentSession` field the pane filters on; child bubbles finalise on the sub-agent's `done` event.
- **Path traversal on session-delete IPCs is closed.** `db:chat:clearThreadMessages`, `db:chat:clearAllThreads`, and `pi-agent:clear` all built `fs.rmSync` targets from renderer-supplied ids without validation. Any id that couldn't path-traverse (matches `[A-Za-z0-9._-]{1,128}` and isn't `.` / `..`) is accepted; every composed path is additionally containment-checked so `rm` can only target inside the session root.
- **A workspace switch mid-stream no longer eats your just-sent message.** Chat's `loadChatFromDb` used to replace every message in memory with the session-log fold on workspace switch. If the just-sent user message hadn't hit the JSONL log yet (a race window of tens of milliseconds), it vanished. The load now preserves the in-memory copy for any thread whose tail is a user message not yet reflected in the DB.
- **`db:piSession:sessionMessages` no longer eats real errors.** The previous version swallowed EVERY error and returned an empty transcript, hiding a dsh format-version bump (empty history with no diagnostic), permission failures, and corrupt logs. Only ENOENT is swallowed now; anything else rethrows with a diagnostic prefix — `SessionFormatUnsupportedError` reports "recorded on a newer runtime version and cannot be read by this build".
- **Concurrent chat streams on the same thread are rejected instead of interleaving.** Two open windows on the same thread used to both write to the same `session.jsonl.zstd` — dsh serialised the writes so the file didn't tear, but the events interleaved into an incoherent transcript. The second stream now returns a plain "another turn is in flight" error instead of racing.
- **Plan approval and dsh AskUserQuestionItem forms are readable again.** The renderer's QuestionForm now accepts BOTH the Cairn `{id, label, prompt}` shape AND dsh's `{id, question, header, detail, options, intent}` — so any dsh-native provider (plan-mode's `exit_plan_mode`, future upstream tools) renders a filled-in form instead of a blank one.
- **Plan mode now follows the dsh lifecycle without a second prompt mode.** Cairn no longer swaps its base coding-agent system prompt when entering plan mode, and a mode toggle is reflected only after dsh commits `plan/mode` to the session log. Resumed sessions preserve the dsh log as the authority instead of reapplying the legacy SQLite mode index.
- **Added breathing room around the agent context summary.** The model thinking summary at the bottom of the coding pane now has its own separation from the final tool or response row instead of appearing attached to it.
- **Slash commands now accept arguments.** Commands such as `/plan lets implement a new feature` are recognized by their command name and passed to dsh intact, instead of falling through as ordinary model prompts.
- **`/plan` now starts the requested planning turn.** A suffix such as `/plan lets implement a new feature` enters dsh plan mode and submits the suffix as the next user message instead of leaving it queued on a temporary idle agent.
- **Fixed coding-agent command and stop lifecycles.** Runtime command results now cross the IPC boundary with the expected shape, `/plan <message>` can start its follow-up turn, and the stop button cancels the live dsh agent instead of only aborting Cairn's wrapper state.
- **Clearing a chat now clears its persisted todo snapshot.** Starting a new conversation from an old thread can no longer resurrect the previous thread's checklist.
- **Coding-agent file guidance now reinforces the configured project root.** The agent is instructed to use relative paths under the session's code directory rather than querying a different checkout, avoiding misleading empty `glob` and `grep` results under the sandbox.
- **Broad coding-agent searches no longer fail prematurely.** The raw ripgrep capture budget now allows large repository listings to be parsed before DSH applies its bounded result limits, while optional empty search paths are explicitly avoided.
- **Removed the duplicate plan/execute toggles.** New coding sessions start in the default DSH mode, while the coding pane shows Plan as passive status; `/plan` and `exit_plan_mode` own plan-mode entry and exit.
- **Read-only Cairn tools no longer prompt for approval.** `get_cairn_context`, `list_folders`, `get_dashboard_constants`, `get_knowledge_graph`, `get_semantic_neighbors`, and `get_project_context_pack` were mis-classified as writes and prompting the user needlessly — training approval fatigue and pushing users to `autoApprove: true`. Reconciled the risk taxonomy against the tool registry and added a test that locks the invariant (every registered tool is classified exactly once, no phantom names).
- **Tool-call chips are keyed by their real callId, not their position in an array.** During a streaming turn or a replay reshuffle, chip identity now survives — a SkillRow's open/closed state can't open on the wrong chip, and plugin-view local state doesn't reset on every token.
- **Sub-agents, plugin views, and long transcripts render smoothly under streaming.** Per-token deltas are batched at the store layer (~1 commit per microtask, coalescing multi-chunk bursts). Plugin views inside `KeyedSlotOutlet` are memoised on the discriminating tool-call fields, so re-mounts on every parent re-render are gone — the disclosure open/closed state of SkillRow, the iframe scroll of visualize, and any plugin `useState` all survive across streaming ticks.
- **Sub-agent traces stop spinning after they finish.** The subagent finalise action was never wired — a completed child block used to spin forever until the pane remounted. Wired through the shared `chat:subagent` bus.
- **Local coding endpoints (Ollama, LM Studio) work with the coding agent again.** The agent pane tagged ANY `localhost`/`127.0.0.1` base URL as the built-in on-device Local Engine, which the coding agent then refused — so a saved Ollama or LM Studio provider was blocked by the very guard that claims to support it (and would otherwise have been silently rerouted to the tiny bundled llama-server). Custom local endpoints now pass through as plain OpenAI-compatible providers with their own base URL; only the chat-only on-device engine keeps the special routing.
- **Restoring the last coding session on app start no longer crashes.** The startup restore still read `db:piSession:sessionMessages` as a bare message array after the channel switched to returning an envelope (`{ messages, usage, todos }`), so launching with a previous coding session failed with "rows.map is not a function" and the session didn't reopen. It now unwraps the same way as manual session resume — including restored token usage and in-session checklists.

### Security-relevant tests restored (pre-merge review pass)

- **Automation approval invariants.** The 308-line security test suite for `automation-approval.ts` was deleted with the pre-Cordis loop even though the production module is still live and load-bearing. Restored (as a smaller, focused suite covering the 5 live functions): `run_script` / `bash` NEVER receive a target-less standing rule, the manifest sanitiser drops unsafe rules with a user-visible reason (not clamped), read-only tools are classified so the gate can waive them, external `mcp__` / `svc__` tools are gate-worthy, `standingRuleTarget` matches what `recordStandingAllowance` persists (so grant/match can't disagree), and `APPROVAL_TIMEOUT_MS` is the documented 10-minute fail-closed budget.
- **Secret-file classification.** The tests for `secrets.ts` (the shell-command secret-exfiltration guard) were deleted while the module is still live and shipped. Restored verbatim: `.env` / `.env.local` / `.env.production` / `*.key` / `id_rsa` / `.npmrc` / `~/.aws/credentials` are blocked; `.env.example` / `.env.sample` / `src/env.ts` are allowed; `bashReferencesSecretFile` blocks `cat`/`grep`/`sed`/`source` of secrets, allows env-variable operations, and `assertCommandNotReadingSecrets` throws `/protected/` without echoing the path.

### Build + CI

- **CI now runs the bundle-guard suite on every PR.** The previous branch had a dedicated `test:bundle` script but no CI job to invoke it. Added a fast-track job that runs `npm run test:bundle` after install so a wrong `esbuild --external`, a missing `@deepseek-ai` package, or a dsh service dropping a peer surfaces here before it silently breaks a real build.
- **CI can run the Electron E2E suite on demand.** A `workflow_dispatch` trigger runs the real Electron QA suite (`tests/e2e/electron/cordis-qa.test.ts`) with `xvfb-run` + `CORDIS_LIVE=1` — invoked manually when a change touches the Cordis integration boundary. The default browser Playwright config now `testIgnore`s the electron path so the two suites don't blur together.
- **`.live.test.ts` files report as SKIPPED, not vacuously PASSED.** Seven live-gated test files (17 tests, ~1054 lines) used an early-return pattern inside `it()` — vitest counted them as passed even though every assertion was skipped. Converted to `describe.skipIf`, matching the repo's own pre-existing convention: the pass count no longer lies about coverage.
- **Fixed lint back to 0 errors / 0 warnings.** The branch had regressed from a clean 0/0 to 64 errors + 50 warnings, and the CI lint job uses `--max-warnings 0`. Two real bugs were hiding in there: `dsh-toolview/index.tsx` was flagged by `react-hooks/static-components` (fixed via `React.createElement`), and `plugin-ui/loader.ts` was flagged by `no-assign-module-variable` (renamed the local `module` shim).
- **`dump-prompt.test.ts` no longer fails on a clean checkout.** The test had zero `expect()` calls (silently passing no matter what it did) and wrote to a gitignored `scratch/` directory that a fresh clone doesn't have — it was CI-red on every clean runner and only green on the author's machine. Moved to `electron/cordis/dump-prompt.ts` as a proper report generator (with `mkdirSync`), and replaced the "test" with a real assertion-based smoke test.
- **`dsh-context-ring` is pinned to an immutable commit SHA.** The dependency was declared as `github:ddutchie/dsh-context-ring` with no revision, so `npm install` would drift silently between developer machines. Pinned to a specific SHA via `git+https://` so every install lands on the same code.
- **Phantom dependencies made explicit.** Seven `@deepseek-ai/*` packages were imported by our code but absent from `package.json`, surviving only on npm's peer auto-install. Any of them dropping a peer or npm changing behaviour would have turned those imports into silent failures. Now direct deps.
- **Session logs are self-limiting.** New age-based sweeper prunes `<userData>/sessions/**` at boot (default 90 days, overridable via `CAIRN_SESSION_MAX_AGE_DAYS`) so a heavy user's disk usage no longer grows unbounded. Resumed sessions are preserved: an old dir with a recently-updated `.jsonl.zstd` survives.

### Under the hood (pre-merge review pass)

- **The dsh type boundary is compile-error-catchable again.** The refactor branch had reached into dsh services through ~50 structural `as unknown as {…}` casts, each hand-copying a slice of dsh's contract with `unknown` args. An upstream signature change produced zero compile errors and a silent runtime regression — the exact opposite of what the whole "runtime is now dsh" refactor was trying to buy. Added `electron/cordis/ctx-augment.ts` — a single side-effect import that pulls in every dsh service's `Context` augmentation. All ~50 casts are now typed direct access (`ctx.sessions.get(id)`, `ctx.compaction.compactNow(agent, signal)`, `ctx.planMode.set(agent, true)`, …). Two real drift bugs the casts were hiding surfaced during the refactor: `ctx.agents.resume({ meta: …, … })` was passing a `meta` key that doesn't exist on `ResumeAgentOptions` (silently ignored), and `ctx.skills.registerProvider(createCairnSkillProvider())` was passing a `SkillProvider` where the API takes a factory `(control) => SkillProvider` (silent no-op). Both fixed as a side effect.
- **`CairnAttachmentStore` retired in favour of upstream's `LocalAttachmentStore`.** The 294-line hand-rolled AttachmentStore (with hand-written PNG/JPEG/WebP/GIF header parsers and an in-memory byte Map) has been replaced by `@deepseek-ai/dsh-attachment-local` — a persistent content-addressed store backed by sharp with proper image normalization, compression limiting, and per-instance concurrency. Limits align with dsh's real defaults (20 MB max image, 20 images per message) instead of the stale hand-copied ones.
- **Plugin UX polish.** Uninstall now confirms before removing files (was one-click destructive on a folder that could hold unpushed work). Install and uninstall both refresh the plugin list on failure as well as success, so a partial install can't leave the UI stale-showing the pre-install state. `PluginBoundary` resets its crash flag when a plugin's children reference changes — a fixed plugin renders again after hot-reload instead of staying blank until the whole app remounts.
- **dsh toolview honours the font-scale.** The vendored `.dsh-toolview-scope` CSS hardcoded 14px / 11px / 24px sizes that didn't scale with the user's font-scale setting. Converted to rem so a user at scale 1.4 sees a toolview chip at 20px like every other Cairn text element.
