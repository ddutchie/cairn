## What's new

### Changed

- **Cairn's session metadata storage uses neutral names.** The post-Cordis metadata tables and indexes are renamed from the old Pi terminology; session logs remain owned by dsh JSONL.
- **Cairn-owned live session IPC channels now use the `session:*` namespace.** The preload bridge, main-process runtime, Cordis integrations, automation forwarding, and renderer-facing test fixtures now share the renamed contract without compatibility aliases.
- **Cairn's agent runtime is now powered by Cordis and DeepSeek Harness (dsh).** The coding agent, chat agent, automations, writing-style helpers, and one-shot AI operations now share the same plugin-based runtime, session model, tool registry, approval seams, compaction, retry handling, and model adapter. This replaces the separate pre-Cordis execution paths.
- **Chat and Coding now share the `session:*` lifecycle IPC contract.** Chat retains its `chat:stream` request entry point, while tokens, thoughts, tools, usage, completion, errors, subagents, and interactive questions use the same session channels and answer path.
- **Chat and Coding now publish the raw DSH session event stream through one `session:event` transport.** Chat pop-outs exchange a session id and reload the shared JSONL history instead of copying conversation state between windows.
- **Chat and Coding fold parent transcript events from the canonical raw session stream.** Text, reasoning, usage, tool calls/results, and turn lifecycle now share one renderer controller while Cairn-specific projections remain explicit.
- **Chat pop-outs are now session-bound views.** A pop-out receives only its session identity and reads canonical session history/events without copying or hydrating the chat-thread Zustand surface.
- **The coding agent now runs on Cordis by default.** File editing, shell access, skills, subagents, attachments, sandboxing, approvals, context compaction, and resumable sessions are composed through dsh plugins rather than Cairn-specific loop code.
- **Cairn now tracks the current dsh runtime packages.** The agent, session, tools, attachment, skill, plan-mode, and supporting Cordis packages are updated together so the desktop runtime follows the upstream plugin ecosystem.
- **Plan Mode is now dsh-native.** DSH owns the logged `plan/mode` state, plan guidance, `/plan` and `/plan off`, and the `exit_plan_mode` review flow. The complete plan is presented through the standard question seam and approval exits at the next dsh step boundary.
- **Commands now use the dsh command registry.** Cairn commands and plugin commands share one executable, logged namespace, including `/plan` and `/compact`.
- **Skills now use the dsh skill registry.** Cairn project skills and plugin-provided skills are merged through one runtime catalog and delivered through dsh's skill tool and invocation path.
- **Runtime context now uses native dsh context snapshots.** Workspace and project identity, descriptions, and code directories are supplied to model requests through the Cordis system-prompt context seam, with per-session isolation.
- **Context and token accounting use shared runtime projections.** The context ring, reasoning provenance, usage breakdowns, and in-session todo state are connected to durable dsh session state rather than independent renderer-only mirrors.
- **A real Electron Cordis QA suite now covers the shipped runtime.** The suite boots the desktop app with an isolated profile and exercises chat, coding, automation, attachments, tool calls, and session persistence through the actual renderer-to-main-to-Cordis path.

### Fixed

- **Session logs are now the source of truth for AI history.** Chat and coding transcripts resume from dsh's append-only JSONL sessions instead of parallel legacy message tables, eliminating history divergence, duplicate bubbles, and lost tool calls across reloads.
- **Session lifecycle and context maintenance are durable.** Resumable sessions, native compaction, request retries, subagent traces, token usage, todo snapshots, and plan state now survive the same session replay path.
- **Tool approvals are enforced through the runtime seams.** Sandbox mode, approval policy, session-scoped grants, per-ask nonces, fail-closed timeouts, and repeated-action protection now share the dsh execution pipeline.
- **Coding-agent security boundaries were restored.** Shell execution uses the sandbox-capable dsh executor, automation-development sessions have their restricted toolset again, and chat does not expose destructive project-management tools without a coding-agent approval path.
- **The dsh interaction contract is preserved through Cairn's renderer.** Native question fields, plan-review details, structured answers, tool-call metadata, attachments, and subagent events are forwarded without losing the fields required by upstream providers.
- **Legacy transcript storage was retired safely.** Existing pre-Cordis transcript data is archived before the old SQLite tables are removed, while new conversations use the dsh session log exclusively.

### Under the hood

- **Chat session execution now uses the shared Cordis profile runner.** Chat retains its streaming, tool, retry, persistence, and live-agent behavior while sharing the lifecycle used by coding sessions.

- **Cordis composition is loader-backed and bundle-safe.** The desktop runtime composes statically bundled dsh plugins through the Cordis loader, retaining plugin lifecycle, dependency injection, disposal, and runtime plugin support inside Electron.
- **The dsh type boundary is explicit again.** Cairn uses dsh's Context augmentations and service contracts instead of hand-copied structural casts, so upstream API drift becomes a compile-time failure.
- **Cairn now uses upstream's persistent attachment store.** The hand-written in-memory attachment implementation was replaced by dsh's content-addressed local store with image normalization and bounded storage behavior.
- **Plugin integration and tool presentation are shared.** Cairn's native tools and community plugins use the dsh tool registry, presentation metadata, skill catalog, and Cordis lifecycle instead of parallel Cairn-only registries.
- **Session logs are self-limiting.** Old persisted session artifacts are pruned by age while recently active sessions remain resumable.
- **The Cordis cutover starts sessions cleanly.** Pre-Cordis chat and coding session indexes are reset instead of archived or resumed; new conversations use the dsh session model from the first turn.

### Build + CI

- **Cordis bundle guards run in CI.** Pull requests verify that the Electron bundle includes the required dsh packages and does not accidentally externalize runtime dependencies.
- **Electron QA is runnable on demand in CI.** The real desktop Cordis suite can be launched separately from browser tests with its isolated profile and live-runtime configuration.
- **Live tests report honestly.** Runtime-gated tests use explicit skipped semantics instead of counting an unexecuted body as passed.
- **The Cordis migration is lint- and type-checked as one system.** Renderer, Electron, shared, native-session, and plugin integration checks run through the normal verification pipeline.
-  Generalized the session pop-out to host shared Chat and Coding conversations.

- **Sessions reopen with their original profile.** Chat, coding, and automation development sessions now persist neutral profile metadata so pop-out and reopen flows can deterministically restore the correct session context.
- **Chat and coding prompts now share canonical session routing.** New prompts declare their profile, existing sessions use persisted `session_profiles` metadata, and both surfaces share session abort and concurrency handling.
- **Obsolete flattened session lifecycle channels were retired.** Chat and coding now expose raw `session:event` data and typed `session:projection` updates without parent `session:token`, `session:thought`, `session:tool`, `session:usage`, `session:step`, `session:done`, `session:error`, or `session:tools-ready` producers.
