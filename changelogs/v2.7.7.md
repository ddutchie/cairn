## What's new

### Changed

- **The coding agent now runs on the new Cordis engine by default.** The agent that edits your files, runs commands, and works through plans has been ported onto Cairn's next-generation runtime, matching the chat engine. Everything you already rely on carries over — plan mode, per-tool approvals, the repeated-action safety pause, skills, image attachments, automatic context compaction, and on-device local models — with resumable sessions and cleaner streaming. This is now the only engine: chat, the coding agent, automations, writing-style, and all one-shot AI helpers route through it.
- **A QA end-to-end suite now boots the real desktop app and exercises every AI loop.** `npm run test:e2e:electron` (with `CORDIS_LIVE=1 CORDIS_DUMMY_KEY=local` and the model bridge running) launches the actual Electron app against an isolated throwaway profile and drives chat ("summarize this project"), the coding agent, and heartbeat automations end-to-end through the real IPC and renderer — confirming the Cordis engine works in the shipped app, not just at the unit level. `CAIRN_USER_DATA_DIR` lets the harness redirect the app's data folder so your real workspace is never touched.
- **Updated the underlying agent runtime (dsh) to the latest release.** Cairn tracks the dsh engine closely; this pulls in the newest agent, session, tools, and attachment packages and adds the skill-registry package, keeping us current with upstream fixes and the plugin ecosystem.
- **Plan mode is now dsh-native.** The coding agent's plan mode is driven by the runtime's own plan-mode controller — the plan policy guidance, the `exit_plan_mode` review flow, and the `/plan` command come from dsh itself. Toggling plan mode now executes the real `/plan` command through the runtime's command registry, so the flip is recorded in the session log (a resumed session keeps its mode), and the UI reflects the authoritative state even when it changes mid-turn. Cairn's custom read-only tool guard was removed to match upstream behavior exactly; as packages evolve, plan mode tracks dsh directly.
- **Cairn commands now live in the runtime's command registry.** `/compact` is registered alongside plugin commands (`/plan`, …) with one shared implementation, and a generic executor lets any surface run registry commands on a session's resumed agent. The command palette now merges these registry commands (executable, logged) above the built-in prompt templates and your custom commands — one namespace for built-ins, plugins, user-defined, and community commands.
- **Skills are now fully driven by the runtime.** Your SKILL.md skills (project `.cairn/skills/` and friends) and skills shipped by installed plugins are merged into one catalog with standard precedence rules. dsh's skill tool owns delivery — it injects the `<available_skills>` list on each step and republishes it when it changes, so a new skill appears automatically, and a `/<name>` message invokes one directly. Chat and the coding agent share the same catalog, and there's a single `skill` tool.

### Fixed

- **The agent settings "Assembled System Prompt" now shows what the agent actually receives.** It previously previewed the legacy prompt builder; it now assembles the real runtime prompt from the dsh SystemPrompt service — the full text, a per-section breakdown (each expandable to its literal text), and the live skills and tool lists, so you can see exactly how Cairn's identity, persona, skills, and tools compose the model input. The old "Discovered Skills" section (and its static `pi-agent:preview-prompt` IPC) was removed — skills are now listed from the shared SkillRegistry in the same view.

- **Chat and coding-agent history is now read straight from the session log, so conversations survive reload cleanly.** Both surfaces rebuild their transcript from the engine's own append-only session log instead of a second copy in the database — the same source the agent resumes from. This ends the duplicated/ghost bubbles, the empty "runtime context" bubble, user messages and tool calls disappearing on reload, and tool chips that stayed spinning after the tool had finished. The legacy database copies of chat and agent messages are no longer written and are purged on launch.
- **Sub-agent traces are replayed correctly after reload.** A conversation that delegated to sub-agents now shows each sub-agent's own block — its instruction/prompt, its tool calls with their outputs, and its findings — reconstructed from the sub-agent's session, attached to the turn that dispatched it. Sub-agent tool calls no longer leak into the main conversation as stray chips.
- **`/compact` works in both chat and the coding agent, and the summary persists.** Compaction now runs through the engine's own compaction (rewriting the session into a summary node) rather than a side transcript, so the compacted history is the real session state — it renders immediately and survives reopening the app. Fixed a crash where a repeated turn could abort the loop with "a user-questions provider is already registered", and fixed one-shot AI helpers (compact summary, commit messages, PR descriptions) that were silently returning empty text on the new engine.
- **Mermaid nodes with light fills are readable again in dark mode.** Diagrams that pin their own fill colours (LLM-generated charts often pick light pastels) rendered white text on a light background, because mermaid's label colour follows the theme. The contrast pass that already fixed subgraph labels now covers regular nodes too — it measures each node's fill and flips the label to a contrasting dark or light colour unless the diagram author set a label colour of their own.
- **Image attachments reach the model again after the runtime update.** The updated agent runtime changed how images are prepared for a model request; Cairn's attachment store now implements the new request-image contract, so pasting or attaching an image to chat or the coding agent works as before (the model sees the image instead of the turn erroring out).
- **"Always allow this command" actually works now.** The approval card's standing-grant button for bash commands was accepted but never honoured — every identical command re-prompted as if only "Allow once" had been clicked. Granted commands are now remembered per agent session (exact command match, whitespace-insensitive), so a workflow you've approved stops nagging without widening the door to different commands.
- **"Always allow this tool" now outlives the current prompt.** Tool grants previously expired at the end of the turn that created them — the next message re-asked for everything. Grants now stick for the lifetime of the agent session and are cleared when you clear or close it.
- **Loop protection now covers approved-and-denied work too.** The repeat-detection guard sits ahead of the approval gate in the tool pipeline, so a model stuck retrying the same write or shell command trips the "repeating the same action" pause even while per-call approvals are enabled — previously that combination silently disabled loop detection.
- **Approval responses are session-scoped.** An approve/deny event can only resolve a confirmation belonging to its own agent session, eliminating a cross-session race between concurrent runs, and pending confirmations are cleaned up when a session is cleared or closed.
