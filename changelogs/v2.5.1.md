## What's new

### Fixes

- **Notes deleted on your phone now disappear on the desktop too.** Deleting a note on mobile removed it from the phone but left it visible on the desktop — the delete synced across as a "tombstone", but the desktop's note list and search didn't filter tombstones, so the row kept showing. Deleted notes (and task cards) are now filtered from every desktop list and search, so a delete on one device correctly hides the item everywhere without leaving it behind or endlessly re-syncing.
- **Chat conversations no longer sync between devices (and no longer bloat sync).** AI chat is a device-local, online-only feature, but chat threads and messages were mistakenly included in the sync set — so every conversation was replicated across devices and made up the bulk of the sync data (hundreds of chat entries re-processed on every sync). Chat is now excluded from sync entirely; existing chat data is purged from the sync log on next launch on both desktop and mobile. Your chat history stays intact locally on each device.
- **Fixed a sync loop that kept "N changes pending" from ever settling.** A combination of issues caused the same batch of changes (e.g. "31") to be re-published on every sync forever: conflicted copies could spawn conflicted-copies-of-conflicted-copies, and deleted notes were being physically removed in a way that made every incoming delete re-apply and re-stage. The engine now (a) never makes a conflicted copy of a conflicted copy, (b) ignores sync entries for things it no longer syncs (like chat) even from an out-of-date device, and (c) keeps deleted items as hidden tombstones so a delete converges once instead of ping-ponging. On next launch the desktop clears out the leftover nested-conflict junk. Together these let the pending count actually reach zero and stay there.
- **Renaming a project relocates its notes folder — and old renames are healed on next launch.** Renaming a project now moves its `.md` files under the new name on disk (e.g. "Test Project" → "Misc" moves `~/Documents/Cairn/Test Project/` to `Misc/`), instead of orphaning them under the old name and writing new notes to a separate folder. On startup the desktop also reconciles any project whose folder still carries an old name from a rename done before this fix — it detects which folder holds each project's notes and moves it to match the current name (merging safely if a folder already exists), so your files consolidate under one folder automatically.
- **Notes can no longer land in a blank "unnamed" folder.** A note created with a whitespace- or slash-only folder value (which an AI assistant could occasionally produce) was filed under an empty folder that showed up as a nameless entry in the notes tree. Such values now collapse to the project root, and the notes tree renders any pre-existing bad entries at the root too, so the phantom folder disappears.
- **Mobile PDF export is safer and handles code correctly.** Exporting a note to PDF on mobile no longer passes raw HTML typed into a note straight through to the renderer (it's now escaped), and Cairn syntax like `[[wikilinks]]` and `> [!callout]` inside fenced or inline code blocks now renders literally instead of being transformed. Callout titles containing characters like `<` also render correctly (they were being escaped twice).
- **Codebase re-index now picks up indexer improvements automatically.** The codebase symbol index caches each file by a content hash (size + modified time), so a file whose contents hadn't changed was skipped on re-index. After the indexer itself was upgraded (e.g. to capture exported `const`/`type`/`interface`/`enum` symbols), previously-indexed files kept their old symbols and a plain re-index couldn't repair them. The cache key now includes a parser version, so bumping the parser invalidates every file on the next re-index. Also added a `force` option to the `codebase_reindex` tool to drop the cache and re-parse everything on demand.

### Under the hood

- **Tag/link merges always converge without dropping edits.** When two devices edited the same note/card's tags or links, the set-union merge now always republishes the complete union — even when the winning side's payload carried an older subset — so no addition is ever silently lost, while still settling (no perpetual re-exchange) once both sides agree.
- **Nested conflict-copy cleanup runs after sync, not just at startup.** Leftover conflicted-copy-of-conflicted-copy junk that lives only in a peer's data is now cleared once it's pulled in during a sync (and the tombstones published so both devices converge), instead of being missed by a startup-only pass.
- **New sync diagnostic.** Added an internal `sync:pendingBreakdown` channel that reports what's currently staged to sync (grouped by type and operation, with sample ids) — used to investigate a pending-changes count that doesn't settle.
