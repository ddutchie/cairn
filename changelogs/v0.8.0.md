# v0.8.0 — Card dependency system

## Card dependencies

Tasks can now block each other. A card marked as blocked by another will not appear as ready to work on until its blockers are resolved — moved to a done column or archived.

### How it works

- Open any card detail → **Blocked By** section in the sidebar metadata panel
- Pick any active, non-done card in the same project as a blocker
- The blocked card shows a **lock icon** with a blocker count on the kanban board
- Resolved blockers (done / archived) appear greyed-out and can be removed
- Blocking a card is **rejected with an error** if it would create a circular dependency (A blocks B blocks A)
- **Deleting a card** automatically cleans up its ID from any other card's blocker list — no orphaned references

### Visual indicators

- Kanban card chip: lock icon + blocker count (e.g. "1 blocker") in amber when the card has active blockers
- Card detail sidebar: **Blocked By** section with rich chips showing blocker title, column name, resolved state, and a remove button

### MCP tools

Three new tools available to AI agents:

| Tool | Description |
|---|---|
| `block_task` | Mark a task as blocked by another task in the same project |
| `unblock_task` | Remove a blocking dependency |
| `list_ready_tasks` | Return only unblocked, active tasks — the agent equivalent of `bd ready` |

`get_task` now includes `blockedByIds` in its response.

`list_ready_tasks` is the key workflow improvement: agents can call it instead of `list_tasks` to get a pre-filtered list of work that can actually start right now, without reasoning about status themselves.

### Technical

- DB migration v7: `blocked_by_ids TEXT NOT NULL DEFAULT '[]'` column on `task_cards` — JSON array, same pattern as `linked_note_ids` and `tag_ids`
- Circular dependency detection: DFS graph traversal across the project's card graph, run before every `addBlocker` call in both IPC and MCP paths
- `getReadyCards` query: joins to `board_columns` to check `type = 'done'` — works correctly with custom column names, not just the column name string
- `createCard` in `queries.ts` also gained the missing `assignee` field in its `INSERT` statement (previously silently dropped)
