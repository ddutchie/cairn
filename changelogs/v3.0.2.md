## What's new in Cairn 3.0.2

### Fixed

- **Sync no longer recreates a deleted checklist note as a conflict.** Deleting a note on mobile while the desktop was closed (or vice versa) could make the other device resurrect the note as a “conflicted copy” instead of deleting it — especially for notes with many `- [ ]` / `- [x]` checkboxes, where the desktop’s last offline toggle was kept as a live recreation that looked like the delete had failed. The engine now only preserves a divergent body as a conflict copy when the losing `put` is *newer* (higher HLC) than the winning `delete`; an older stale snapshot is just the pre-delete state and is discarded, so a delete performed while the peer is offline propagates cleanly and both devices converge without a spurious conflict. A trailing-newline / CRLF difference (matter round-trip, Windows import) is also no longer treated as a divergent edit — bodies are compared after stripping `\r` and trailing whitespace, matching the import ledger’s `bodyHash` (`shared/sync/engine.ts:normalizeForSyncBody`, `reconcileOne` put-put and delete-wins paths, `preserveRejectedNotePut`).
- **Spurious conflicts from file round-trips.** A desktop note file written with `gray-matter` gains a trailing newline that the DB row does not have; the sync 3-way check previously treated that as a remote change, so a note the user never touched could still spawn a conflict copy on the next edit. The comparison is now normalized (`CRLF → LF`, `trimEnd`) before `localChanged` / `remoteChanged` and when deciding whether a rejected put equals its ancestor.

### Changed

- **Sync protocol v3.** The oplog now carries `v: 3` (`SYNC_PROTOCOL_VERSION = 3`). A peer still on v2 is reported as `behind` in Settings → Sync / mobile Sync screen’s “device needs updating” hint until it updates — otherwise the fleet would converge to the old “always keep the stale snapshot” outcome for one more sync. Additive `observed` / `tombstone` fields remain optional for back-compat; no migration.
