# v0.3.8

## What's new

### MCP server — self-contained binary
The MCP server is now shipped as a self-contained executable (`cairn-mcp` on macOS, `cairn-mcp.exe` on Windows, `cairn-mcp-linux` on Linux) that bundles Node 22 and its own `better-sqlite3` native binding. This means:

- **No system Node dependency** — the MCP server works regardless of what version of Node (or no Node at all) the user has installed
- **No ABI mismatch** — the bundled Node runtime and native binding are always compiled together, so connection failures caused by NODE_MODULE_VERSION mismatches are eliminated
- **Simpler config** — the OpenCode / Claude config snippet in Settings now points directly to the binary with no `node` prefix required

The Settings → MCP page will show the updated config snippet automatically. If you have an existing `opencode.json` pointing to `mcp-server.bundle.js`, update it to point to the `cairn-mcp` binary instead (path shown in Settings).

## Internals

- `scripts/build-mcp-binary.js` added — wraps `@yao-pkg/pkg` to produce platform-specific binaries from `dist-mcp/mcp-server.bundle.js`. Run via `npm run build:mcp-binary`.
- `scripts/rebuild-native.js` updated — now builds `better-sqlite3` for the pkg-bundled Node 22 target (output: `pkg-native/better_sqlite3.node`) in addition to the Electron ABI build. The old `mcp-native/` system-Node build is removed.
- `electron-builder.yml` updated — packages `dist-mcp/cairn-mcp*` binaries (unpacked from asar); removes `mcp-native/` from files and asarUnpack.
- `app:mcpServerPath` IPC handler updated — returns the platform-appropriate binary path instead of the JS bundle path.
- Settings config snippets updated — `command` is now `[mcpServerPath]` with no `node` prefix.
- CI workflow updated — `node scripts/build-mcp-binary.js` runs after `npm run compile` on all three platform jobs.
