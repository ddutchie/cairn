## What's new

A live sync status indicator in the title bar, and a way to see and resolve — or merge — sync conflicts.

### New

- **Sync status in the title bar.** When Device Sync is connected, a small cloud indicator now sits at the right of the title bar showing the live state — synced, syncing, offline, changes pending, or conflicts waiting. Click it for a popover with the last-sync time, pending-change and conflict counts, and a **Sync now** button. It stays hidden entirely when sync isn't set up.
- **See and resolve sync conflicts on desktop.** When the same note was edited on two devices at once, Cairn keeps both versions (the losing side becomes a "conflicted copy") so nothing is lost — but until now the desktop app gave you no way to reconcile them; they just piled up as extra notes. A new conflict banner appears under the title bar when conflicts exist, and opens a resolution dialog showing the current note and the conflicted copy side by side, with a choice per conflict: **Keep current**, **Use copy**, or **Merge**. This mirrors the mobile Sync Conflicts screen.
- **Merge conflicting note edits.** The new **Merge** option combines both edits rather than forcing you to discard one. Non-overlapping changes (for example, you appended a different checklist item on each device) are merged automatically into a single note using the common ancestor the sync engine tracks. When both devices changed the *same* lines in different ways, an editable box opens pre-filled with the best-effort merged text so you can reconcile it by hand — Cairn never injects `<<<<<<<` conflict markers into your note. The same merge is available on mobile.

The conflict dialog now updates live — if a background sync surfaces a new conflict while the dialog is open, it appears without reopening — and the Device Sync settings panel links straight to it when conflicts exist. The status popover's "last synced" time also ticks so it no longer freezes between syncs.

### Fixes

- **Idle syncs no longer re-touch the sync file.** The background sync loop publishes this device's oplog on every tick. Because writes now reliably land in place (see v2.4.11), that meant an idle device kept re-writing an unchanged file, which made the cloud provider re-upload it needlessly. The writer now skips the write entirely when the on-disk content is already identical, so an idle device stops churning its synced file.
