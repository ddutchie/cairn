# v1.2.1

## What's new

### Features

- **Plan Mode** — the Cairn Agent can now be launched in Plan Mode. The agent reads your codebase (read-only tools only) and writes a PRD note rather than making changes. A mode badge appears in the chat header and an Approve Plan button promotes the session to Execute Mode, injecting the full PRD as context for the coding run. The plan note title is derived from the feature name (e.g. `Plan: Dark mode toggle`).

- **Task archive management** — the Done column now has an "Archive all done" option in its `⋯` menu that bulk-archives every active card in one click. A new **Archive view** (Board / Archive toggle tab above the board) shows all archived tasks in a searchable grid with per-card Restore and Delete buttons, tooltips, click-to-open detail modal, and a "Delete all" button on the filter bar. Archived tasks are now included in all Insights canvases and the Knowledge Graph.

- **MCP archive tools** — two new MCP tools: `archive_task` (sets `archived_at`) and `restore_task` (clears it; queries the DB directly since archived cards are filtered from the snapshot). `list_tasks` gains an `includeArchived` parameter that returns archived cards grouped with column info and a restore hint.

- **Streaming test suite** — `electron/lib/pi-agent-loop.test.ts` — 8 mock scenarios (real Node HTTP server per test) covering: text-only, tool-call with no text, text-then-tool, multi-turn `onStepStart`, split SSE chunks, usage chunks, no-text tools-ready ordering, and parallel tool calls. Two live integration tests run against `TEST_LLM_BASE_URL` when `.env.test` is present (skipped otherwise).

- **`normaliseBaseUrl` helper** — strips trailing `/` and `/v1` from LLM endpoint URLs. Used in `pi-agent.ts`, `chat.ts`, `handlers.ts`, `AISettings.tsx`, and the test suite.

- **Incremental graph recompute** — `computeAutoRelationships` now accepts an optional `entityIds` array. `db:note:update` and `db:card:update` call the incremental variant, limiting recompute to affected nodes only. `GraphAIPanel.applyAction` collects affected IDs and triggers the same path.

- **AI visibility decoupled** — `aiEnabled` now controls only the inline AI suggestion buttons. View/nav visibility is controlled exclusively by `hiddenViews`. The two settings no longer affect each other.

### Fixes

- **Tool chips only appeared after stream completion** — root cause: the loop buffered all tool calls and only fired `onToolsReady` + `onToolStart` after `[DONE]`. Fixed by firing `onToolPending` during SSE streaming as soon as a tool name first appears in the delta, mirroring pi's approach of creating chips imperatively during `message_update`. The chip is now in the DOM within milliseconds of the LLM deciding to call a tool. `onToolStart` at execution time reuses the same `callId` to update the existing chip's label rather than creating a duplicate.

- **Tool chip spinner never showed (React 18 batching)** — even after the streaming fix, `onToolStart` and `onToolEnd` IPC messages arrived close enough together that React 18's automatic batching coalesced them into a single commit. Added `flushSync` around `addPiToolCall` to force a synchronous DOM commit before execution proceeds.

- **Tool chip race on IPC delivery** — `addPiToolCall` silently dropped chips when `onToolsReady` and `onToolStart` arrived in the same microtask batch (before `ensurePiStreamingMessage` had applied its state update). Fixed by making `addPiToolCall` atomically create the streaming message itself when none exists — same fix applied to `addPiSubagentToolCall`.

- **Main process blocking renderer IPC** — synchronous SQLite tool executions (Cairn DB writes) blocked the main process event loop between `onToolStart` and `onToolEnd` sends, causing both IPC messages to be delivered together. Added a `setImmediate` yield after `onToolStart` to flush the IPC queue before tool execution.

- **Archive all done — no re-render** — `getColumnCards` / `getArchivedColumnCards` are stable function references; `useShallow` never saw them change after bulk-archive. Added `cards: s.cards` to the board's shallow selector so any cards mutation triggers a re-render immediately.

- **Null task titles** — `create_task` in chat-executor, mcp-server, and the `db:card:create` handler now validate and trim titles. `spawn_tasks_from_note` skips blank-title items.

- **Blocker auto-clear on Done** — `db:card:update` (drag-and-drop path) now calls `clearBlockersFromAll` when `patch.columnId` resolves to a done-type column. Previously this only ran through MCP/chat-executor paths.

### Changes

- `pi-agent:tool` IPC event gains `status: "pending"` (fired during stream) and an optional `callId` field that links the pending chip to the execution-time start event.
- `onToolStart` callback gains an optional `callId` parameter.
- `addPiToolCall` and `addPiSubagentToolCall` in the terminal-sessions store update an existing chip in-place when a matching `callId` is found, rather than appending a duplicate.
- `getArchivedProjectCards` selector added to `SelectorsSlice`.
- `GraphNode.meta` gains `isArchived?: boolean` — set for archived cards included in the graph.
- `loadGraph` card query no longer filters `archived_at IS NULL`; archived cards appear in `graphData.nodes` with `meta.isArchived: true`.
- `useScopedData` no longer filters `!c.archivedAt` from `scopedCards`; canvases that previously added inline `!c.archivedAt` guards (BulletCanvas, BeeswarmCanvas, SankeyCanvas) have those guards removed. BulletCanvas counts archived cards as done. SankeyCanvas routes archived cards to the `"done"` bucket.
- `.env.test` (gitignored) + `vitest.config.ts` dotenv loading for live test endpoint configuration (`TEST_LLM_BASE_URL`, `TEST_LLM_MODEL`, `TEST_LLM_API_KEY`).
- `~/.zshenv` created to run `path_helper` for all zsh instances, ensuring `node`/`npx` are on PATH in non-interactive shells.
