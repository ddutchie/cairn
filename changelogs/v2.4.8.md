## What's new

The built-in AI assistant now uses a much leaner system prompt with no change to what it can do.

### Under the hood

- **Trimmed the AI Chat system prompt (~960 → ~240 tokens).** The prompt previously restated per-tool guidance (Notes / Tasks / Dashboards / Idea Flow / Knowledge Graph sections) that the model already receives from each tool's own description. A live tool-selection experiment showed the assistant picks the right tool at least as reliably — actually slightly better — with a prompt that keeps only the cross-cutting rules (obtaining IDs, confirming after writes, the suggest-connections behaviour, and markdown/mermaid rendering) and leans on the tool descriptions for the rest. An opt-in regression test (`electron/lib/prompt-optimization.test.ts`, skipped unless an LLM endpoint is configured — no secrets in source) guards that the trimmed prompt keeps selecting tools at least as well as the old one.
- **Slimmer AI tool definitions (~5,090 → ~4,630 tokens per request).** The JSON tool schemas sent to the model on every chat turn carried mechanical validation noise that the model never uses — giant ISO-8601 date regexes, integer min/max bounds, defaults, and `additionalProperties` flags (server-side validation is unchanged and still enforces all of it). Stripping that noise from the emitted schemas shrinks every request with no change to tool selection or argument correctness — verified by a live experiment across single-turn and multi-turn (chained) tool sequences. Field descriptions are kept, since those genuinely help the model fill arguments.
- **Leaner project-context tool responses.** `get_project_context_pack` (used by the AI assistant and MCP clients) previously embedded up to 1,000 characters for *every* pinned note with no limit on how many, plus every open task's description — a busy project could return 5,000+ tokens in a single call that then rode along in the conversation for the rest of the session. It now returns the 5 most-recent pinned notes with a short excerpt (and a `pinnedNotesTotal` count) and caps open tasks with short previews, cutting a busy project's response ~70%. The assistant fetches full content on demand via `get_note` / `get_task`.
