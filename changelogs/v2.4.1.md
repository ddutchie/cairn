## What's new

A focused fix release for the board: drag-and-drop now drops where you aim, and dragging cards stays smooth on large boards. Also includes a store-wide responsiveness improvement that benefits every view when the database changes.

### Fixes

- **Board drops land on the right column again**: Dragging a card onto a column (or onto another card) was unreliable — depending on screen size and how far the board had scrolled, only the furthest columns would accept a drop, while the Archive/Delete zones worked fine. Collision detection now resolves the drop target from the actual pointer position instead of the dragged card's estimated rectangle, which drifted during horizontal auto-scroll. Dropping onto columns, reordering within a column, and moving between columns all work consistently across window sizes.
- **Column highlights when hovering a card**: While dragging, the target column now highlights even when the pointer is directly over one of its cards (previously the highlight only appeared over empty column space).
- **Duplicate drop-target registration removed**: Each column was registering two overlapping drop targets under the same id, which made the board's hit-testing inconsistent. Each column now exposes a single, full-height drop zone with a larger, more forgiving hitbox.

### Changes

- **Much smoother card dragging on busy boards**: Dragging a card no longer re-renders every other card on the board on each pointer move. Columns and cards are now memoized, per-card click handlers are stable, and the card's heavier content (markdown description, tags, tooltips, due-date/blocker footer) is split out and reused across the frequent drag-driven re-renders instead of being rebuilt every frame.
- **Faster switch to the Board view**: Opening the board no longer renders full markdown for every card up front. Collapsed cards now show a lightweight text preview (the same two truncated lines you already saw), and the full markdown formatting renders only when you expand a card. On boards with many descriptive cards this removes a noticeable delay when switching to the Board.
- **Markdown previews stop re-parsing needlessly**: The shared markdown renderer (used by board cards, the archive view, the knowledge-graph detail panel, flow AI-summary nodes, and the agent editor) is now memoized, so it only re-runs its full parse pipeline when the content actually changes — not on unrelated re-renders.
- **Database refreshes no longer churn the whole UI**: Whenever the app re-syncs from the local database (after a move, an MCP/AI write, or a background file change), it previously replaced every workspace, project, note, column, card, and tag with brand-new objects — forcing the entire board (and other views) to re-render and, in the board's case, causing a hitch mid-drag. The refresh now preserves the identity of anything that hasn't actually changed, so unchanged items are left untouched and only genuinely modified rows trigger a re-render.
