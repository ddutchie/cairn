## What's new in Cairn 3.2.0

### Changed

#### A new agent engine

- **Cairn now runs its own agent engine.** Chat, coding sessions and automations share one engine built on the pi-ai provider layer, replacing the DeepSeek harness (`@deepseek-ai/cordis` and the `dsh-*` packages), which has been removed along with its patches. Subagents, goals, reminders, background jobs, persistent terminals, language-server navigation, workflows, Claude Code / Codex command hooks, plan mode, slash commands and context compaction all run on it. Reply speed (time to first token, tokens/s, output tokens) and timeline chips for slash commands and plan-mode toggles are shown as before; speed isn't available on messages reloaded from older sessions.
- **Your history carries over.** Sessions recorded by the previous runtime are imported the first time you open them; clearing or deleting a session also removes the old copy.
- **Smaller install.** Dropping the harness removes about 230 packages, including the native FFI module and the Windows sandbox runner.
- **Agent shell commands are sandboxed.** On macOS (seatbelt) and Linux (bubblewrap) the agent's `bash`, background jobs and persistent terminals can only write inside the working directory and temp/cache folders; reads and the network stay open, and sandboxed Linux commands get their own process namespace. The agent is told how its commands are confined. If a command genuinely needs more, the agent can request `unsandboxed` and is asked to say why. The approval card shows its reason, or "(no reason given)", and it asks you every time and can't be remembered. If the sandbox is on but can't start (bubblewrap missing or blocked, or macOS refusing to nest `sandbox-exec`), commands ask before running unconfined and model terminals refuse to start, rather than silently skipping it. Toggle it under Settings → Coding agent → "Sandbox shell commands", which also shows when the sandbox is unavailable (Windows has no sandbox).
- **Plan mode can run shell commands.** They run in a read-only sandbox (only temp folders are writable), so the agent can inspect the repo with `git log`, `rg`, test listings and the like while planning but can't write to your files. The network stays open, so a command can still change data on a service it can reach. If the sandbox is off or unavailable, plan mode still blocks the shell.
- **Auto permission preset for coding sessions.** A model reviews each risky action: routine ones run, dangerous ones are blocked, unclear ones ask you. External tool calls and sandbox escalations always ask, and Auto pauses to manual after repeated blocks.
- **The AI can search your earlier chats and coding sessions.** `search_sessions` and `read_session` look up past work in the workspace you are in (for example "what did we decide about the export format?") and read the exact messages. With embeddings turned on, matches are found by meaning as well as by words (the index fills in as you chat and when you search). They only read, so they never ask for approval.
- **Coding sessions read project instructions.** The project's `AGENTS.md` / `CLAUDE.md` (with `@file` imports and parent directories up to the repo root) go into the system prompt on every message.
- **Skills run by name** in coding sessions with `/<skill-name> [task]`.
- **Command hooks report what they block.** A prompt refused by a `UserPromptSubmit` hook stays in your transcript with the hook's reason, but is never sent to the model, now or after a restart.
- **A reply that comes back empty says so.** A turn that ends with no text and no tool calls (reasoning only, or the output limit was hit) now shows an error instead of ending silently.
- **Local (stdio) MCP servers run on the new engine.** They connect through Cairn's MCP client alongside remote servers; the dev-only "Route via dsh" toggle is gone.
- **Settings tool lists reflect the real toolsets.** They are now built from the engine's own tools for each surface.
- **The writing-style wizard** reads notes and tasks through the same engine, limited to read-only tools.
- **Session reminders stay opt-in.** The tools are only offered when the setting is on.
- Model requests carry the session id, so providers that support prompt caching (OpenAI-style cache keys, OpenRouter affinity) can reuse the prompt prefix.
- **Long sessions reuse far more of the provider's prompt cache**, which lowers cost on hosted models and cuts prompt re-reading on local ones. Old tool output and images are now trimmed from requests in large steps instead of a little on every step. Approving a plan no longer changes the system prompt or the tool list (the plan and the plan-mode notes travel with the prompt instead). Connector tools are listed after the built-in ones, so a server that connects late no longer shifts the rest.

#### Chat

- **The working indicator shows what Cairn is doing.** The blinking caret is replaced by a small animated loader that changes with the phase of the turn: waiting for the first token, thinking, writing the answer, running a tool, retrying after a transient error, compacting context, or waiting for your answer. The same loader sits in the composer's busy strip and at the end of the transcript, and follows your theme and accent colour.
- **The chat panel no longer gets stuck at full width.** The side panel shrinks to fit when the window gets smaller (down to 240px) and can always be dragged narrower. If the window is too narrow for even a minimum-width panel beside the main view, chat opens in the expanded chat view instead; widening the window brings the side panel back, and leaving the expanded view closes the chat.
- **The chat session switcher matches the rest of the app.** It's a single-line picker that opens a floating list with the same rows as the sidebar's conversation list. It also lists sessions from your other projects under their project names, so a conversation started in another project is one click away.

#### First run

- **Onboarding makes Cairn yours.** It opens with a short "What it is" panel, then appearance (theme, font size and font), then folder, workspace and project. AI setup moved out of the first run: add a provider in Settings → Models, or from the chat dialog that opens when you send a message without one.
- **Vault import is reviewed on the project step.** Projects found in your vault are listed with an undo option, and the separate import screen is gone.
- **Last onboarding step is "Ready to start".** It shows a "Start the demo" switch instead of the feature cards. Turn it off to skip the walkthrough.
- **Starter project.** "Start with a sample project" creates a Getting started project with a welcome note and two cards, so the board and the app tour have something to show.
- **The app tour covers the current app.** It has steps for search, the Agent, Automations, Insights and the Knowledge Graph, and Settings, and points at the redesigned sidebar and the Chat button.

#### Look and feel

- **A tidier sidebar.** There's one Calendar entry, with a This project / All projects switch in the calendar itself; the entry and its shortcut reopen whichever you used last. The all-projects calendar no longer holds a shortcut of its own, so Knowledge Graph, Insights and Automations move up to ⌘7–⌘9. Notifications live on the bell only. The active project's name sits in its own bordered button above the progress card, so it reads as a dropdown; the progress card below is read-only.
- **Settings is reorganised and searchable.** It's one list of pages grouped as App, AI, Extensions and Data, with no tabs inside pages. A search box above the list jumps straight to a setting and highlights it. Community providers and local-server detection have their own Models page, instead of appearing on both the Chat and Coding agent pages. Tags and Sidebar & views have their own pages. The page that lets Claude Desktop or OpenCode use Cairn is now called "Connect other agents", so it's no longer confused with the MCP servers Cairn itself uses (under Tools).
- **Number settings use one control.** Max steps, temperature, context window and max output tokens show their presets, Auto and a custom value in a single row of options. Tabbing through the custom field no longer switches Auto off.
- **Insights names every chart.** All eight canvases are labelled in a tab strip instead of showing only icons, and the ridgeline style and time-range zoom are labelled.
- **Automations read in plain words.** Schedules show as "Weekdays at 08:00" or "Every 6 hours", with the cron expression in a tooltip. Run and Edit are labelled buttons, the other actions are under "⋯", and a paused automation says "Paused".
- **Every icon button looks and behaves the same.** About 150 icon-only buttons across the app share one shape, a visible accent focus ring when you tab onto them, and a styled tooltip with a screen-reader label. Other buttons that only had the slow system tooltip now show the app's own, and settings buttons are announced by their own text ("Browse Community", "Export") rather than the row they sit in.
- **Menus and pickers behave consistently.** The new-session menu, note export, graph label mode, Idea Flow's "Add node", tag colour and tag pickers, and the sync status panel use the app's shared menu and popover components. They close on outside click and Escape, support the keyboard, and return focus to the button that opened them.
- **Text sizes, shadows and labels are consistent.** Interface text follows one four-step scale instead of more than a dozen near-identical sizes, so the smallest labels are a little easier to read. Menus, popovers and dialogs use three shadow levels that look right in both themes. Section labels and buttons use sentence case, except the sidebar's group headings, and dates and status words are no longer set in monospace.
- **Smaller touches:** search shows its keyboard hints and result count once. Terminals follow light and dark mode and your accent colour. The agent's structure panel appears when you open a file. Empty screens say what to do next.

#### Search

- **Semantic search finds exact names and ids, and stops repeating itself.** Notes and tasks combine meaning-based search with full-text (FTS5) matching, boost results that contain every search term, and spread near-duplicate results apart. This applies to related-note suggestions and semantic `search_notes` / `search_tasks` (`mode: "semantic"`) in chat and over MCP, which may now return fewer results when only a few are clearly relevant.

#### Under the hood

- **Dependency updates.** Electron 45 (Node 24.22), Next.js 16.4, React 19.3, Mermaid 12, the pi-ai provider layer 1.4, three.js 0.187, KaTeX 0.19, Vitest 5 and jsdom 30, plus current Radix UI, Lucide, Playwright, AI SDK, nanoid, chokidar and gpt-tokenizer releases. The embeddings runtime moves to onnxruntime-node 1.23.2, which still ships the Intel Mac build. No change to how Cairn looks or behaves.
- **Linux downloads are about half the size.** The Linux AppImages bundled NVIDIA GPU libraries (CUDA and TensorRT, ~350 MB) that Cairn never uses, plus the other architecture's embedding runtime. They are now stripped from the package, bringing each AppImage from ~425 MB down to roughly 190 MB.

- Experimental: with `CAIRN_STAGED_TOOLS=1` (or `agentConfig.stagedTools`), coding sessions load terminals, language-server lookups, goals, reminders and workflows only when the agent asks for them through an `enable_tools` tool, instead of sending them on every request. Off by default; there is no setting for it yet.

### Removed

- **The local-network Mobile Access server is gone.** Settings → Mobile Access (the QR code / PIN web companion that served Cairn to a phone browser) has been removed, along with its LAN server, so Cairn no longer opens a network port for it. The Cairn mobile app is unaffected: use Settings → Device sync to keep your workspace in step with your phone. Leftover `mobile-config.json` and `mobile-sessions.json` files (including the old PIN) are deleted on first launch.
- **The unreleased Plugins preview is gone.** Settings → Extensions no longer shows a Plugins tab, and the developer-only plugin loader (`CAIRN_PLUGINS_DEV`) has been removed. Tools, Commands and MCP servers are unaffected.

### Fixed

#### Chat and agent

- **Chat stays on the latest message.** Once a conversation filled the panel, new replies, and even your own message, could land out of view. The transcript now follows new content until you scroll up, picks up again when you return to the bottom, and always jumps down when you send. A slow scroll up during a reply is no longer pulled back down by each new line.
- **Deleting a coding session removes it for good.** It only left the Agent view's list: its history stayed on disk, the AI could still find it when searching past work, and it could reappear elsewhere. Deleting now removes its history, its search index and its subagents' history too, as deleting a chat already did.
- **The right provider is checked before sending.** Coding sessions in the Overview and in pop-out windows checked the chat provider rather than the coding one.
- **The Overview's model picker follows the mode.** In Coding agent mode it changed the chat model, so the session ran on a different model from the one you picked. It now sets the Coding agent's model.
- **A failed AI edit leaves your note alone.** If an AI action in the editor failed partway, its partial text still replaced your selection.
- **Suggested chat prompts ask for a provider first.** With no AI provider, clicking a suggested prompt started a turn that spun forever. It now opens the provider dialog and keeps the prompt in the input.
- **The expanded chat view names the open conversation.** Its session switcher said "Choose a session" even with a chat open; it now shows that chat's title.
- **Search can ask the AI.** The search bar and tour promised this, but only searching worked. Every search now offers "Ask AI", and Enter asks when nothing matches.

- **A reply cut off at the output limit says so.** It used to end as if it were complete; now it tells you to ask the agent to continue or raise the limit.
- **Subagents no longer touch their parent's checklist, goal or reminders.** A subagent's todo list replaced the session's own in the UI, and it could mark the session's goal complete.
- **A session resumed after a restart sends the model the same conversation it had.** Context added by hooks, and the follow-up a Stop hook asks for, were missing from the saved log, which could make a compacted session fail to continue.
- The coding agent's instructions name the `subagent` tool correctly.

#### Providers

- **The provider dialog waits for you.** It no longer checks the default endpoint and shows "the endpoint refused the key" before you have typed anything. It says why it opened, fetches models as you enter a key or a local address, and picks a real model from that list.
- **The provider form settles when you change it.** Clearing the key during a check could leave "Checking…" on screen, and a slow response from the previous endpoint could pick a model the new one doesn't have.
- **You can use a provider you already saved.** The chat and agent "Add a provider" dialog lists saved providers, so a second surface doesn't need the same details again.
- **Providers without a key work.** A self-hosted provider on your network could be saved but never used, because chat kept asking for a key. Any provider you select now counts. The Coding agent checks its own provider, and a provider added from its composer becomes the agent's.
- **Provider errors read plainly.** A rejected key, a rate limit or an unreachable server gets a sentence saying what to do instead of raw JSON from the provider. When the fix is in AI settings, the main window also offers a button to open them.
- **AI settings no longer crash before you add a provider.** Opening them with no saved providers froze the app ("Maximum update depth exceeded"); they now open normally.

#### Onboarding and the app tour

- **Onboarding has Back on every early step**, including Appearance and choosing a folder. Back only appears when there is still something to change, so going back from the last step can't create a second copy of your first project.
- **Quitting during onboarding resumes it.** If you close Cairn after naming your workspace, the next launch returns to the project step instead of an empty app. If you were reviewing a vault import, you return to that review, with Undo.
- **A project that couldn't be saved says so.** Onboarding used to carry on as if it had worked, and the project could then vanish. It now shows the error so you can try again, and the sidebar reports it too. The same goes for the starter project's note and cards.
- **A project is selected when onboarding ends.** The first project opens on the Overview instead of an empty state.
- **Undoing a vault import works cleanly.** Choosing the folder again after an undo imports it (it used to import nothing and leave a second workspace). Notes at the top of the vault have Cairn's frontmatter removed like everywhere else, your own frontmatter stays, and a symlink can no longer lead the undo to a file outside the folder.
- **New users skip What's New.** It no longer appears right after onboarding, since there is nothing to compare it to, and the tour starts straight away.
- **The app tour shows every step.** Several steps looked for elements the sidebar redesign had removed, and others (Agent, Automations, Insights, Settings, Search) were skipped after a pause, so the tour flew through. Steps now wait up to four seconds for their target, outline the visible copy of controls that exist in both sidebar layouts, and open the sidebar's Workspace group if you had it collapsed. With the sidebar collapsed to icons, steps with no icon to point at are still skipped.
- **The app tour no longer starts without a project.** Skipping project creation used to start a tour whose steps pointed at things that didn't exist. The tour option is hidden until a project exists.

#### Elsewhere

- **Sidebar shortcut hints match the keys again.** The sidebar showed Overview as ⌘3 and Board as ⌘5; it now shows ⌘1 for Overview, ⌘2 for Notes and ⌘3 onwards for the other views, the same keys that switch to them.
- **Shortcut hints match your platform.** The starter note and the Overview showed ⌘/ on Windows and Linux.
- **Running-automations bar shows only on the Automations view.** It was covering the top of every other view while automations ran.
- **A new board isn't told it has a bottleneck.** A column is only called the bottleneck when it holds at least three cards and most of the open ones.
- **Counts read properly.** "1 project" and "1 note" replace "1 projects" and "1 notes".
- Device Sync's setup note no longer runs two words together ("installedfor").
