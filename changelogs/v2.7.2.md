## What's new

### Added

- **Queue messages while the assistant is working.** When a reply (or coding-agent run) is in progress, the composer stays active — sending adds your message to a queue instead of being blocked. Queued messages show in a pinned, collapsed strip above the input (count by default, expand to see each message truncated + Remove), then send automatically (in order) when the current reply finishes. Stopping only cancels the in-flight turn; queued messages still go through, and a failed turn still lets the queue continue.
- **Chat threads keep their chain-of-thought across restarts.** The raw Responses reasoning items (plus the reasoning field and model that produced them) are now persisted on chat messages, so a resumed thread round-trips the prior reasoning to the same model — keeping multi-turn tool loops on GPT‑5.x/Luna consistent after an app restart, not just mid-session.

### Changed

- **The coding agent's and chat's transcripts are now virtualized.** Only the messages near the viewport are mounted, so sessions and threads with thousands of messages (each with reasoning, tool chips, and subagent traces) stay smooth — you can scroll from the newest message all the way back to the start and the render cost never grows. (Mobile chat keeps the standard lightweight rendering.)
- **Condensed reasoning summaries are now requested for reasoning models.** Chat and the coding agent ask the Responses API for a concise summary (`reasoning.summary`) on reasoning models, so the collapsed Thinking panel shows a real summary instead of an empty one.

### Fixed

- **Env and config dotfiles are visible in the agent's file browser.** The agent file tree (and its file search) hid every dotfile, so `.env`, `.gitignore`, `.editorconfig` etc. couldn't be opened or edited. Only `.git` and `.DS_Store` are now hidden — everything else, including env files, shows up and can be edited from the tree.
- **The agent is blocked from reading or writing secrets.** The coding agent's `read`/`write`/`edit`/`grep` tools refuse secret-bearing files (`.env*`, private keys, `.npmrc`, credentials), so chain-of-thought and exports can't leak them. Env *templates* like `.env.example` stay readable, and you can still open and edit `.env` yourself from the file browser.
- **Reasoning items are replayed with their `summary` field intact.** When the previous turn's reasoning carried a summary array (even an empty one), the round-trip now sends it back — strict Responses providers reject a reasoning item that omits `summary` when encrypted reasoning content is replayed.
- **Strict Responses endpoints that reject optional fields are retried stripped.** Chat and the agent loop now retry a 400/422 once without `temperature`, `reasoning.effort`, `reasoning.encrypted_content`, and the condensed reasoning-summary request — matching compaction — so models that refuse those fields still respond.
