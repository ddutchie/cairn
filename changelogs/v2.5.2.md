## What's new

### New

- **Distraction-free note editing.** A new fullscreen toggle in the note editor's toolbar hides the notes list so the editor fills the window — in both Write and Read modes. Toggle it with the expand/collapse button or `⌘.` (Ctrl+. on Windows/Linux). The list slides back the moment you close the note.

### Fixes

- **AI chat no longer makes notes disappear when it moves or files them into folders.** When the assistant created a note directly inside an existing subfolder, or moved notes between folders, the note could vanish entirely. The file watcher was misreading two normal situations as deletions: a brand-new note whose file landed on disk a split second before its database row was visible, and the old-path removal that happens whenever a note is relocated (Cairn writes the note to its new location, then deletes the old copy). In both cases the watcher deleted the note. The watcher now recognises an in-flight AI write and, as a final safeguard, never deletes a note while a copy of its file still exists elsewhere in the project — so moves and folder placements keep the note intact.
- **Renaming a note via AI chat no longer risks deleting it.** A rename changes a note's on-disk filename, which briefly removes the old file; that removal could be mistaken for a deletion. Renames are now protected the same way as moves, so the note is always preserved under its new name.
- **Moving a note out of a folder no longer leaves an empty folder behind.** After a note was moved (or the last note in a folder was deleted), the now-empty subfolder used to linger in the notes tree. Cairn now removes a folder once it's emptied by a move or delete — including collapsing a whole chain of nested empty parents — while always leaving the project's top-level folder in place.
- **AI folder moves are more reliable and can't create blank "unnamed" folders.** When the assistant moves or files notes, messy folder values (extra spaces, stray or doubled slashes, or a whitespace-only path) are now cleaned up — so `" /Archive// Old / "` becomes `Archive/Old` and a blank value files the note at the project root instead of under a nameless folder. Bulk-moving notes to the project root also works correctly now (it previously used a code path that could silently ignore an empty destination).
- **AI "create or update note" no longer risks a duplicate.** `ensure_note` (used by the assistant to sync a note) decided whether a note already existed from a snapshot taken at the start of the call. If the agent issued two same-title `ensure_note` calls in one turn (agent mode runs a turn's tools concurrently), both could think the note was new and create it twice. It now checks the live database and, inside the same write transaction, re-checks and adopts a note a concurrent call just created — so the same title always resolves to a single note, whether created or updated.

### Under the hood

- The file watcher's "orphaned file" and "note deleted" checks now consult both the in-process AI write guard and the cross-process `mcp_active_writes` table before acting, with a disk-existence backstop that is independent of lock timing. Added `electron/file-watcher.test.ts` covering the relocation, in-flight-write, and genuine-delete cases.
- `writeNoteFile` and `deleteNoteFile` now prune empty vacated directories via `pruneEmptyDirsUpTo`, which walks upward removing empty dirs and halts at (never removing) the project notes root. Covered by new tests in `electron/notes-files.test.ts`.
- `bulk_move_notes` now uses `moveNoteFolder` (direct SET) instead of `updateNote` (COALESCE), matching the desktop `db:note:moveToFolder` handler so a move to root is never silently dropped. `bulk_move_notes`, `ensure_note`, and `instantiate_template` all run the folder through `normalizeFolderPath` at the write boundary. Corrected the misleading comment in `pi-agent-loop.ts` that claimed the coding-tools file mutex serialised note writes (it does not — note tools rely on `mcp_active_writes` + the file-watcher guards).
- Added sync-engine regression tests (`shared/sync/engine.test.ts`) proving a folder move is captured as a `put` (never a `delete`), replicates the new folder by LWW (including moves to root), resolves concurrent moves without a conflict copy, never resurrects a peer-deleted note, and converges without re-exchange — confirming the oplog can't mishandle a move the way the file-watcher previously did.
- `ensure_note`'s existence check now uses a new `findLiveNoteByTitle` live-DB lookup instead of the pre-call snapshot, and the create path re-checks inside its synchronous `db.transaction()` (better-sqlite3 runs transactions with no interleaving), adopting a raced note as an update. No DB unique index was added — a hard constraint would risk failing the migration on legitimate pre-existing same-title notes (Obsidian imports, old conflict copies); the synchronous check-then-create is sufficient for the only reachable concurrency (the in-app agent loop). The chat-executor `aiWriteLock` wrapper uses the same lookup so its id can't diverge. Covered by new tests in `electron/ipc/chat-executor.test.ts`.
