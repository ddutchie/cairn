## What's new

### Features

- **Markdown rendering on board cards**: Kanban card descriptions now render as full markdown — checkboxes, lists, code blocks, tables, callouts, math, and wikilinks all render inline. Long descriptions are collapsible: a "More"/"Less" chevron toggle expands the content with a scrollable `max-h-48` container, and collapsing resets scroll to top so re-expanding starts at the beginning.

- **Links panel in graph detail**: Selecting a note node in the knowledge graph now shows a **Links** section with two subsections — **Wikilinks** (outgoing `[[Title]]` links from the note body plus graph-derived wikilink edges, deduplicated) and **Semantic** (embedding-cosine-similarity edges sorted by weight, each showing a similarity percentage). Clicking any link navigates to that note node in the graph. The section is collapsible and pinned to the bottom of the panel.

- **Linked tasks & notes panels**: The graph detail panel now shows collapsible **Linked tasks** (for note nodes) and **Linked notes** (for card nodes) sections, listing the actual linked items by name with click-to-navigate. Previously these were just plain-text counts in the meta fields.

- **Open in Board deep-links**: Clicking "Open in Board" from a graph card node now scrolls to and highlights the containing column, and opens the card detail modal — matching the existing `cairn:open-card` and `cairn:scroll-to-column` deep-link pattern used elsewhere in the app. Events are deferred via `requestAnimationFrame` so the board mounts its listeners first.

- **Badge size variant**: `Badge` component now supports a `size="xs"` variant with tighter padding (`px-1 py-0.5`) and `text-[0.643rem]` for compact UI areas like kanban card tags.

### Fixes

- **SSE tool-call argument assembly**: The streaming SSE parsers in both the chat loop (`electron/ipc/chat.ts`) and the coding agent loop (`electron/lib/pi-agent-loop.ts`) split incoming chunks by newline with no carry buffer. When a `reader.read()` boundary landed mid-`data:` line — common for large `tool_calls[].function.arguments` deltas — the head of the record failed the `startsWith("data:")` check on one chunk and the tail failed it on the next, so entire argument fragments were silently dropped. This was the root cause of truncated note titles (e.g. "Interview Pipeline Tracker" → "Inter Pipeline Tracker") and malformed JSON passed to tool executors. Both parsers now use a shared `iterSseData()` async generator (`electron/lib/sse.ts`) with a running carry buffer so partial lines survive chunk boundaries.

- **Malformed tool-call arguments no longer execute as destructive writes**: When `JSON.parse` of assembled tool arguments failed, both the chat loop and the coding agent loop silently fell through to `args = {}` and dispatched the tool anyway. For `ensure_note` this meant a call with `title: undefined` — which never matched an existing note, always created a new row, and inserted junk into the title column with no validation. Both paths now emit the tool chip (so the UI still tracks the call), push a `tool`-role error message back to the model (`{ error: "Malformed tool-call arguments JSON from model: …" }`), and skip execution — letting the model re-issue the call correctly.

- **`ensure_note` title matching now normalizes whitespace**: The dedup predicate was a raw `n.title === title` equality check — no trimming, no whitespace collapse — so a model-emitted `"Foo  Bar"` or `"Foo\nBar"` created a duplicate of an existing `"Foo Bar"`. Matching now uses `normalizeNoteTitle()` (`trim()` + collapse internal whitespace runs to a single space) at both lookup sites: the canonical implementation in `electron/mcp/tools/notes.ts` and the `aiWriteLock` wrapper in `electron/ipc/chat-executor.ts`. The wrapper previously re-implemented the predicate independently and could disagree with the canonical function, letting it mint a fresh `newId()` while `ensure_note` matched an existing row — so the lock keyed on a different id and parallel writes both landed. Both sites now share the same normalized predicate. Case-sensitivity is preserved by design.

- **DatePicker portal clicks no longer dismiss dialogs**: The date picker popover is portaled to `document.body`, making it a sibling of `RadixDialog.Content`. Two issues were fixed: (1) Radix modal dialogs set `document.body.style.pointerEvents = "none"` while open, so the portaled popover inherited `pointer-events: none` and silently swallowed every click/hover — fixed by adding `[data-dialog-portal] { pointer-events: auto }` to `globals.css` (CSS spec allows descendants to override a parent's `pointer-events: none`). (2) `DialogContent.onInteractOutside` now reads the real target from `event.detail.target` (not `event.target`, which is wrong for Radix's `CustomEvent`) and calls `preventDefault()` when the target is inside a `[data-dialog-portal]` element. The `onInteractOutside` prop is destructured before `{...props}` spread so consumer handlers can't clobber the override.

- **Consistent markdown rendering everywhere**: Five components that had hand-rolled or incomplete markdown pipelines now use the shared `NoteMarkdownPreview` component (same full pipeline as the note editor's read mode — callouts, math, wikilinks, embeds, code blocks, tables, GFM checkboxes, mermaid, footnotes):
  - `MDPreviewPanel.tsx` — was a ~70-line duplicate of the full pipeline
  - `AboutSection.tsx` — was bare `ReactMarkdown` with only `remarkGfm` + `remarkBreaks`
  - `board.tsx` archive view — was rendering `card.description` as plain text
  - `card-detail.tsx` — was using the chat renderer (`MarkdownContent`), causing inconsistencies with the board card
  - `AiSummaryNode.tsx` — was rendering AI summaries as plain text with `whitespace-pre-wrap`

- **Graph snippet length increased**: Note and card snippets in the knowledge graph increased from 120 → 600 characters so more content is visible.

- **"Open note" button in card detail now selects the note**: Previously the button only switched to the notes view without selecting the target note. It now dispatches `CairnEvents.selectNote(noteId)`, which navigates to the notes view and highlights/scrolls to the note.

- **Semantic links "show more"**: The semantic links section in the graph detail panel now shows 10 by default with a "+N more"/"Show less" toggle, preventing long similarity lists from pushing other content off-screen.

- **Tag node escape hatch**: Selecting a tag node in the knowledge graph now shows a "Browse tagged notes" button in the footer that navigates to the notes view, so you're never stuck on a tag node with no way to see the notes behind it.

- **Notes filter clear button**: The notes view filter input now has a clear (×) button when text is present, matching the board's filter UX.

### Changes

- **Kanban card tags moved to bottom**: Tags are now rendered at the bottom of the card (below due date / blockers / linked notes), separated by a divider border. Up to 3 tags are shown with a `+N` overflow indicator. Tags use the new `xs` badge size for a more compact look.

- **Graph detail panel layout restructured**: The panel body is now a flex column — title and meta fields are `flex-shrink-0`, and the markdown snippet uses `flex-1 min-h-0` so it stretches to fill all available vertical space between the header and the pinned collapsible sections (linked tasks, linked notes, links). Three collapsible sections are pinned at the bottom above the footer, each with expand/collapse chevron toggles defaulting to expanded.

- **`data-dialog-portal` attribute added** to `DatePicker` popover and `WikilinkPicker` so the dialog's `onInteractOutside` handler and CSS `pointer-events` override can target portaled children generically.

- **Sidebar project task counts**: Each project item in the sidebar now shows its open (non-archived) task card count next to the project name, giving at-a-glance workload awareness without navigating to the board.

- **Board tab task count badge**: The Board tab in the sidebar now shows the total open card count, matching the Archive tab which already had a count badge.

- **Column WIP count is clickable**: The WIP limit counter on a kanban column header is now a button that opens the column limit settings dialog — previously you had to know to click the column menu.

- **Column rename hint**: Column names now show `cursor-text` and a `"Double-click to rename"` tooltip to hint at the double-click-to-rename interaction.

- **Kanban card assignee in footer**: Cards now show the assignee name with a `User` icon in the footer when set.

- **Tags on note list items**: `NoteListItem` now shows up to 3 tags (using the `xs` badge size) alongside the note title, fetched from the store via `getTagById`.

- **Pinned notes capped in overview**: The overview's pinned notes section now caps at 4 items to prevent layout break on projects with many pinned notes.

- **Tooltips on graph/card actions**: `+N` tag overflow on cards, archived card titles, linked note action buttons in card detail, and URL hostnames on `UrlNode` in the Idea Flow all now have `title` attributes or `Tooltip` components for full-text visibility on hover.

### Knowledge Graph audit fixes

**Bugs:**

- **Semantic edges are now clickable**: Both Force and Radial canvases had `cursor: pointer` on semantic edges but no click handler. Clicking a semantic edge now selects the target node, opening its detail panel.
- **Empty state distinguishes "no data" from "filtered out"**: When the graph has no nodes at all, the empty state reads "No connections yet". When nodes exist but are hidden by filters/search, it reads "No nodes match your filters" instead — so users know to adjust filters rather than think the graph is broken.
- **Edge count in stats bar respects semantic threshold**: The "N edges" counter now excludes semantic edges below the current threshold slider, matching what's actually drawn on canvas.
- **GraphDetailPanel uses typed `CairnEvents`**: Replaced raw `new CustomEvent(...)` calls with `CairnEvents.scrollToColumn()` and `CairnEvents.openCard()` for type safety and refactor consistency.

**Polish:**

- **Tooltips on truncated titles in detail panel**: All four list sections (Linked tasks, Linked notes, Wikilinks, Semantic) now have `title` attributes on truncated spans so hovering reveals the full title.
- **Zoom controls on Radial tree**: The radial tree canvas now has zoom in/out/fit buttons in the bottom-right corner, matching the Force graph canvas.
- **Error overlay has a surface backdrop**: The graph error overlay now renders in a card with `bg-[var(--surface)]` and backdrop, matching the loading overlay style.
- **Edge-type legend**: A secondary legend below the node-type legend shows the four most common edge types (Linked, Wikilink, Semantic, Co-mention) with their colour and dash/solid pattern.
- **Graph preferences persist across view switches**: `labelMode`, `spacing`, and `semanticThreshold` are now stored in localStorage so they survive switching away from the graph and back.
- **Recompute button shows elapsed time**: The recompute button now shows a live elapsed seconds counter while computing, so users know it's working on large workspaces.
- **Duplicate tag nodes in radial tree highlight together**: When a tag spans multiple projects (creating multiple synthetic nodes), hovering or selecting one now highlights all sibling instances sharing the same tag ID.
- **"Browse tagged notes" applies tag filter**: Clicking the tag node CTA now dispatches a `cairn:filter-by-tag` event that the notes view listens for and applies as an active tag filter — fulfilling the button's promise instead of just switching views.
- **Project breadcrumb in detail panel header**: The project name ("in {project}") is now shown in the panel header next to the type badge, rather than below the title, giving full context at a glance.

### Idea Flow audit fixes

**Bugs:**

- **Edge stroke uses CSS variable**: `FlowEdge` stroke changed from hardcoded `#6366f1` to `var(--accent)`, adapting to theme and accent colour.
- **Per-edge delete now pushes undo command**: The floating X button on edges previously bypassed the undo history by calling `setEdges` + DB delete directly. It now uses `deleteElements()` which triggers `onEdgesDelete`, pushing the undo command so ⌘Z works.
- **GroupNode border alpha works correctly**: The `.replace("0.4", "0.2")` was a no-op because the border values use `"40%"` not `"0.4"`. Now uses explicit `borderIdle` and `border` variants in `COLOR_MAP`.
- **Double-click-on-pane creates node at cursor position**: Previously nodes were created at a fixed grid offset from top-left. Now uses `screenToFlowPosition({ x: e.clientX, y: e.clientY })` so the node appears where you clicked.
- **AI Summary nodes are editable**: The `ai_summary` branch in `NodeEditModal` was dead code — the modal was never opened for AI summaries on creation or double-click. Both guards now only skip `group` nodes; AI summaries can be hand-edited.
- **NodeEditModal colour swatches use CSS variables**: The group colour picker swatches were hardcoded `rgb()` values. Now use the same tokens (`var(--success)`, `var(--warning)`, `var(--danger)`, `var(--accent)`) as `GroupNode`'s `COLOR_MAP`.

**Polish:**

- **Save button foreground consistent**: `NodeEditModal` Save button changed from `text-white` to `text-[var(--background)]`, matching the convention used by all other accent buttons in the app.
- **Dangling ref nodes show distinct state**: `NoteRefNode` and `TaskRefNode` now distinguish three states — never linked ("No note/task linked"), linked and resolved (shows title + snippet), and linked but not found ("Linked note/task not found" in `var(--danger)`).
- **Idea body preserves whitespace**: `IdeaNode` body now uses `whitespace-pre-wrap` so line breaks typed in the edit modal are preserved in the card.
- **AiSummaryNode overflow fixed**: The nested `overflow-y-auto` containers (outer `max-h-64` + inner `NoteMarkdownPreview` with its own `overflow-y-auto h-full`) caused double scrollbars. The inner overflow is now overridden with `!overflow-visible !h-auto`.

### Settings audit fixes

**Bugs:**

- **`--error` CSS variable typo**: `EmbeddingsSettings` used `text-[var(--error)]` which is undefined — only `--danger` exists in `globals.css`. Model install errors now correctly appear in red.
- **Toggle switches have accessible names**: The shared `Toggle` component accepted a `label` prop but never wired it to `aria-label`. All call sites in `AISettings`, `MobileSettings`, and `ViewVisibilitySettings` now pass labels. The local `ViewVisibilitySettings` Toggle also adds `aria-label` and replaces hardcoded `bg-white` knob with `bg-[var(--surface)]`.
- **SettingsRow labels associated with inputs**: `SettingsRow` now generates a `useId`, renders the label as `<label htmlFor={id}>`, and injects the `id` into the child input via `cloneElement` — so screen readers announce the label when focus lands on the input.
- **Workspace name input supports Escape-to-revert**: Pressing Escape now resets the input to the current workspace name and blurs, matching standard text-input cancel behaviour.
- **Context-limit select no longer clamps values**: The select previously silently mapped any value above 32768 to 16384, hiding the actual setting. Now renders the real value and adds a "Custom: N tokens" option for non-standard values.
- **"Show in Finder" is cross-platform**: The assets folder button now reads "Show in Finder" on macOS, "Show in Explorer" on Windows, and "Open folder" on Linux, via `window.electron.platform`.
- **Pervasive hardcoded colours replaced**: All `text-red-500`, `border-red-500/30`, `bg-amber-500/10`, `text-amber-400`, `bg-yellow-500`, `text-gray-500`, `text-emerald-500`, `ring-black/20`, `bg-white`, `text-white`, and `to-indigo-500` in `AISettings`, `MobileSettings`, `TagsSettings`, and `AgentSettings` replaced with CSS variables and `color-mix()` alpha variants.
- **Accent button foreground unified**: All `bg-[var(--accent)]` buttons now use `text-[var(--background)]` instead of `text-white`, which was unreadable on light-theme accents.

**Polish:**

- **ShortcutsSettings respects hidden views**: The keyboard shortcuts list was hardcoded (Agent=⌘5, KG=⌘6, etc.) but the actual shortcuts shift when views are hidden. The list now dynamically computes from `hiddenViews`, mirroring `page.tsx`'s `ORDERED_VIEWS` logic. The "Toggle AI chat" shortcut is omitted when Chat is hidden.
- **TagsSettings colour swatches have aria-labels**: Palette buttons now have `aria-label="Set color to {name}"` with a colour name lookup (Indigo, Violet, Purple, etc.) instead of announcing raw hex codes to screen readers.
- **TagsSettings colour picker closes on Escape**: The popover now listens for Escape key in addition to outside-click, and its keydown listener is properly cleaned up on unmount.
- **DataSettings "Wipe all data" requires type-to-confirm**: The reset dialog now requires typing "DELETE" in a confirmation input before the Wipe button is enabled, preventing accidental irreversible data loss.
- **DataSettings export surfaces errors**: `handleExport` is now wrapped in try/catch — if the blob download fails (sandbox, permissions), the button shows a "Failed" state with an `AlertCircle` icon instead of falsely showing "Exported".

### Enhancements

- **Graph search matches snippets and tag names**: The knowledge graph search box now matches note/card snippets (body text) and tag names in addition to node titles, so you can find a note by its content or by an applied tag without navigating to the notes view first.

- **Idea Flow empty-state hint**: When a project has zero Idea Flow nodes, the canvas now shows a centered hint card ("Your Idea Flow is empty — double-click the canvas or use 'Add node' to start capturing ideas") instead of a blank dotted background.

- **Accessibility for flow icon buttons**: All icon-only buttons in the Idea Flow (promote-to-task, open note, open board, open link, delete edge, group colour swatches) now have `aria-label` attributes and `focus-visible:ring-2` styles so keyboard users get a visible focus ring and screen readers announce the action.
