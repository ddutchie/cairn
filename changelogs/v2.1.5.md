## What's new

### Fixes

- **Crash on launch in packaged app**: `umap-js` (used by the embeddings projection module) was marked `--external:umap-js` in the esbuild build scripts, leaving `require("umap-js")` in the bundled output. In dev this resolved from `node_modules`, but in the packaged `.app` there is no `node_modules` directory — crashing on launch with `Cannot find module 'umap-js'`. Removed the `--external:umap-js` flag from all three esbuild commands (`compile`, `compile:watch`, embeddings-server bundle). `umap-js` is pure JavaScript with one transitive dependency (`ml-levenberg-marquardt`); esbuild now inlines both into the bundle.

### Tests

- **Bundle self-containment guard** (`electron/bundle-guard.test.ts`): New test that scans `dist-electron/main.js` and `dist-electron/embeddings-server.bundle.js` for `require()` calls and fails if any package outside the Node.js built-ins + `ALLOWED_EXTERNALS` list (`electron`, `better-sqlite3`, `node-pty`, `@huggingface/transformers`, `onnxruntime-node`) is required externally. Catches the class of bug where a package is mistakenly marked `--external` in esbuild but not shipped via `electron-builder.yml`. Verified the test catches the `umap-js` regression by re-injecting `require("umap-js")` into the bundle.
