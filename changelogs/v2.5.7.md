# v2.5.7

## Added

- **Custom HTTP services can now authenticate with OAuth.** Previously a custom HTTP service (any REST endpoint exposed to the AI as a tool) could only send a static API key or bearer token via a header — fine for key-based APIs, but useless for services whose access tokens expire (Gmail, Microsoft Graph, and most modern OAuth 2.1 APIs), where you'd have to paste a fresh token roughly every hour. A service can now be set to **OAuth**: you sign in once in the browser (the same PKCE + dynamic-client-registration flow Cairn already uses for OAuth MCP servers), and Cairn stores the tokens encrypted in your OS keychain, refreshes them automatically as they expire, and injects `Authorization: Bearer <token>` on every request. Nothing is written to the database and no token is ever exposed to the model. This is the foundation for a wave of new one-click community connectors that talk directly to a vendor's REST API without needing a gateway. Key-based and header-secret services keep working exactly as before.
- **The community registry can ship OAuth service presets.** Registry `service` entries gained optional `authMode` and `oauth` fields, so a connector can declare "this REST service uses OAuth" (with an optional pre-set scope / discovery base / client id). For any authorization server that supports dynamic client registration — most modern ones — no per-vendor setup is needed: install, click Connect, done.
