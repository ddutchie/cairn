## What's new in Cairn 3.1.0

### New

- **Shipped this week and At risk on the project Overview.** Cards now record when they were finished (when they enter a Done column; cleared if moved back out, kept when archived). The Overview shows everything finished in the last 7 days, and a list of open cards that need attention: overdue, blocked by an open card while due within 3 days, or sitting in In Progress / Review with no updates for a week. Existing Done cards are backfilled from their last update time.
- **Weekly review and daily brief notes.** A new button on the Overview header writes a review note into the project's `Reviews` folder: what shipped, what's at risk, the next unblocked cards by priority, and wikilinks to every note touched in the period, with a space for your own reflections. It's plain markdown, so you can edit it or ask the agent to expand on it.
- **More board filters, and saved views.** Next to the priority chips and search, a Filters menu narrows the board by assignee (including Unassigned), tags, due date (overdue, due within 7 days, no date) and "blocked by an open card". Save any combination as a named view per project and switch between views from the Views menu.
- **Quick capture from anywhere.** Press ⌘⇧Space (Ctrl+Shift+Space on Windows/Linux) from any app, or choose "Quick capture…" in the tray menu, to bring Cairn forward with a small capture dialog: add a card to a project's Backlog (or To Do) or create a note, with optional details. ⇧↵ saves and keeps the dialog open for the next item.
- **Know when an agent needs you.** While Cairn is in the background, a coding session now sends a system notification (and bumps the dock badge) when it finishes, stops with an error, asks for an approval or asks you a question. The notification also appears in the in-app bell; clicking it opens the session. Repeats are grouped so a burst of approvals is one notification.
- **Live agent status on board cards.** A card whose coding session is running shows an "Agent" pill, which turns into "Needs you" while the agent is waiting for an approval. Click it to jump to the session.
- **External agents can claim tasks and log progress.** Two new MCP tools: `claim_task` sets the card's assignee to the agent (e.g. "Claude Code"), moves it from To Do to In Progress and refuses if another agent already holds it; `add_task_progress` appends timestamped updates under a "Progress" section in the card description and can move the card to Review or Done when finished. `get_task` now also returns `assignee` and `completedAt`.
- **Daily automation budget.** Set a daily spend limit from the Automations toolbar, which also shows today's estimated automation spend. Once it's reached, scheduled runs are skipped (and shown as skipped in the run history) until the next day, with one notification; manual runs still work.

### Improved

- **Automations recover from failures on their own.** A recurring automation that fails is retried after 5 minutes, then 10 (never later than its next scheduled run). After 3 failed runs in a row it pauses itself and tells you why, instead of failing every night. Failed runs have a Retry button in the run history.
- **Mobile Access is limited to your workspace.** A phone paired through Mobile Access can still read and edit notes, cards, Idea Flow and tags, chat with the agent, and browse code, diffs and git history. It can no longer run anything on your computer or change Cairn's setup: no terminals or shells, file edits in code folders, git commits, pushes or discards, MCP servers, plugins, sync, secrets, approval grants, AI provider and agent settings, automation edits or runs, resetting or relaunching the app, or Mobile Access settings. Do those from the desktop app.
- **Agent turns started from Mobile Access follow your desktop settings.** A paired phone can no longer choose its own chat approval policy or agent approval mode (such as "Allow everything"), send a saved API key to an endpoint you haven't set up, or pick the folder a coding session runs in. It uses your desktop's approval settings and saved AI connections. New coding sessions from the phone run only in the project's code directory, and that directory can only be changed on the desktop. Prompts from the phone no longer change the desktop's saved connection.
- The running-sessions poller now only re-renders the sidebar and board when the set of running sessions actually changes, instead of every two seconds.

### Fixed

- **Move a notes folder to another project again.** Hover a folder in the notes tree and choose the new "Move to project" button; the folder, its subfolders and their notes all move. This replaces drag-to-project, which stopped working when the old sidebar was removed in 3.0.4. Cards and single notes still move through their "Move to project" menus.
- The Overview's due-soon list now reads due dates as local calendar days, so in time zones west of UTC it no longer includes a card due 8 days out or orders same-day cards wrongly. Desktop and mobile now compute Overview numbers with the same code.
- The Overview's Notes panel and note counts now update as soon as you add, pin or edit a note, instead of waiting for the next card change.
- Idea Flow changes that fail to save (moving, resizing, deleting or adding nodes, auto-layout, promoting an idea to a task) now show an error instead of failing silently, and a failed promote reloads the canvas so it matches what was saved. A failed undo or redo is reported too.
- **Approving a tool call while watching an automation run works.** The Approve, Always allow and Deny buttons in the run watcher never reached the running automation, so a run in "ask" mode stayed blocked on that tool call. They now answer it.
- Creating an automation whose schedule is invalid or has no future run (e.g. a one-off time in the past) now shows the reason, instead of adding a broken entry to the list. Failing to update, delete or start an automation, or to save the daily budget, is reported too.
- **Promote to task in Idea Flow works again.** Promoting an idea never created the card (it failed silently, and since the previous fix showed an error). It now creates the card and swaps the idea for a linked task node, including when redone with ⌘⇧Z.
- When setting up Cairn on an existing notes folder, the onboarding summary of the projects it imported (with its Undo import button) now appears, instead of being skipped straight to "create your first project".
- A brand-new project's board columns now match the saved ones straight away, so a card added to it before the next refresh is saved instead of being rejected.
- **Archive chat to note writes an AI summary again.** Archiving a conversation into a project note had silently fallen back to the raw transcript (labelled "AI Compaction Unavailable") since chat history moved to session logs. It now writes a short summary of decisions, findings and open questions, and still falls back to the transcript when AI isn't configured.
- Renaming a chat thread now sticks: the new title is pinned, so automatic titling no longer replaces it later.
- **AI helpers report a failed model call instead of returning nothing.** When the AI endpoint was unreachable, rejected the key or ran out of quota, generating a commit message, PR description, architecture explanation, PRD or writing-style guide quietly produced empty or placeholder text (a commit subject of "Update", an empty PRD note), and summarising Idea Flow nodes replaced the node's text with nothing. They now show the provider's error and leave your content untouched.
- In Settings → Tools, failing to delete an MCP server or service, attach or detach a tool, change which of a server's tools are enabled, or sign out of a connector now shows an error. Failing to mark notifications read or clear them is reported too, and removing an AI provider no longer leaves an unreported error when its saved key can't be deleted.
- Installing a downloaded update, opening the assets folder, revealing a note in Finder or Explorer, and saving the theme or accent colour for the next launch now show an error if they fail, instead of failing silently.
