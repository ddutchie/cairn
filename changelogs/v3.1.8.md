## What's new in Cairn 3.1.8

### Fixed

- **Settings → AI no longer crashes before you add a provider.** Opening the AI settings with no saved providers froze the app ("Maximum update depth exceeded"); it now opens normally.
- **Sidebar shortcut hints match the keys again.** The sidebar showed Overview as ⌘3 and Board as ⌘5; it now shows ⌘1 for Overview, ⌘2 for Notes and ⌘3 onwards for the other views, the same keys that switch to them.
- **The expanded chat view names the open conversation.** Its session switcher said "Choose a session" even with a chat open; it now shows that chat's title.
- Device Sync's setup note no longer runs two words together ("installedfor").
- **Linux downloads are about half the size.** The Linux AppImages bundled NVIDIA GPU libraries (CUDA and TensorRT, ~350 MB) that Cairn never uses, plus the other architecture's embedding runtime. They are now stripped from the package, bringing each AppImage from ~425 MB down to roughly 190 MB.

### Removed

- **The unreleased Plugins preview is gone.** Settings → Extensions no longer shows a Plugins tab, and the developer-only plugin loader (`CAIRN_PLUGINS_DEV`) has been removed. Tools, Commands and MCP servers are unaffected.

### Changed

- **Insights names every chart.** All eight canvases are labelled in a tab strip instead of showing only icons, and the ridgeline style and time-range zoom are labelled.
- **Automations read in plain words.** Schedules show as "Weekdays at 08:00" or "Every 6 hours", with the cron expression in a tooltip. Run and Edit are labelled buttons, the other actions are under "⋯", and a paused automation says "Paused".
- **A tidier sidebar.** There's one Calendar entry, with a This project / All projects switch in the calendar itself. Notifications live on the bell only. You switch projects from the project card's title.
- **Smaller fixes:** search shows its keyboard hints and result count once. Terminals follow light and dark mode and your accent colour. The agent's structure panel appears when you open a file. Empty screens say what to do next. Buttons and headings use sentence case.
- **Settings is reorganised and searchable.** It's now one list of pages grouped as App, AI, Extensions and Data, with no tabs inside pages. A search box above the list jumps straight to a setting and highlights it. Community providers and local-server detection have their own Models page, instead of appearing on both the Chat and Coding agent pages. Tags and Sidebar & views have their own pages. The page that lets Claude Desktop or OpenCode use Cairn is now called "Connect other agents", so it's no longer confused with the MCP servers Cairn itself uses (under Tools).
- **Number settings use one control.** Max steps, temperature, context window and max output tokens now show their presets, Auto and a custom value in a single row of options. Tabbing through the custom field no longer switches Auto off.
- **The chat session switcher matches the rest of the app.** It's now a single-line picker that opens a floating list aligned to it, with the same rows as the sidebar's conversation list. It also lists sessions from your other projects under their project names, so a conversation started in another project is one click away. Every button in the chat panel header has the same shape, a tooltip and a screen-reader label.
- **Menus and pickers behave consistently.** The new-session menu, note export, graph label mode, Idea Flow's "Add node", tag colour and tag pickers, and the sync status panel use the app's shared menu and popover components. They close on outside click and Escape, support the keyboard, and return focus to the button that opened them.
- **Text sizes, shadows and labels are consistent across the app.** Interface text now follows one four-step scale instead of more than a dozen near-identical sizes, so the smallest labels are a little easier to read. Menus, popovers and dialogs use three shadow levels that look right in both themes. Section labels are in sentence case rather than small capitals, except the sidebar's group headings.
- **Keyboard focus is visible on buttons.** Tabbing onto a button or an icon button now shows an accent ring. Every icon button in the chat panel header has a tooltip and a screen-reader label.
- **Settings buttons are announced by their own text.** Screen readers read "Browse Community" or "Export", not the title of the settings row the button sits in.
- **Semantic search finds exact names and ids, and stops repeating itself.** Notes and tasks now combine meaning-based search with full-text (FTS5) matching, boost results that contain every search term, and spread near-duplicate results apart. This applies to related-note suggestions and the `search_notes_semantic` / `search_tasks_semantic` MCP tools, which may now return fewer results when only a few are clearly relevant.
- **Cairn now runs its own agent engine.** Chat, coding sessions and automations share one engine built on the pi-ai provider layer, replacing the DeepSeek harness (`@deepseek-ai/cordis` and the `dsh-*` packages), which has been removed along with its patches. Subagents, goals, reminders, background jobs, persistent terminals, language-server navigation, workflows, Claude Code / Codex command hooks, plan mode, slash commands and context compaction all run on it.
- **Your history carries over.** Sessions recorded by the previous runtime are imported the first time you open them; clearing or deleting a session also removes the old copy.
- **Smaller install.** Dropping the harness removes about 230 packages, including the native FFI module and the Windows sandbox runner.
- **Settings → AI tool lists reflect the real toolsets.** They are now built from the engine's own tools for each surface.
- **The writing-style wizard** reads notes and tasks through the same engine, limited to read-only tools.
- **Local (stdio) MCP servers run on the new engine.** They connect through Cairn's MCP client alongside remote servers; the dev-only "Route via dsh" toggle is gone.
- **Session reminders stay opt-in.** The tools are only offered when the setting is on.
- **Agent shell commands are sandboxed.** On macOS (seatbelt) and Linux (bubblewrap) the agent's `bash`, background jobs and persistent terminals can only write inside the working directory and temp/cache folders; reads and the network stay open. If a command genuinely needs more, the agent can request `unsandboxed`, which asks you every time and can't be remembered. Toggle under Settings → Agent → "Sandbox shell commands" (Windows has no sandbox).
- **The AI can search your earlier chats and coding sessions again.** `search_sessions` and `read_session` look up past work in the workspace you are in (for example "what did we decide about the export format?") and read the exact messages. With embeddings turned on, matches are found by meaning as well as by words (the index fills in as you chat and when you search). They only read, so they never ask for approval. Chat and coding sessions are listed again in the session index (pop-out, usage and thread ordering) after the engine change.
- Chat/coding replies show their speed again (time to first token, tokens/s, output tokens) after the engine switch; stats are measured live, so they aren't available on messages reloaded from older sessions.
- Coding sessions have an **Auto** permission preset: a model reviews each risky action (routine ones run, dangerous ones are blocked, unclear ones ask you); external tool calls and sandbox escalations still always ask, and Auto pauses to manual after repeated blocks.
- Coding sessions read the project's `AGENTS.md` / `CLAUDE.md` (and `@file` imports, parent directories up to the repo root) into the system prompt on every message.
- Skills can be run by name in coding sessions with `/<skill-name> [task]`.
- Timeline chips are back for slash commands and plan-mode toggles.
- Model requests now carry the session id, so providers that support prompt caching (OpenAI-style cache keys, OpenRouter affinity) can reuse the prompt prefix.
- The shell sandbox now **fails closed**: if it is turned on but can't start (bubblewrap missing or blocked, or macOS refusing to nest `sandbox-exec`), commands ask before running unconfined instead of silently skipping the sandbox, and model terminals refuse to start. Settings → Agent shows when that is the case.
- The agent is told how its commands are confined, and must say why when it asks to run `unsandboxed`; the reason is shown on the approval card. Sandboxed Linux commands also get their own process namespace.
- **Plan mode can now run shell commands.** They run in a read-only sandbox (only temp folders are writable), so the agent can inspect the repo with `git log`, `rg`, test listings and the like while planning but can't change anything. If the sandbox is off or unavailable, plan mode still blocks the shell.
- Desktop and mobile now share one retry policy (`shared/agent/retry.ts`), so both treat the same provider errors as transient and back off the same way. No desktop behaviour change.
- **The working indicator shows what Cairn is doing.** The blinking caret is replaced by a small animated loader that changes with the phase of the turn: waiting for the first token, thinking, writing the answer, running a tool, retrying after a transient error, compacting context, or waiting for your answer. The same loader sits in the composer's busy strip and at the end of the transcript, and follows your theme and accent colour.
- **The chat panel no longer gets stuck at full width.** The side panel now shrinks to fit when the window gets smaller (down to 240px) and can always be dragged narrower, instead of jumping to full width when its saved width no longer fit. If the window is too narrow for even a minimum-width panel beside the main view, chat opens in the expanded chat view instead; widening the window brings the side panel back, and leaving the expanded view closes the chat.
- **The local-network Mobile Access server is gone.** Settings → Mobile Access (the QR code / PIN web companion that served Cairn to a phone browser) has been removed, along with its LAN server, so Cairn no longer opens a network port for it. The Cairn mobile app is unaffected: use Settings → Device Sync to keep your workspace in step with your phone. Leftover `mobile-config.json` and `mobile-sessions.json` files (including the old PIN) are deleted on first launch.
