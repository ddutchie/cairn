## What's new

### Features

- **Pop-out chat window**: Chat can now be popped out into a separate always-on-top window via a button in the chat panel header. The pop-out shares the same thread and messages as the main window — streaming events are broadcast to both. Chat state is relayed through the main process on pop-out and pop-in, so nothing is lost. Switching project context is available via a dropdown in the pop-out's header bar. Supports pop-in from either window (pop-out's own button or main window's placeholder).
- **Resizable notes sidebar**: The notes panel's sidebar can now be resized by dragging its right edge. Min width 160px, max 400px, persisted across sessions.
- **Truncated note/folder tooltips**: Note titles and folder names that overflow with an ellipsis now show a tooltip on hover revealing the full name.

### Refactor

- **Chat streaming broadcast**: The chat IPC `send()` function now calls `broadcastToChat()` alongside the originator's `event.sender.send()`, so all chat participants (main window, pop-out, mobile SSE clients) receive streaming tokens, tool calls, and completion events simultaneously.
- **Shared chat participant tracking**: Extracted pop-out window management into `electron/chat-popout.ts` with a `chatParticipants` Set, `broadcastToChat()`, and IPC handlers for state relay (`chat:popOut`, `chat:popoutReady`, `chat:requestPopIn`, `chat:popIn`). Main process tracks windows by webContents ID, not BrowserWindow ID, fixing a subtle ID-space mismatch.

### Fixes

- **Window pop-in "Object has been destroyed" crash**: The pop-out window's `closed` event handler was accessing `win.webContents.id` after the webContents was already destroyed. Captured the ID into a local variable at window creation time instead.
- **MCP server binary crash at startup (`ZodCustom`)** : The bundled MCP server binary crashed with `"undefined is not a constructor"` in `_custom` on launch. esbuild tree-shook the `import * as z from "zod"` in `mcp-server.ts` because `z` was only used in a TypeScript type assertion. This meant `init_zod()` (which sets up the `ZodCustom` class used by `z.custom()`) never ran before the MCP SDK's internal `types.js` called `z.custom()` at module scope. Fixed by replacing the value import with `import type { ZodTypeAny }` and reordering the `tool-schemas` import (which loads `zod` eagerly) before the MCP SDK imports so esbuild emits `init_zod()` first.
