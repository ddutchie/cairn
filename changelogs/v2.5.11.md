# v2.5.11

## Fixed

- **AI Tool Builder works again with keychain-stored provider keys.** "Build a tool with AI" failed with `AI endpoint error 401: Incorrect API key provided` for any AI provider that requires an API key, even though normal chat worked fine. Since the v2.5.9 migration that moved provider keys into the OS keychain, the cached AI config holds a `secret://…` reference rather than the raw key. Chat, inline AI, Idea Flow summaries, and the coding agent all resolve that reference to the real key before making a request, but the Tool Builder was missed — it sent the reference string verbatim as the bearer token, which the provider rejected. The Tool Builder now resolves the key the same way (via `resolveLlmApiKey`), so it authenticates correctly. Keyless local endpoints (Ollama, LM Studio, On-Device Llama) were unaffected, which is why the failure looked provider-specific.
