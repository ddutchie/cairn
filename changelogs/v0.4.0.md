# v0.4.0 — Compartmentalising Sprint

This release is entirely internal — no new user-facing features. The focus is on making the codebase maintainable for open source contributions: eliminating duplication, splitting large files into focused modules, establishing shared constants and utilities, and adding the first unit tests.

## Architecture

### Electron main process — new `electron/lib/` layer

A new shared library layer sits between the IPC handlers, the MCP server, and the AI chat loop:

| File | Purpose |
|------|---------|
| `electron/lib/llm.ts` | `LLMConfig`, `callLLM`, `streamCompletion` (AsyncGenerator), `isLocalEndpoint` |
| `electron/lib/tools.ts` | `TOOLS` (OpenAI function definitions), `TOOL_LABELS`, `buildSystemPrompt` |
| `electron/lib/context.ts` | `buildContextResponse` — single source for `get_cairn_context` response shape |
| `electron/lib/prd.ts` | `generatePrd` — shared PRD generation logic used by chat and IPC handlers |
| `electron/db/utils.ts` | `newId()`, `ts()` — shared ID generation and timestamp helpers |
| `electron/db/defaults.ts` | `DEFAULT_COLUMNS` — canonical 5-column board layout |

### IPC surface tidy

- All `app:*` channels consolidated in `electron/ipc/handlers.ts` via `registerAppHandlers()` — previously split between `main.ts` and `handlers.ts`
- `mcp:markNotificationsRead` moved to `handlers.ts`
- Preload namespaced: `electron.chat.stream`, `electron.chat.onToken`, `electron.chat.onDone`, `electron.chat.onToolCall`
- `generatePrd` moved to `electron.ai.generatePrd`

### Query layer improvements

- `searchNotes(db, opts)` and `searchTasks(db, opts)` added to `electron/db/queries.ts`, replacing identical inline filter/map logic in `chat-executor.ts` and `handlers.ts`
- `buildContextResponse(db)` in `electron/lib/context.ts` unifies the `get_cairn_context` response previously built independently in three places with inconsistent field sets

### LLM abstraction

`streamCompletion(config, messages, tools)` added to `electron/lib/llm.ts` as an `AsyncGenerator<string>` — replaces the inline SSE parsing loop in `chat.ts`. `callLLM` moved from `chat.ts` to `llm.ts` as the canonical one-shot completion function.

## Type system

- `IpcResult<T>` and `isIpcError<T>()` type guard added to `src/types/index.ts` — provides a typed wrapper for IPC return values instead of inline `if (result?.error)` checks

## Naming fixes

- `update_task` MCP/chat tool: parameter renamed `taskId` → `cardId` for consistency with all other `*_task` tools
- `getConfigBasePath()` extracted in `mcp-server.ts` to eliminate three identical `if (win32 / darwin / linux)` blocks
- Dead code removed: `contentToText()`, `Paperclip` icon import, empty migration guard block, `PendingActionCard` component

## MCP server isolation note

`electron/mcp-server.ts` intentionally retains its own copies of note file helpers (`toSlug`, `writeNoteFile`, etc.). This is a known constraint: the MCP binary is bundled with `@yao-pkg/pkg` and runs under a system Node ABI that is incompatible with the Electron-compiled `better-sqlite3` binding. The helpers are documented in-file and kept in sync manually.
