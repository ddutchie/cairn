## What's new

### Added

- **Automations can run scripts.** Automations now have a working `run_script` tool: a named script in the automation's `.automations/<id>/scripts/` folder is executed by the agent with the run's working folder as cwd. `.js`/`.ts` run on the app's bundled Node (works everywhere), plus `.sh`, `.py`, and Windows `.bat`/`.cmd`/`.ps1` when the runtime is available. Scripts write durable deliverables to the never-pruned `out/` folder (`CAIRN_OUT_DIR`). Running a script always requires approval (or a script-scoped standing rule) — never silently auto-approved. A new `write_run_file` tool lets the automation agent stage data (e.g. connector results as JSON) inside the run's scratch folder for a script to consume via `-input <file>` — so recipes like "fetch news → save JSON → run script" actually work end-to-end. A `deliver_file` tool copies generated images from `out/` into the workspace `attachments/` folder and returns a renderable `asset://` URL, so notes can actually embed the images they produce.
- **Automation env vars.** The Automations detail view has an Environment editor for configuring what scripts can read via `process.env`. Plain values are stored on the automation and written to the automation folder's `.env`; secrets are stored in your OS keychain and injected directly into scripts at run time — never written to disk or sent to the renderer. A minimal `manifest.json` (name, env schema, connectors) is created per automation for the build/test loop.
- **Develop automations with an agent.** A "Develop" button (on each automation card and in its detail view) opens a self-contained modal with the agent session and a live **Files** panel showing every file it writes in the automation folder. The session runs a restricted **automation-builder persona** — file tools only (`read`/`write`/`edit`/`bash`/`grep`/`find`/`ls` scoped to the automation folder) — so it can never create tasks or touch your board while working. The agent authors the scripts in `scripts/` and writes the final recipe into `manifest.json` (orchestrating connectors, `run_script` calls, and note delivery). "Sync from manifest" applies the agent-authored recipe back to the automation, and "Run now" exercises the exact scheduler path (real keychain secrets injected) for a true end-to-end check. The runner prefers the manifest recipe, so a developed automation always actually calls its scripts. Connectors are called directly by the automation's agent at run time — scripts never replicate them.
- **Watch an automation run live.** Running automations show a "Watch" button (on the card and in the detail view) that opens a live transcript of the run — the recipe it's following, streaming output, thinking, and each tool call as it happens — so you can see exactly why a script did (or didn't) do what was expected.
- **"Always allow" now sticks.** Approving a tool call once with "Always allow" persists a standing rule on the automation (script-scoped for `run_script`, command-scoped for `bash`, identifier-scoped otherwise), so the next run lets it through without asking again.
- **Every run saves a transcript.** Each run now writes `run-log.json` into its run folder — the recipe it followed, the assistant's output, and every tool call with its result — so you can see exactly what happened (e.g. "the Tavily connector returned 0 articles"). The run's detail view has a log button that renders it inline.

### Fixed

- **Secrets can never be persisted to the database.** Automation env entries are normalised at the DB boundary: a secret's value is stripped on both write and read, so even a stray caller passing `{ secret: true, value: "…" }` can't land plaintext in the `automations.env` column — it lives only in the OS keychain. Reading also tolerates a corrupt env column (a non-array JSON value or null entries can no longer crash the automation list).
- **A Develop session can no longer run commands.** The automation-builder persona is now strictly file-scoped (`read`/`write`/`edit`/`grep`/`find`/`ls`); `bash` was removed until shell execution can be sandboxed. The persona prompt now tells the agent to reason about scripts statically and verify via "Run now" instead of executing them. The session's persona is also validated on every entry point (prompt, plan approval, context restore) and fails closed to the restricted persona for an unknown value.
- **Two prompts can't run the same agent session at once.** `pi-agent:prompt`/`approve-plan` now reject a second request while that session's loop is running, so replacing `abortCtrl` mid-flight (and leaving `is-running` wrong) is impossible. `/compact` and clearing a session's history get the same guard — neither mutates `messages` under an active loop.
- **Manifest "Sync" can no longer silently auto-approve arbitrary scripts.** A target-less `run_script`/`bash` standing rule in an agent-authored `manifest.json` would have been installed verbatim on sync — a wildcard grant that auto-approves *every* future script run. Synced rules are now sanitised (code-executing tools require a script/command target) and any skipped rule is reported back in the sync confirmation. The manifest's declared connectors (`requires`) are also synced now, so a recipe that depends on a connector actually fails loudly at run time if it's missing instead of silently running without it. The "Always allow" path got the same guard: it refuses to record a target-less rule for a code-executing tool.
- **Scripts can no longer read the app's own environment.** `run_script` previously inherited the full parent `process.env` (which may include e.g. an LLM API key exported when Cairn launched). Children now get a minimal safe environment (PATH, HOME, system vars) plus the automation's own env vars only.
- **Develop sessions are genuinely folder-scoped.** The `write`/`edit` agent tools rejected nothing before — absolute paths and `..` traversal could write outside the working directory. They now enforce the same containment as `read`/`grep`/`find`/`ls`, so a Develop session can't touch files outside its automation folder.
- **Run transcripts are written atomically.** `run-log.json` is written via a temp file + fsync + rename, so an interrupted write can never leave a partial (unparseable) transcript at the final path; `readRunLog` only ever sees complete logs.
- **A crashed run keeps its progress.** If a run throws mid-way, `failRun` now merges the error into the already-flushed transcript (tool history, tokens, thoughts) instead of replacing it with an empty log, and still emits the `finished` event.
- **Reopening a running agent session shows it busy again.** The automation Develop modal (and any agent pane) keeps the agent loop alive when closed, but the input box came back looking idle because the busy flag was local UI state. The main process now tracks live agent loops, and a remount polls it — so resuming a session mid-run immediately shows the "Working…" state (and a run that finished while closed is cleaned up, with no ghost streaming bubble).
- **Exhausted runs now show as "exhausted", not green "done".** A run that hit the step limit previously got `status: done` with a red error line. It's now its own terminal state, rendered in warning amber in the run history (row + transcript agree).
- **Stale approval requests expire on their own.** Pending approvals older than the timeout are now swept to `expired` on the heartbeat (cutoff derived from the scheduler's own clock), so an approval parked by a run whose process died doesn't sit in the inbox forever.
- **Env editor no longer orphans keychain secrets.** Toggling a secret row to a plain value now deletes the old keychain secret, and a blanked-out non-secret value removes the var instead of silently persisting a no-op. The Save button stays enabled when the only change is a pending removal.
- **`ask_questions` fails loudly in background runs.** A headless automation that called it previously got a fake success and kept going as if you'd answered. It now returns an error telling the agent to make reasonable assumptions instead.
- **Clearing a chat can no longer leak a queued message.** `handleClear` now drops the message queue *before* stopping the stream — stopping flips the loading state, which drains the queue, and a pending prompt must not land in a just-cleared thread.
- **Escaping an empty non-void tag keeps both tags.** `rehypeEscapeUnknownTags` now serializes e.g. `<text></text>` back as `<text></text>` (not the collapsed `<text>`); void elements keep their normal self-closing form.
- **Tooltips in the window chrome no longer get hidden behind the native window buttons on Windows.** Tooltips for top-bar buttons (AI Chat, running automations, notifications, sync) now pop up *below* the button instead of into the title-bar area where the OS's minimize/maximize/close overlay lives.
- **The title bar's sync and notification buttons now use the app tooltip system**, matching every other icon button in the app (native `title` replaced with the styled tooltip).
- **Automation panel buttons now use the app tooltip system.** Every icon button and status chip in the Automations view, its modals, the Environment editor, schedule builder, community browser, and notification center shows a consistent styled tooltip instead of the browser's native title.
- **Chat/agent replies with raw SVG no longer crash the app.** A stray `<text>` (or other SVG tag) outside an `<svg>` in a model reply reached React as an unknown HTML tag and threw "The tag <text> is unrecognized". SVG-only tags are now escaped to literal text unless they're genuinely inside an `<svg>` — notes' KaTeX/diagram rendering is unaffected.
- **Closing the Develop modal no longer orphans in-flight work.** "Develop" now reopens a running dev session for the same automation instead of always spawning a fresh one; a "Start over" button aborts the old session and starts clean.
- **Agent tasks no longer re-spawn after switching projects.** A session spawned from a board card fired its initial prompt again when the agent pane remounted (e.g. visiting a project without a code directory), re-running a task that had already started. The fire-once guard is now app-lifetime rather than per-render, so each session's initial prompt runs exactly once.
- **Automations stuck "running" after an app restart are auto-recovered.** If the app closed mid-run (crash, quit during a turn, dev reload), the run's row stayed `running` forever and the scheduler's skip-on-overlap guard silently blocked that automation from ever running again. On startup (and workspace re-initialise), any in-flight run is marked interrupted so the automation can fire again.
- **Queued chat messages are no longer re-sent alongside the previous message.** When you queued a message while a reply was running, the next turn's request could omit the reply that had just finished — so the model saw the previous user message and the queued one back-to-back as if both were new. Drained messages now always carry the complete, current conversation history. The queue logic is now shared and covered by regression tests (`useChatMessageQueue` hook, chat + agent panes).
- **Temperature is now optional — and never forced on models that don't want it.** Cairn previously sent `temperature: 0.3` on every chat/agent/one-shot request, even to frontier reasoning models (GPT-5.x, Claude 5, Kimi K3…) that models.dev marks `temperature: false` — the vendor manages sampling internally, so the value was ignored at best. Temperature in **Settings → AI & Chat** and **Settings → Coding Agent** now defaults to **Auto**: no temperature is sent, so each model uses its own intended default (GLM-5.2 ships with 1.0, DeepSeek recommends 0.0 for coding). Set a value and it's honoured only for models that support temperature control — the control shows when a model declares it can't take one, and the request omits the field entirely (matching opencode's capability gate).
