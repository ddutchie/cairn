## What's new in Cairn 3.0 — Unified Runtime

Cairn 3.0 is a foundation rebuild rather than a patch cycle. Chat, coding, automations, and every one-shot helper (writing style, PRDs, commit-message drafting) now run on a single **Cordis + DeepSeek Harness (dsh)** engine, sessions become portable views you can pop out and rebind, and the surrounding shell tightens up to match. The dozens of "fixes" that accumulated on this branch are the surface of that unification — not a list of papercuts.

### One engine for everything

- **One agent runtime.** The coding agent, chat, automations, and one-shot flows share the same plugin-based runtime, session model, tool registry, approval seams, compaction, retry handling, and model adapter. What was three separate execution paths is now one Cordis composition.
- **Plan Mode is dsh-native.** `/plan` and `/plan off`, plan guidance, and the `exit_plan_mode` review are owned by dsh and flow through the standard question/approval seam at the next step boundary — not a Cairn-only overlay.
- **Commands and skills from one registry.** Cairn commands + plugin commands share a single executable namespace (`/plan`, `/compact`, …) and Cairn project skills + plugin skills are merged through dsh's skill catalog and tool.
- **Context is per-session, via dsh snapshots.** Workspace/project identity, descriptions, and code directories are supplied through the Cordis system-prompt context seam with proper per-session isolation, and the shared context ring, reasoning provenance, usage breakdowns, and todo state project from durable dsh state.
- **Smaller, explicit plumbing.** Loader-backed composition keeps plugin lifecycle, DI, and disposal inside Electron; the dsh type boundary uses upstream Context augmentations so API drift fails at compile time; attachments flow through dsh's content-addressed store with image normalization and bounded storage.

### One session, everywhere you look

- **Session logs are the transcript.** Chat and coding history resume from dsh's append-only JSONL log — no parallel SQLite message tables, no divergence, no lost tool calls across reloads. Resumable sessions, native compaction, request retries, subagent traces, token usage, todo snapshots, and plan state all survive the same replay path.
- **One `session:*` contract.** The live IPC surface is `session:*` (with `session:event` as the single raw event transport); chat keeps its `chat:stream` entry point while tokens, thoughts, tools, usage, completion, errors, subagents, and questions share the same channels and answer path. The old flattened `session:token` / `session:thought` / `session:tool` … fan-out is retired.
- **Pop-outs are session-bound views.** A pop-out exchanges only a session id and reloads the shared JSONL history — it no longer copies Zustand state. It restores its own workspace/project/workdir profile, uses Cairn's custom chrome (same title bar as the main window), and brings live notification + automation counts with it. Chat and coding share the same pop-out controller, conversation pane, and header shells.
- **A session browser that stays put.** The dock and the chat header both expose a session switcher that lists Chat, Coding, and Terminal sessions per project; the inline sidebar browser keeps its place when you switch, highlights only the session you are actually viewing, and shows a truthful "running" pulse that reconciles crash-left mid-run sessions on startup. Pop-outs gain the same collapsible project/session panel and can rebind independently of the main window.

### Conversations you can steer and see through

- **Reasoning-effort control.** A pill next to the model picker (Auto / Off / Low / Medium / High, per models.dev) lets you steer thinking effort for capable models. Auto — the default — sends no override so the provider default applies, distinct from Off. The choice persists across restarts and threads through Cordis model selection without recreating the agent.
- **Per-message throughput & latency.** A compact stats line under settled messages (time-to-first-token, decode tok/s, output tokens) is captured live and folded from the durable log for both streaming and chat-completions transports — tool-wait and approval time excluded, no zero/NaN placeholders.
- **Protocol is pinned per provider.** Each saved provider declares its API protocol — Chat Completions (default), Responses, or Anthropic Messages — instead of auto-probing the endpoint. That keeps resumed sessions stable across restarts and removes the latency-doubling fallback that corrupted history when a session changed protocol mid-stream.
- **A context ring you can trust.** Live turns now emit the same full token breakdown that reload does (system prompt, tool definitions, tool outputs, conversation), and the fold uses the latest request's fixed overhead so multi-turn conversations no longer collapse to `0`. Ask-user questions render once, in the composer pane, instead of twice.

### A calmer shell and a sharper Overview

- **Rail is the default.** A single `UnifiedRail` header (44 px / 2.75 rem, window-centered `⌘K` with macOS inset, icon-only view tabs) plus a `DockSidebar` (48 px collapsed / 244 px expanded) replaces the double header. Health sparkline sits 20 px below Expand; stacks go Views → Conversations → Projects → pinned Workspace + Calendar. The `A · Rail` variant is now production-persisted.
- **Overview as instrument.** `⌘1` moves from seven drawers to an F-pattern instrument: editorial masthead with bottleneck insight, sticky Focus bar (All / Due today / Overdue / Pinned), four headline KPIs with hairline accents and WoW comparison, tappable attention queue, horizon task-flow bars with bottleneck callout, and keycap priority grid — sage tokens, knurled progress, tabular mono, offset-blur depth.
- **Health at a glance.** A 6-axis radar (Done / Momentum / Focus / Knowledge / Flow / Calm, 280 px, 0→1) with mini sparks in the dock (110 px card / 20 px dock icon) and on the project card (72 px), with soft shadows and tilt-on-hover lift.
- **Settings 14 → 8.** General holds Tags, AI holds Coding Agents (Chat/Agents tabs), Extensions holds Tools/Commands/Plugins, System holds Shortcuts/Data/About — each with sub-tabs and legacy deep-link mapping.
- **Palette & chrome refinements.** Command palette (`⌘K`) as a `640 px` instrument (52 px input, semantic pill, project capsules, `2 px` left accent), continuous `1 px --border` line at the top chrome seam, and responsive collapsing to a hamburger at narrow widths.

### Hardened and tested

- **Approvals through the runtime.** Sandbox mode, approval policy, session-scoped grants, per-ask nonces, fail-closed timeouts, and repeated-action protection run in the dsh pipeline. Shell execution uses the sandbox-capable executor; automation-development sessions regain their restricted toolset; chat no longer exposes destructive project tools without a coding-agent gate.
- **Boundaries restored.** Strict `window.open` / `app://` / `asset://` guards, base64 validation, per-IPC `sessionId`/`callId` checks, scoped approval nonces, CSPRNG fixes, and sanitized session paths.
- **Accessibility and polish.** Listbox roles, Escape-to-close, roving focus, drawer focus-return, reduced-motion affordances, live regions for busy/error states, and unified `tablist`/`tabpanel` semantics.
- **Real Electron QA on the shipped runtime.** An isolated-profile Electron suite exercises chat, coding, automation, attachments, tool calls, and persistence through the actual renderer→main→Cordis path, plus bundle guards in CI that ensure dsh packages stay bundled and live tests report skipped vs. passed honestly.
- **Clean cutover.** Pre-Cordis chat/coding indexes are reset on first run; new conversations start on the dsh model, and session artifacts are pruned by age.

> Cairn 3.0 starts new sessions on the new model. Existing workspaces are untouched on disk; pre-Cordis transcripts are archived before the legacy tables are removed.

### Merge-prep — Cordis parity fixes

Verified against the DeepSeek Harness (dsh) source and closed the gaps found in review before merge.

**Protocol pinned end-to-end (no more silent Chat Completions downgrade).** The coding agent now honours the saved provider's protocol (Chat Completions / Responses / Anthropic Messages) instead of always falling back to Chat Completions, matching chat. Both compaction paths (`/compact` and coding-session compaction) stopped live-probing the endpoint and pin the summariser to the same protocol the session was written under — the probe could never select Anthropic and risked corrupting a resumed session's history.

**Reasoning-effort works for coding sessions.** The effort pill (Auto / Off / Low / Medium / High) now actually steers the coding agent — it was previously a no-op there. Auto still sends no override so the provider default applies.

**Quieter, safer approvals.** Viewing a file with the editor tool no longer prompts for approval (its edit/create commands still do). The subagent tool is now correctly treated as shell-capable execution — approved per-use rather than offered a standing session-wide grant — and coding sessions default to workspace-confined access when a mode isn't specified.

**Clearer compaction outcomes.** `/compact` now reports how much history was summarised and surfaces specific, actionable messages when it can't complete (e.g. "inspect the current session state before retrying", "the session could not be saved") instead of a generic error.

**One-shot helpers honour the pinned protocol.** PRD generation, commit-message drafting, flow summaries, and writing-style analysis now use the saved provider's protocol like everything else — an Anthropic or Responses provider is no longer silently issued over Chat Completions.

**Tool cards show live state in reloaded transcripts.** A running tool with a custom view (e.g. skills) no longer renders as already-finished when viewed from history or a pop-out.



### Agent-loop diagnostics — coding turns fixed, latency made visible

Two reports ("coding agent just says *Agent turn ended abnormally (error)*" and "chat takes 13 s before tokens appear") turned out to share one cause: nothing was written to disk, so neither could be explained. Both are now diagnosable, and the coding failure is fixed.

**Coding sessions no longer die instantly.** Every coding turn was ending ~2 ms after it began. The doom-loop guard's reset hook was registered on `agent/pre-step`, which is a *waterfall* — dsh uses the listener's return value as the step decision — but the hook returned nothing instead of delegating, collapsing the decision to `undefined` and killing the turn before the model was ever called. It now always delegates. Its streak-reset also actually works: it inspected a field that does not exist on the payload, so a repeat-loop in one turn used to leak into the next.

**Failures say what went wrong.** dsh reports a structured `{message, code}` on a failed turn; Cairn discarded it and printed only the kind, so a plugin bug, an auth rejection, and a rate limit were all the indistinguishable string "(error)". The real message now reaches the transcript, internal errors are labelled as such (rather than looking like a provider outage), and interrupted/blocked/max-token endings read as themselves.

**A real log file.** Diagnostics went only to `console`, invisible in a packaged build and gone on restart. Cairn now keeps a rotating JSON log at `<userData>/logs/cairn-debug.log` recording per-phase turn timings for both chat and coding, the registered tool count, and the full reason for any abnormal ending.

**Latency is attributed.** Chat turns log where the time actually went — context build, workspace/git probe, tool registration, agent resume, then the model call — and, critically, split time-to-first-token into *Cairn assembly* versus *provider wait*, alongside prompt-token count and a retry counter. The coding path had no instrumentation at all and now has the same. On the reported 13 s turns this shows Cairn handing off the request in ~7 ms and the remaining ~15 s being spent upstream.


### Usage accounting corrected

Token and cost figures in the Usage view were inflated — by roughly **4x** on a multi-step turn, not the 2x an initial look suggested. Three separate places recorded the same turn, and the canonical one accumulated as it went: it wrote a row on every usage event carrying the running total, and since the Usage view sums rows, a four-step turn counted its prompt tokens four times over. One real turn was recorded as 59,186 prompt tokens and $0.272 against a true 13,623 and $0.069.

There is now a single writer, recording one row per model request with that request's own tokens — which sums correctly, because you are billed for the prefill of every request. Usage is also attributed to the right feature: every profile previously reported as "Chat", so Agent, Automation, and subagent rows were indistinguishable. Usage events carrying no tokens no longer create empty rows.

Historical rows are untouched, so totals spanning this release still include the old inflated figures.

### Coding agent: subagent traces appear again

The coding agent has always had the `subagent` tool and the UI has always been able to render child traces, but nothing connected them — the bridge was only ever wired up for chat, so delegated work ran invisibly. Coding sessions now show subagent traces the same way chat does.


### Chat & coding unified — chat gains MCP (gated)

Chat and coding were the same engine but two profiles and two renderers. Five of the seven bugs this cycle traced to that drift, not to external services. They now share one live path.

**One live renderer.** Chat drew its in-flight turn outside the message list (a `ToolCallIndicator` footer, a second tool-chip renderer); coding pushed a real streaming message into the list. Two renderers of one stream is why the empty-bubble bug hit only coding and why chat never gained the approval card, expandable tool output, or Open file / View diff. Chat's live turn is now appended to `messages` via the same `toLiveConversationMessage` helper the pop-out already used — one renderer, one empty-bubble guard.

**Chat has MCP, gated.** The P0-3 that blocked `registerExternalCairnTools` for chat ("would run ungated") is gone: chat now mounts the same HITL seam as coding (`cairnApprovalPlugin` + doom-loop guard, per-turn nonce, pending-ask reload recovery) and so can be offered MCP/service tools. The chat+code loops differ only in declared capabilities (tools + sandbox + plan mode); everything else is shared.

**Only EXTERNAL + EXEC gate in chat.** Cairn DB writes (notes/tasks) are chat's core job and auto-allow; deletions remain gated (even though they are `WRITE_LOCAL`, which chat otherwise allows). MCP/service calls and shell-ish tools ask. This is the risk-scoped policy chosen for per-workspace "Always allow".

**"Always allow" is workspace-persistent.** The first MCP call asks; "Always allow" grants it for the workspace permanently — the next session auto-allows without re-asking. Grants are one row per `(workspace, tool, target)` (target is the exact bash command for `bash`, otherwise the whole tool), mirroring automation standing rules (target-aware, exec refuses a wildcard grant) but scoped to a workspace. Intentionally device-local and **not synced** — a trust decision on one machine must not silently apply on another. Stored in a new `approval_grants` table (migration v54). The card's nonce + `pendingAsks` binding guarantees only the original ask's tool can be granted, and `recordPendingApprovalArgs` guarantees only the executed arguments are trusted.

**Deletes are gated, not blocked.** `CHAT_FORBIDDEN_TOOLS` (`delete_note`/`delete_task`/`delete_project`) existed only because there was no gate. Chat now has one, so deletes are offered with confirmation rather than hard-removed (they trash, not destroy).

**Shared layer no longer depends on chat.** `ConversationLiveToolCall`/`PendingQuestion` moved out of `useChatStream` into `conversation-message.ts` (compat re-exports kept); `MarkdownContent`/`ThinkingPanel`/`message-ui`/`QuestionForm` moved from `chat-panel/` into `conversation/` via `git mv` — the shared layer's only remaining imports are within `conversation/`.
