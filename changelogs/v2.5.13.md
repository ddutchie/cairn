## Fixes

- **Follow-up: linking a note to a task could still delete the note on macOS/Windows.** The v2.5.12 fix handled the common case but missed a case-insensitive-filesystem edge: when a note's stored folder or title differed only in **case** from its actual on-disk path (e.g. a note filed under `Research` whose `.md` lives in a `research/` directory), `writeNoteFile` recomputed a target path that differed from the existing one only by case, took the *relocation* branch, and then unlinked the "old" file — which is the very same inode it had just written, deleting the note. `writeNoteFile` now compares the two paths by real file identity (resolving case + symlinks via `realpathSync`, with a case-insensitive fallback) instead of an exact string match, so a case-only difference is correctly treated as an in-place rewrite and the file is never unlinked. Added a regression test covering the case-only-folder scenario.
