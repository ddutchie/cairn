## Features

- **Remaining-credit badges now work beyond OpenRouter.** The settings credit lookup previously probed a single OpenRouter-style `GET {base}/v1/key` endpoint, so only OpenRouter showed a balance. Community providers can now advertise a `credits` descriptor (a dedicated HTTPS endpoint + response shape) in the `providers.json` catalog, and the main process looks that up for the active endpoint and parses the reply accordingly. DeepSeek (via `GET /user/balance`, with its USD/CNY balance shown in the right currency) and OpenAI (via the legacy `credit_grants` endpoint) ship with descriptors; any provider that doesn't expose a balance API still gracefully hides the display.
- **Neuralwatt now shows a live balance too.** Its catalog entry gained a `credits` descriptor pointing at `GET /v1/quota`, and the parser reads the energy account's `credits_remaining_usd` / `total_credits_usd` / `credits_used_usd`. The credit-parsing logic moved into a small shared module, and the `cairn-community` repo gained a live endpoint test (`npm run test:credits`) that exercises every provider's balance endpoint against real keys (set them in `.env.test`).
- **Per-turn cost in the context ring.** Providers that report the USD cost of a call in their usage (`usage.cost` — Neuralwatt's energy accounting does) now surface that figure in the context-ring popover, alongside the token breakdown, so you can see what each message cost.
- **Account balance in the context ring.** The ring's popover now also shows a **Balance** row with your remaining credits for the active provider (`$5.42 of $45.5`, or "Free tier" for no-cost providers), refreshed at most once a minute so repeated ring instances share a single probe. It hides when the provider exposes no balance or you're offline, and is skipped on per-subagent rings (it's account-level, not per-turn).
- **New default model.** Fresh installs, resets, and unset-model fallbacks now use **`gpt-5.6-luna`** instead of `gpt-4o`/`gpt-4o-mini` as the default for chat, coding agents, notes AI actions, and flow summaries (the model picker still lists the endpoint's real models).
- **Model pickers now show cost and provider logos.** Every model dropdown (chat quick-settings, endpoint rows, saved-provider form) pulls live per-model data from the public models.dev catalog: the provider logo sits next to the model name, a compact **`$in/$out`** cost label shows the per-1M-token price (or "free"), and a warning triangle marks models known not to support tool calls. The same info appears on the closed trigger button, and logos adapt to the theme (light glyph on dark, dark on light).
- **Provider logos now match the model's own brand.** models.dev lists each model under every host that serves it, so the logo used to be whoever came first in the catalog (e.g. `deepseek/deepseek-v4-flash` could show an HPC AI or Cortecs glyph instead of DeepSeek's). Cairn now reads models.dev's canonical ownership list (`models.json`, keyed by `<provider>/<model>` id) and uses the model's actual owner for the icon — falling back to a brand-name heuristic and finally the catalog entry. Correct logos now appear for long-tail labs too (GLM, Grok, Qwen, Gemma, and more), even before the full catalog has loaded.
- **Saved providers show their community brand mark.** Installed community AI providers now display their real brand icon in the saved-providers switcher (trigger and dropdown) instead of the generic Server glyph. The logo is resolved from the community catalog by `communityId`, with a fallback to a normalized base-URL match — so a provider you added manually that happens to share an endpoint with a catalog entry (e.g. added before it was in the registry) gets its brand mark too. Providers whose hostname maps to a direct vendor models.dev serves (OpenAI, Anthropic, Google, DeepSeek, OpenRouter, Together, Groq, Fireworks, Neuralwatt, …) fall back to that models.dev logo when the community catalog has no inline `iconSvg` for them.
- **Image attachments are gated per model.** The chat composer's attach-image button is hidden when the selected model is known (via models.dev) not to accept image input; models we can't look up stay permissive. Pasting images is ignored too. Everything falls back gracefully offline or before the catalog loads.
- **Attach PDFs to chat messages.** The chat composer now accepts PDF files alongside images. Models known (via models.dev) to take PDF input receive the raw bytes as an Anthropic-style `document` part — lossless, and smaller for text-heavy files. Models that only take images get the PDF rasterized (pdf.js, up to 8 pages) into image parts instead, so the file still arrives. Attachments show as a PDF chip in the composer and the sent message, and the context-ring token count uses a size-based estimate for document parts rather than raw base64 length.

## Fixes

- **Chat settings no longer clip in narrow windows.** The in-chat quick-settings dropdown used inline positioning inside the chat panel's overflow container, so in a narrow window (or a docked panel) it could get cut off at the panel edge. It's now a portaled popover, so it always floats above the window edge.
