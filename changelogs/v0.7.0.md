# v0.7.0 — Knowledge Graph

## Overview

v0.7.0 introduces a workspace-level Knowledge Graph — a visual layer that reveals the relationships between all your projects, notes, tasks, and tags in one interactive canvas. This release also exposes the full relationship graph to the MCP and AI chat, enabling research-style traversal without manual querying.

## New: Knowledge Graph view

A new **Knowledge Graph** view (⌘5, or the branch icon in the sidebar) shows your entire workspace as an interactive graph.

### Two layout modes

- **Force Graph** — a 2D physics-based force-directed layout using Canvas/WebGL. Every node and edge is visible simultaneously; the physics engine clusters related entities naturally.
- **Radial Tree** — a hierarchical radial layout rooted at the workspace, branching out through projects → notes/cards → tags. Cross-project links are shown as chord overlays over the tree structure.

### Six relationship types

All existing connections in your workspace are surfaced as edges:

| Type | Source |
|---|---|
| Note ↔ Note | `linked_note_ids` backlinks |
| Note ↔ Task | `linked_card_ids` / `linked_note_ids` |
| Tag membership | `tag_ids` on notes and cards |
| Project membership | `project_id` FK (notes and cards → project) |
| IdeaFlow refs | `note_ref` / `task_ref` nodes in the Idea Flow canvas |
| IdeaFlow edges | Explicit directional edges drawn in the Idea Flow canvas |

### Auto-discovered relationships

Cairn now automatically computes three additional relationship types and caches them in the database:

- **Co-mention** — a note's content mentions another note's or task's title
- **Keyword similarity** — Jaccard similarity on tokenised title + content; edges drawn above a 0.15 threshold
- **Same assignee** — task cards sharing an assignee

Auto-relationships can be toggled on/off in the toolbar and recomputed on demand with the **Refresh** button.

> **Coming in v0.7.x:** AI semantic similarity using embedding vectors from your configured AI provider.

### Toolbar controls

- Layout toggle: Force / Radial
- Project filter: scope to one or more projects (workspace-wide by default)
- Node type toggles: show/hide projects, notes, cards, tags independently
- Edge type toggles: show/hide each relationship category
- Auto-links toggle + Refresh button
- Live node/edge count

### Detail panel

Clicking any node opens a slide-in detail panel showing the entity's title, type, project, snippet, priority/assignee/tags, and an **Open in [view]** button that navigates directly to the entity in its native view (Notes, Board, or Overview).

## New: MCP tools for AI research

Two new MCP tools give the AI assistant structured access to the knowledge graph:

### `get_knowledge_graph`

Returns the full workspace graph as `{ nodes, edges }`. Useful when the AI needs to reason about all connections at once.

```json
{
  "workspaceId": "...",
  "projectIds": ["..."],   // optional — scope to specific projects
  "includeAuto": true      // include auto-discovered relationships
}
```

### `get_neighbors`

Hop-by-hop traversal from any node. Returns the centre node and all connected nodes within `depth` hops. Enables efficient incremental research without loading the full graph.

```json
{
  "workspaceId": "...",
  "nodeId": "...",   // note, card, project, or tag ID
  "depth": 2         // 1–3 hops
}
```

## Technical

- New DB migration (v6): `relationship_cache` table with `(source_id, target_id, type, weight, computed_at)` and a `PRIMARY KEY (source_id, target_id, type)` for idempotent upserts
- Cache is invalidated automatically on note/card update via IPC handlers
- New `GraphSlice` in Zustand: `graphData`, `graphFilters`, `graphLayout`, `selectedGraphNodeId`
- New IPC channels: `db:graph:get`, `db:graph:neighbors`, `db:graph:recompute`
- Libraries added: `react-force-graph-2d`, `d3-hierarchy`, `d3-zoom`, `d3-selection`
- All graph colours use CSS variables — fully theme-aware (light + dark)
