## What's new

A small fix release for dashboards and due-date display.

### Fixes

- **Dashboards can embed external pages via `<iframe>`**: A dashboard containing an `<iframe src="https://…">` rendered blank. Two restrictions were blocking it: the app's Content-Security-Policy only permitted `blob:` frames, and the dashboard's sandbox ran in an opaque origin — so any nested iframe pointing at an external URL was refused. The CSP now allows `https:` frames, and the dashboard sandbox permits same-origin, popups, and forms, so embedded pages load and behave normally. Data access from dashboard scripts stays gated by the read-only tool allowlist, so nothing new is exposed.
- **Dashboards show "Dashboard" instead of "Empty note"**: In the notes list, dashboards always displayed the **Empty note** subtitle because their HTML content produces no plain-text preview. Dashboards now show **Dashboard** as their subtitle instead.
- **Overview due-date countdown is off by a day no more**: On the Project Overview, a task due yesterday could read **2d overdue** when it was only one day past. The day count parsed a bare `yyyy-MM-dd` due date as UTC midnight — which lands on the previous local day in western timezones — while the "overdue/today" label used timezone-safe parsing, so the two disagreed. The countdown now parses due dates as local calendar days too, so the number matches the label (e.g. **1d overdue**).
- **Completed tasks are no longer shown as overdue**: A task sitting in the **Done** column still displayed a red **Overdue** badge if its due date had passed. Cards in a done column now render their due date plainly, without overdue or due-today emphasis — the work is finished, so the deadline no longer applies.
