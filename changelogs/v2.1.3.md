## What's new

### Fixes

- **Windows arm64 build failure**: `@xenova/transformers` depends on `sharp` (native image processing library) which has no prebuilt binary for Windows arm64. The build attempted to compile `libvips-cpp` from source and failed with 108 unresolved linker symbols. Replaced `sharp` with a minimal stub (`electron/sharp-stub/`) that exports `null` — Cairn only uses text tokenization from transformers.js, never image processing, so the stub is a no-op. Transformers.js gracefully skips the image-loading path when `sharp` is falsy. Applied via npm `overrides` in `package.json` + `package-lock.json` so `npm ci` resolves correctly on CI.

- **Benchmark ceilings bumped for CI**: CPU-bound embeddings benchmarks (`topK`, `cosine`, `chunkLongText`, `averageVectors`) had p95 ceilings of 1ms that flaked on GitHub Actions runners (measured ~1.57ms). Raised ceilings to 2-10ms depending on operation — still catches catastrophic regressions while accommodating slower CI hardware.
