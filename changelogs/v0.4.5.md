# v0.4.5

## Dashboard template gallery

Clicking "New Dashboard" now opens a template picker instead of creating a blank note immediately.

- **Blank** — empty dashboard with a prompt to ask the AI (spans full width)
- **Project Health** — task counts per column with a live progress bar showing done/total
- **Daily Standup** — in-progress and in-review tasks for the current project at a glance
- **Priority Board** — open tasks grouped into urgent / high / medium / low lanes
- **Workspace Overview** — all projects listed with open and done task counts

All templates use the `window.cairn` bridge for live data and re-fetch automatically on `cairn:refresh` events, so they stay current as tasks change.

## Dashboard: Edit HTML

A new "Edit HTML" button in the dashboard header opens a full-screen CodeMirror editor overlaying the iframe.

- HTML language mode with syntax highlighting, theme-aware (dark/light)
- "Save & reload" writes the new HTML back and refreshes the dashboard
- "Cancel" discards changes and closes the editor
- CodeMirror is loaded dynamically — no bundle size impact until first use

## Dashboard: Fix with AI

When a dashboard throws a runtime JS error, the error overlay now includes a "Fix with AI" button alongside the existing dismiss button.

- Clicking "Fix with AI" opens the chat panel pre-filled with the error details and the current dashboard HTML
- The AI can then patch the dashboard HTML directly using `update_dashboard`
- The chat panel auto-focuses the input so the user can send immediately or add context

## `patch_note` tool

New tool available in both MCP and AI chat for surgical note editing without re-sending the full content.

```
patch_note(noteId, oldString, newString, replaceAll?)
```

- Finds `oldString` in the note and replaces it with `newString`
- Returns an error if `oldString` is not found — no silent no-ops
- Returns an error if `oldString` matches multiple times, unless `replaceAll: true` is passed
- Include enough surrounding context in `oldString` to make it unique (same discipline as file editing)
- Prefer this over `update_note` when editing a section of a large note — the LLM only needs to send the changed fragment, not the entire document
