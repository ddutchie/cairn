## What's new

### New

- **Chat/agent no longer 400s on providers that reject the `developer` role.** The system prompt was sent as `role: "developer"` for reasoning models on every provider not on an internal denylist — an unknown gateway (e.g. opencode's Console Go) would reject it with `unknown variant developer, expected one of system/user/assistant`. The `developer` role is now an **allowlist**: only OpenAI, Azure OpenAI, and OpenRouter `anthropic/`/`openai/` models get it, and every other provider falls back to the universally-supported `system` role. Reasoning still works either way — the `developer` role is only an instruction-hierarchy nicety.
- **The Estimates toggle is now "on = estimates shown".** The Usage view toggle is restyled to match the Knowledge Graph hulls toggle, and its meaning is no longer inverted — toggling it on (the default) includes rows whose cost is estimated from models.dev pricing, toggling off filters to provider-reported spend only.
- **Model picker: capabilities left, pricing right.** The model rows (open menu and closed trigger) now left-align the input-capability icons and push the per-1M price to the right edge, so long model names no longer squeeze the metadata.
- **Cache percentages are colour-coded by how good they are.** The "% of input cached" figures in the context ring and Usage view now scale from grey (no cache) → amber → accent → green as the cache-hit rate rises (≥50% cached is green).
- **Chat subagent rings show the full breakdown now.** Each research/write subagent's context ring in a chat turn gets the same per-category prompt split (system prompt, tools, conversation, …) and cache row that the agent's subagent rings already showed — pi parity for the chat subagent path.
- **Prompt-cache tracking now works on mobile too.** The mobile chat context ring shows a **Prompt cache** row (read/written tokens + % of input) whenever the provider reports cached tokens, with the same colour scale as desktop.
- **The mobile context ring survives upgrades and workspace switches.** The ring's last usage was stored in a per-workspace table that's wiped on the legacy→multi-source upgrade, so it reset to empty until the next reply; it now lives in the device-global meta store (with a one-time migration), so it's retained across upgrades and workspace changes.
- **Re-importing an Obsidian vault no longer silently clobbers your edits.** Cairn now tracks every adopted note's body in a per-workspace ledger and does a real 3-way check on re-scan (and on live file changes): if only the vault file changed, the file wins; if the note was edited **both** in Cairn and in the vault since adoption, the vault file is kept as current and Cairn's version is preserved as a **conflict copy** — it shows up in the same Conflict-resolution panel device-sync conflicts use, so there's one consistent "these two versions disagree" experience instead of silent data loss.
- **You can undo an import.** If you pointed Cairn at the wrong folder, the "found these projects" summary now has an **Undo import** action: it removes the projects and notes Cairn created, strips Cairn's frontmatter from the vault files (leaving your own Obsidian frontmatter and content untouched), and marks the folder as un-managed so it's never re-imported — without publishing deletions to your synced devices.
- **The Usage view shows provider logos.** Each model in the "by model" list and the history table now shows the provider's logo next to it, and the history table's Provider column shows the provider logo too; history rows also get a thin left border tinted with the model's colour, so models are scannable at a glance.
- **You can clear the recorded usage data.** A trash button in the Usage toolbar wipes the token/cost/request history for the current workspace (two-step confirm, styled tooltips on the toolbar actions) — useful for a fresh month or before handing a device over.
- **Task lists are tickable right in the editor.** `- [ ]` / `- [x]` items in Live Preview now render as real checkboxes — click to toggle, which writes `[ ]` ↔ `[x]` back to the note's source (same write path as read-mode toggling). Works for ordered (`1. [ ]`) lists too, and the raw marker stays editable when your cursor is on the line.
- **Every dropdown now shares one look.** The Usage source filter, chat/kanban/automation selects, kebab menus, and the project filter in Insights / Knowledge Graph / Calendar are all built on the same Radix dropdown primitives, so triggers and menus match everywhere — same panel, item size, hover state, and accent highlight for the active choice. The Project filter (previously a one-off hand-rolled menu) now also gets proper keyboard navigation, click-away handling, and focus rings for free.

### Fixed

- **Agent/chat tool calls no longer get cut off at a 4096-token output cap.** When "Max output tokens" was left on **Auto**, Cairn omitted `max_tokens` from the request — but the endpoint then applied its own server-side default (often just 4096), which reasoning models burned through and got truncated mid-tool-call ("Tool call not executed: the model hit its output-token limit"). Cairn now mirrors opencode: Auto always sends an explicit `max_tokens` cap — **bounded by the model's own declared output limit** from the models.dev catalog (a small model gets its smaller limit; larger models are capped at 32K, opencode's ceiling) so the model can finish naturally without 400ing the provider. A manual value is still respected.
- **A dropped closing delimiter no longer discards a complete tool call.** When a stream/gateway emits tool-call arguments that are complete except the final `"}` (e.g. a fully-streamed note body whose closing brace never arrived), the arguments are now **tail-repaired** — the missing closers are appended and the call executes with the content intact — instead of being refused and re-issued (which re-hit the same cap). Only genuinely ambiguous cuts (mid-structure, or valid-but-possibly-incomplete) are still refused, and genuinely chopped payloads remain "fail loud, never partially persist" except for the tail-repairable case.
- **Continuing a conversation no longer 400s after a tool call was truncated.** The refused truncated turn is never replayed into history (no truncated tool-call JSON, no duplicate/orphaned `tool_call_id`s), truncation-no-id fallbacks synthesize globally-unique ids, and internal reasoning round-trip metadata is stripped from every outgoing request.
- **The Usage log now records `finish_reason` per agent call**, so output-token truncations are diagnosable instead of silent.
- **Chat now round-trips chain-of-thought back to the model (pi parity).** The chat loop previously stripped reasoning entirely from the re-sent history, starving "thinking" models of their own prior reasoning on tool-call rounds. Streamed reasoning is now re-sent to the **same** model under its native field (e.g. `reasoning_content`) and folded into text when the model changes — matching the coding agent and opencode. The on-device Llama path still strips it (local models reject a reasoning field).
- **The Agent view now matches the Chat view's styling and busy state.** The agent pane's background is the same lighter `surface` tone as chat, and the agent now shows a spinner (and "Working…" chip in the message list) while it's busy, like chat does.
- **Agent and chat tabs got distinct, correct icons.** The Agent tab now uses a code icon (`Code2`) across the top bar, session tab, and "New agent session" menu — and the Chat session tab uses the chat icon (`MessageSquare`) instead of the sparkles it had before.
- **A provider · model picker is now always in reach.** A compact "who am I talking to?" control shows the active provider and model and opens a dropdown to browse **every connected provider** and switch model on the fly — rendered above the input box in Chat, the Agent pane, and the Overview's pinned chat input (shown when the chat panel is collapsed), so you can switch mid-typing. The input hint text ("Shift+Enter for new line · Enter to send") is now identical across Chat and Agent. The chat quick-settings popover no longer duplicates provider/model — it keeps max steps, temperature, and subagents only.
- **The coding agent now accepts image/PDF attachments** (matching chat). The agent input gates the attach button on the selected model's vision/pdf support, staged images/PDFs are serialized to content parts and sent with the prompt through the agent loop, and the transcript shows the attached thumbnails. The whole input is now a single shared component — `ChatInputArea` (input + attachment staging + provider · model picker + status line) used by Chat, the Agent pane, and the Overview launcher — so the surfaces can't drift; file→dataUrl/PDF-rasterization lives in one shared helper.
