## What's new

### New

- **Chat/agent no longer 400s on providers that reject the `developer` role.** The system prompt was sent as `role: "developer"` for reasoning models on every provider not on an internal denylist — an unknown gateway (e.g. opencode's Console Go) would reject it with `unknown variant developer, expected one of system/user/assistant`. The `developer` role is now an **allowlist**: only OpenAI, Azure OpenAI, and OpenRouter `anthropic/`/`openai/` models get it, and every other provider falls back to the universally-supported `system` role. Reasoning still works either way — the `developer` role is only an instruction-hierarchy nicety.
- **The Estimates toggle is now "on = estimates shown".** The Usage view toggle is restyled to match the Knowledge Graph hulls toggle, and its meaning is no longer inverted — toggling it on (the default) includes rows whose cost is estimated from models.dev pricing, toggling off filters to provider-reported spend only.
- **Model picker: capabilities left, pricing right.** The model rows (open menu and closed trigger) now left-align the input-capability icons and push the per-1M price to the right edge, so long model names no longer squeeze the metadata.
- **Cache percentages are colour-coded by how good they are.** The "% of input cached" figures in the context ring and Usage view now scale from grey (no cache) → amber → accent → green as the cache-hit rate rises (≥50% cached is green).
- **Chat subagent rings show the full breakdown now.** Each research/write subagent's context ring in a chat turn gets the same per-category prompt split (system prompt, tools, conversation, …) and cache row that the agent's subagent rings already showed — pi parity for the chat subagent path.
- **Prompt-cache tracking now works on mobile too.** The mobile chat context ring shows a **Prompt cache** row (read/written tokens + % of input) whenever the provider reports cached tokens, with the same colour scale as desktop.
- **The mobile context ring survives upgrades and workspace switches.** The ring's last usage was stored in a per-workspace table that's wiped on the legacy→multi-source upgrade, so it reset to empty until the next reply; it now lives in the device-global meta store (with a one-time migration), so it's retained across upgrades and workspace changes.
- **Re-importing an Obsidian vault no longer silently clobbers your edits.** Cairn now tracks every adopted note's body in a per-workspace ledger and does a real 3-way check on re-scan (and on live file changes): if only the vault file changed, the file wins; if the note was edited **both** in Cairn and in the vault since adoption, the vault file is kept as current and Cairn's version is preserved as a **conflict copy** — it shows up in the same Conflict-resolution panel device-sync conflicts use, so there's one consistent "these two versions disagree" experience instead of silent data loss.
- **You can undo an import.** If you pointed Cairn at the wrong folder, the "found these projects" summary now has an **Undo import** action: it removes the projects and notes Cairn created, strips Cairn's frontmatter from the vault files (leaving your own Obsidian frontmatter and content untouched), and marks the folder as un-managed so it's never re-imported — without publishing deletions to your synced devices.
