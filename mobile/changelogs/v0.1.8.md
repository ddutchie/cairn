## What's new

### Added

- **Choose a font for your note text.** Pick between Sans (the default), Serif, or Mono for note content — the editor, the preview, and PDF exports all use the chosen font. UI chrome stays on the system font. Set it in Settings → Appearance ("Note font"). System font stacks are used throughout so exports render identically on every platform.
- **Chat themes.** Re-skin the chat surface with full distinct looks — each theme bundles its own chat font, a background treatment (solid, gradient, or scanline pattern), a bubble style (filled, glass, or outlined), and a dark/light palette. Five built-in themes ship out of the box (Default, Paper, Terminal, Midnight, Aurora), and more arrive over time from the cairn-community catalog — no app update needed. Pick one in Settings → Appearance ("Chat theme"). Accent colour and note font are independent of the chat theme.

### Changed

- **The assistant now remembers its reasoning across turns.** Multi-turn conversations and agent tasks round-trip the model's chain-of-thought between requests — reasoning items on the Responses API, and the `reasoning_content` field on DeepSeek/OpenRouter-style Chat Completions — so follow-ups continue from the prior thinking instead of starting over. Longer conversations and multi-step requests stay more consistent as a result.

### Fixed

- **The chat agent no longer stops after its first tool call on the Responses API.** A turn that ended on a function call was reported as "finished", so the model's follow-up reasoning over the tool result never ran. It now continues the loop, and falls back to Chat Completions if the endpoint doesn't actually serve `/responses`.
- **Thinking blocks match desktop.** Reasoning auto-collapses the moment the answer starts streaming (instead of staying expanded for the whole turn), renders when the model returns only a condensed summary, and is ordered tools → thinking → answer like the desktop chat.
- **Copy on a chat reply copies just the answer text**, matching the desktop copy button.
- **The image-attach button respects the model on Responses providers too.** When chat runs through `/responses` with a catalog model that doesn't accept images, the attach button is hidden just as it is for the Chat Completions provider.
