## What's new

Polish for the workspace switcher and Knowledge Graph controls.

### New

- **Save and switch between AI providers**: In **Settings → AI**, the OpenAI-compatible backend now lets you save several named connections — each with its own name, base URL, API key, and default model — and switch between them with a tap instead of retyping your endpoint each time. Save one for OpenAI, another for OpenRouter or a local server, and flip between them from the row of provider chips; the active one fills the fields below and is used for chat. Add a new provider, rename it, or delete it right from the settings screen. Each provider's API key is stored securely in the device keychain (never synced), and your existing endpoint carries over automatically as your first saved provider — nothing to reconfigure.
- **The assistant can search and read the web**: Chat can now go beyond your notes and tasks to answer questions about current events, external facts, and documentation — it searches the live web and can open a result to read the full page, citing its sources as links. Add a web provider from the new **Settings → AI → Tools & Services** screen — connect **Tavily** (sign in, no key to copy) or add **Brave Search** with an API key. Credentials are stored securely in the device keychain and never sync. Works with any chat backend (Apple Intelligence, Rork, or OpenAI-compatible).
- **Add community services and see the assistant's tools**: A new **Settings → AI → Tools & Services** screen lets you browse Cairn's community connector catalog and install HTTP services (like **Brave Search**) with just an API key — no app update needed, and an installed service works in every project on your device. Each installed service has an on/off switch so you can silence one you don't want the assistant to reach for. The screen also lists Cairn's built-in tools (collapsed, grouped into Read and Write) so you can see exactly what the assistant can do with your notes and tasks — these are always on and match the desktop app. Services and toggles live only on your device and never sync; API keys are stored in the device keychain.
- **Connect MCP servers to the assistant**: Tools & Services can now also install **MCP servers** from the community catalog — including ones that need you to sign in (OAuth). Tap **Connect**, approve access in the browser, and the server's tools become available to the assistant in chat (across every project on your device). Each connected server shows its tools in an expandable list, each with its own on/off switch, plus a refresh to re-discover tools; sign-in tokens are stored securely in the device keychain and never sync, and you can sign out or remove a server anytime. Connectors show their brand logo. (Streamable-HTTP MCP servers are supported. A few providers only allow sign-in from a pre-registered desktop app and can't be connected from mobile yet — the screen notes this.)
- **Export a note as a PDF**: The note menu now has an **Export as PDF** action alongside Export as Markdown. It renders the note into a beautifully formatted PDF — the same layout, typography, code blocks, tables, and callouts as the desktop PDF export (following your light/dark appearance) — then opens the system share sheet so you can Print it, save it to Files, or send it via Messages/Mail/AirDrop. Callouts (`> [!note]`, `[!warning]`, etc.) and `[[wikilinks]]` render with the same styling as desktop.
- **Long-press a note to move, pin, or delete it**: Press and hold any note in a project's Notes list to open a quick actions menu — **Pin/Unpin**, **Move to project**, **Move to folder**, or **Delete** — mirroring the note menu on desktop. "Move to project" and "Move to folder" open a picker of your other projects / this project's folders. This is the first way to move a note between projects on mobile (there was previously no manual way to do it at all).
- **Project Overview on mobile**: Opening a project now starts on a new **Overview** tab (alongside Notes and Board) that gives you an at-a-glance snapshot — a completion ring, note / open-task / overdue counts, a breakdown of tasks by column and by priority, what's due soon, your pinned and recent notes, and a recent-activity feed. Tapping anything jumps straight to it. This mirrors the desktop project Overview.
- **Drag to reschedule on the calendar**: Long-press a task on the calendar and drag it onto another day to change its due date — the same lift-and-drop gesture as the board. There's also a new **Unscheduled** tray at the bottom listing tasks with no due date: drag one onto a day to schedule it, or drag a dated task into the tray to clear its due date. Available on both the workspace and per-project calendars.
- **Merge sync conflicts instead of only picking a side**: When the same note was edited on two devices at once, the Sync Conflicts screen previously only let you keep one version and discard the other. It now has a third option — **Merge** — that combines both edits. Non-overlapping changes (e.g. you added one checklist item on your phone and a different one on the desktop) are merged automatically into a single note using the common ancestor. When the two devices changed the *same* lines in different ways, an editable box opens with the best-effort merged text so you can reconcile it by hand — Cairn never injects `<<<<<<<` conflict markers into your note.
- **Pull to refresh the project Overview**: Pull down on a project's Overview tab to reload its snapshot — counts, due-soon, pinned and recent notes, and the activity feed — matching the pull-to-refresh already on the Projects list and Search.

### Improvements

- **Search and scroll through models**: In **Settings → AI** (OpenAI-compatible), fetching models now shows a search box and a scrollable list instead of a wall of chips — so providers that return 50+ models (like OpenRouter) are easy to browse. Type to filter by name, and the list shows how many match; your currently-selected model stays pinned in view. Tap any row to pick it.
- **See your provider's remaining credits**: When a provider reports a credit balance (for example OpenRouter), the AI settings now show a "credits left" card above the model picker — the remaining balance, plus the amount used and your limit. It's fetched alongside the model list and stays hidden for providers that don't expose credits. Your API key never leaves the device except to your chosen endpoint.

- **Search & filter the community catalog**: The Tools & Services screen now has a search box and category chips (Dev & Code, Finance, Search & Web, and so on) that filter both the installable services and MCP servers at once — matching the desktop Browse Community experience. As the catalog grows, finding a specific connector is much quicker.
- **Services can bundle several tools**: An installed service from the community catalog can now offer multiple related operations — each its own tool — sharing one connection and API key, shown as an expandable list with a per-tool switch (like MCP servers). For example, Hacker News now offers both "search" and "search by date". Existing single-tool services are unchanged.
- **Chat shows tools while they're running**: When the assistant uses a tool — especially a slower one like a web search or an MCP call — its chip now appears immediately with a spinner and updates when the result arrives, instead of only showing up once the tool had already finished. So you can see what the assistant is doing in real time.
- **Tidier Knowledge Graph header**: The label-density control now lives in the top-left of the header (a native menu) instead of taking up space in the in-graph toolbar, and the Semantic-links toggle now sits next to the Hulls toggle — so the graph controls fit better and read more clearly. The Semantic toggle also shows a spinner while it computes connections (which can take a moment on device).
- **Snappier graph toggles**: Toggling semantic links, cluster hulls, or label density now updates the graph in place instead of rebuilding the whole visualisation each time — no more full redraw / layout restart, so the controls respond immediately.
- **Calendar day selection matches desktop**: The selected (and today's) day are now shown with a soft accent background wash instead of an outline, so the grid reads more cleanly.
- **Tasks now show up in the graph's semantic links**: With the Knowledge Graph's Semantic-links toggle on, meaning-based connections now include tasks — related cards link to each other (**task↔task**), and a note links to a card about the same topic (**note↔task**), not just note-to-note. Recomputed automatically as your notes and cards change.

### Fixes

- **Clearer message when an MCP server needs desktop sign-in**: Some providers (e.g. Asana) only accept an OAuth sign-in from a desktop app and reject the mobile connection. Instead of a cryptic technical error, Cairn now explains it plainly — "{Provider} doesn't allow sign-in from a phone … connect it in the Cairn desktop app instead" — under a "Connect on desktop" heading.

- **Knowledge Graph no longer goes blank after the app was backgrounded**: On iOS the system can terminate a web view's content process while the app is in the background (to reclaim memory), which left the Knowledge Graph (and, more rarely, rendered math/diagram blocks in notes) blank until you fully restarted the app — in-app navigation didn't recover it. Cairn now detects the terminated content process and reloads the view automatically, so the graph and note diagrams come back on their own.
- **Chat opens at the latest message and stays the right size**: The Chat transcript now jumps to the newest message when you open the tab (and when the app resumes), instead of sometimes opening scrolled to the top and only snapping down after you sent a message. The message list also gets a stable height so it tracks content correctly rather than mis-sizing under the keyboard/composer.
- **No more ghost bands after reopening Chat**: Returning to the Chat screen after the app had been backgrounded could briefly show faint vertical bands over the messages (an iOS snapshot artifact from the frosted composer). Chat now repaints on resume so they no longer appear.
- **Chat scrolls correctly after the app returns from the background**: After backgrounding and reopening the app, the chat transcript could get stuck at the wrong height — you couldn't scroll the conversation up above the keyboard until you fully quit and relaunched. The resume repaint now refreshes only the messages, not the whole scroll view, so it keeps its measured size and scrolls correctly right away.
- **Reschedule overdue tasks by dragging**: Overdue chips in the calendar's overdue tray can now be long-pressed and dragged onto a day (or into the Unscheduled tray) to reschedule or clear their due date — same as tasks in the grid.
- **Consistent calendar header**: The Today and Month/Week controls now sit in the top navigation bar on the per-project calendar too, matching the Calendar tab — the calendar looks the same however you open it.
- **Chat attachment icon stays put**: The image-attachment button in the chat composer no longer jumps up out of place after you tap it while the keyboard is open — it's now a plain button (opening a native photo action sheet) that rides the keyboard exactly like the send button, instead of a native menu control that anchored to the screen and drifted when its menu opened.
- **Chat keeps the latest message visible with the keyboard open**: The conversation now sits just above the keyboard (and the composer) instead of leaving the last message hidden behind it, using a purpose-built keyboard-aware scroll view.
- **Context ring persists across the Chat tab**: The context-window usage ring now restores when you close and reopen Chat, instead of disappearing until the next message (the last usage is saved on-device).
- **Expanding reasoning no longer jumps the chat**: Tapping to expand a past message's "Reasoning" block no longer scrolls the conversation to the bottom — the transcript only auto-follows new content when you're already near the end (and still jumps to the latest when you focus the input or send).
- **Assistant semantic search matches the Search tab**: The chat assistant's meaning-based note search now indexes any new/edited notes first (like the Search tab does) and ranks results the same way, so it finds recently changed notes and surfaces the best match — previously it could search a stale index and miss them. Results are also merged and ranked across all notes before being trimmed, so a strongly-relevant note can no longer be dropped for being outside an early per-batch cutoff.
- **Keyboard no longer gets stuck open**: Sending a message (and leaving the Chat tab) now reliably dismisses the keyboard, so it no longer occasionally stays open until you switch apps and back.
- **Chat links to notes/tasks are collision-proof**: When the assistant links a note or task it now uses the item's exact id (still shown as the title), so a link can never open the wrong item when two share the same title.
- **Completed tasks are no longer flagged overdue**: A task in a Done column with a past due date is no longer shown in the calendar's overdue tray (it still keeps a chip on its due day).
- **Workspace switcher is always the Cairn icon**: The switcher in the top-left of the Projects screen no longer occasionally flashes the word "Workspaces" in place of the icon.
- **Drag near an edge to auto-scroll**: While dragging a card on the board or a task on the calendar, holding near the top/bottom (or left/right) edge now auto-scrolls the list so you can reach columns, days, or the Unscheduled tray that are off-screen. Drop targets stay accurate as the list scrolls.
- **Callouts render correctly in dark and light mode**: Callout blocks (`> [!note]`, `[!tip]`, `[!warning]`, etc.) now use the same surface-anchored fill, muted border, and per-type icon as the desktop app, so they look right on both themes instead of washing out. Added the missing callout aliases (`caution`, `check`, `done`, `faq`, `cite`) and matched their colours to desktop (e.g. `question`/`faq` now use the accent colour). Plain blockquotes and `==highlight==` now match the desktop colours too.
- **Quote blocks are no longer a white box in dark mode**: A plain blockquote (`> …` without a callout type) was showing as a light-grey box with unreadable text on the dark theme, because it fell back to the markdown library's built-in light background. It now uses the themed border with no fill, so it's readable on both themes.
- **Dead wikilinks no longer open an empty note**: A `[[wikilink]]` that points to a note (or task) that doesn't exist now renders **dimmed and greyed-out** (matching desktop) instead of looking like a live link — and tapping it does nothing, rather than navigating to a blank note screen. Working wikilinks are shown as an accent-tinted chip and still navigate to the right note or task.
- **Folders that differ only in capitalisation are now merged**: Notes filed under `Mobile` and `mobile` (or `Mobile/AI` and `mobile/ai`) were listed as two separate folders. They now collapse into one — matched case-insensitively, keeping the first casing seen as the folder's name. The assistant's folder list dedupes the same way.
- **Reschedule uses timezone-safe dates**: The project Overview's "due soon" list now compares due dates by local calendar day (matching the rest of the app), so a task due today is never shown a day early/late in some timezones.
- **Sync screen tidied up**: Removed the duplicate workspace picker from the Sync screen — switch workspaces from the Cairn icon in the Projects header. The Sync screen now focuses purely on sync status, iCloud availability, and conflicts.
- **The assistant no longer silently loses a note's content on a malformed edit**: On the on-device (Apple) model, if the assistant emitted slightly-malformed JSON for a note write (for example markdown with real line breaks in the middle of the text), the app previously ran the tool with *empty* arguments — silently creating or overwriting a note with no content. The assistant now parses those arguments the same forgiving-but-lossless way the desktop app does (fixing only unambiguous JSON formatting slips, never changing your actual text), and if it still can't parse them it reports the error back to the model to retry instead of writing an empty note.
- **Tap web results straight from chat**: When the assistant runs a web search (or another external tool that returns a link), its tool chip is now tappable and opens that page in your browser — the same way note/task chips open in-app.
- **See exactly what differs in a sync conflict**: The Sync Conflicts screen used to show the original note and the conflicted copy as two plain text previews, leaving you to spot the difference by eye. It now shows a unified diff — lines only in the copy are highlighted green (+), lines only in the original red (−), unchanged lines dimmed — with a count of what changed, and says so plainly when the two bodies are actually identical.

- **Open notes and tasks straight from chat**: Chat is now far more reliable at jumping to what it mentions. When the assistant creates or touches a note or task, its little tool chip is now tappable and takes you straight there. `[[Wikilinks]]` in replies now open **tasks** too (not just notes), and both are matched to the exact item at the moment they're shown — so taps no longer occasionally open the wrong item or quietly do nothing.

- **The assistant can now manage tasks and organise notes**: Chat gained several tools it was missing — it can open a task's full detail, edit a task (including moving it to another column, changing priority, due date or assignee), rename a note (fixing links to it automatically), move notes into folders, **move a note to another project**, list a project's folders, and delete a note or task. Previously it could only read and create/append to notes and tasks.
- **The assistant's task search actually searches now**: Asking the assistant to find tasks matching some text used to return *every* card in the project (the search ignored the query), forcing it to sift through everything. It now filters by title/description like it should. It also gained a "what should I work on?" tool that lists only ready tasks — live, not done, and with no unresolved blockers.
- **Multi-word search now finds what you mean**: Searching notes or tasks previously required your whole query to appear as one exact phrase — so "auth flow" would miss "Authentication flow" or "flow for auth". Search (the Search tab and the assistant's note/task search) now matches when every word appears somewhere in the title or body, in any order. This matches the desktop behaviour.

- **The assistant's task search no longer drops matches.** When the assistant searched a project's tasks for text, the project filter was applied *after* an internal 50-row cap — so in a large workspace a project's matching tasks could be silently missed. The search now scopes to the project before the limit, so it reliably finds the project's matches.

### Accessibility

- Chat controls now expose proper labels to VoiceOver: the send button (with its disabled state), the attachment "remove" button, and tappable tool chips that open a note or task are all announced as buttons with descriptive labels.

- **Apple Intelligence works with more tools**: Some installed services (and any tool with an optional/nullable field in its schema) made Apple's on-device / Private Cloud Compute models refuse the whole request with an "unsupported schema type: null" error. Cairn now normalises those schemas to the types Apple accepts before sending them, so those tools work on Apple Foundation Models too.
- **Faster Tools & Services screen**: When a community catalog is already cached, the screen now shows it instantly and refreshes in the background, instead of blocking on a full-screen spinner. The catalog fetch also has a 20-second timeout so a hung network falls back to the cache rather than spinning forever.
- **Android API-key entry**: Installing a key-based service on Android now opens an in-app key prompt (Android has no native text-input alert), so key-based connectors can be added there too — iOS keeps its native prompt.

### Under the hood

- Multi-operation HTTP services: the shared service core + registry schema gained `baseUrl` + `operations[]` (path templating with `{placeholders}`, per-argument path/query/body placement, and connector-supplied static query params), so one connector can expose several tools over a real multi-endpoint API. Mobile builds one namespaced tool per operation and routes calls through the shared `resolveOperation` + `buildOperationRequest`, identical to desktop. Backward-compatible with existing single-endpoint services.
- Hardening from a code review: the registry schema now rejects service-operation `path`s that carry their own scheme/host (so a connector can't redirect a request off its pinned `baseUrl` origin); a failed MCP `connect` now closes the half-open client/transport instead of leaking it; malformed tool definitions on both desktop and mobile now return a clean error instead of throwing into the chat loop; and the service call error message reports the fully-resolved request URL. Added tests for the path-origin rule. Also gave the icon-only controls on the Tools & Services screen accessibility labels.
- Renamed the assistant's semantic-search tools to match the desktop app (`search_notes_semantic` / `search_tasks_semantic`), so both surfaces expose one consistent tool vocabulary. No user-visible change.
- Consolidated repeated UI patterns into shared building blocks (a uniform section-label style, priority/column chips, result rows, the not-found placeholder, the Markdown note editor, and refresh-on-focus / workspace-discovery hooks) so screens stay consistent and easier to maintain. No visible change.
- Moved the note section-splitter and vector-similarity math into shared code used by both the desktop and mobile apps, so semantic-search indexing and ranking stay identical across devices. No visible change.
- The board and calendar now share a single drag-and-drop engine (long-press to lift, on-thread hit-testing, a floating drag preview), so both feel identical and future drag features land in one place. The calendar's drop rules (which day / clearing a due date) are the exact same shared logic the desktop calendar uses. No visible change beyond the new calendar dragging.
- Chat wikilink resolution now happens at render time against the local database and bakes the concrete note/card id into the link (matching desktop), instead of matching by title on each tap — removing title-collision misroutes and silent no-ops. Shared `preprocessCairnMarkdown` gained an optional resolver + a `cairn://task/` scheme, covered by new unit tests.
- Trimmed the mobile chat system prompt (~224 → ~146 tokens). It no longer restates per-tool guidance the model already gets from each tool's description; a live tool-selection experiment confirmed the assistant picks tools just as reliably with the leaner prompt. Kept only the cross-cutting rules (get-context-first, never invent an id, emit `[[wikilinks]]`, confirm after writes).
- **Chat uses far less context per query.** Two fixes stop a single question from ballooning the conversation (which could crowd out history or, on the on-device model, overflow entirely): the project summary the assistant reads first now caps how many pinned notes and tasks it inlines (with short excerpts) instead of dumping everything, and reading a long note now returns its outline (headings + line numbers) so the assistant can pull just the relevant section via a new "read note range" step rather than loading the whole document. Pinned notes with headings are now summarised by that outline instead of a raw text excerpt — more meaning in fewer tokens.
- **Semantic search now covers tasks.** Meaning-based (on-device) search previously found only notes; it now finds **task cards** too. Search now has a ✨ toggle in the header for meaning-based ranking (**on by default** when your device supports it) and a simple **All / Notes / Tasks** type filter along the bottom — replacing the old three-way Notes/Tasks/Semantic switch, which mixed "how to rank" with "what to search". Semantic results (and keyword results) show a coloured left edge marking notes (blue) vs tasks (green) and open the right screen; the chat assistant also gained a `semantic_search_tasks` tool. So a conceptual query like "what's blocking the login work" can surface a card titled "Auth token refresh bug". Cards are embedded on-device and kept current automatically; the indexing readout counts notes and tasks together, and pull-to-reindex works from the empty semantic screen.
- **Graph semantic edges now pool notes and cards.** `semanticEdges()` combines note and card section vectors into one corpus (shared `EmbeddingRow` shape via the `card_id AS note_id` alias), so a single all-pairs pass produces note↔note, task↔task and note↔task edges. The graph screen's existing merge (keep edges whose both endpoints are nodes) and `card`-node routing needed no changes; cards are already indexed by `catchUpIndex`.
- Note and task semantic search now share one ranking pipeline (`rankSemantic`) parameterised by row source and id→text/title lookups, instead of two near-identical copies — so query-cache, centroid centring, hybrid dense+lexical rerank and slicing can't drift apart between notes and tasks. No behaviour change.
- Syntax-highlighting grammars (lowlight/highlight.js `common` set) now construct lazily on the first code block render instead of at module import, so app launch and the first notes/chat render don't pay the grammar-registration cost when no code is shown.
- Split the Chat screen — which had grown to one 800-line file mixing message rendering, the composer, keyboard/scroll choreography and tool-navigation logic — into focused pieces (a message bubble, reasoning disclosure, tool-chip trail, composer, a keyboard-scroll hook, and shared/unit-tested tool-navigation logic), and made it load its saved history only once on open instead of twice. No visible change; the chat behaves and looks exactly the same, but the code is far easier to change safely.
- Split the Calendar view (previously a single ~930-line file) into focused pieces — the month/week grid math, the day cell, task chips, the unscheduled tray, and the day-detail row — with the grid/date logic now covered by unit tests. Mobile logic tests are also wired into the shared test runner for the first time (the calendar date math and the drag auto-scroll helpers now run in CI). No visible change; the calendar looks and behaves exactly the same.
- Moved the on-device semantic-search index queries (note + task embeddings) out of the 1,600-line database-queries file into their own module, and factored the shared SQL fragments into one place. Purely internal reorganisation — every existing import keeps working via a re-export; no behaviour change.
- Continued splitting the database-queries file: the shared row/graph types, the knowledge-graph builder, the tag-id parser, and the breakout easter-egg sampler now live in their own small modules (re-exported so imports are unchanged). Purely internal, cycle-free reorganisation; no behaviour change.
- Split the AI-settings form into smaller pieces (the provider/reasoning segmented buttons, the labelled input field, and the Private-Cloud-Compute usage bar now live in their own files, sharing one style module). Purely internal; the settings screen looks and behaves exactly the same.
- Split the project detail screen — its note-row, folder-row, tab segment, filter bar and list-row helpers now live in their own files. Purely internal; the project's Overview / Notes / Board tabs look and behave exactly the same.
- Moved the Knowledge Graph's WebView document builder (the bundled D3 library plus the force-simulation and radial-sunburst rendering code) out of the 1,000-line graph component into its own file. Purely internal; the graph renders and behaves exactly the same.
- The "ready to work on" task list now resolves each task's blockers in a single batched database query instead of one lookup per blocker. Same result; fewer queries.
- The unscheduled-tray drop-zone registration and the sync-conflict diff view were made more render-stable (a memoised diff and a stable zone-ref callback), avoiding needless re-registration / recomputation. No visible change.
- Moved the tolerant tool-argument parser and the external-link extractor into shared code used by both desktop and mobile, so the assistant handles model JSON identically everywhere. The pure HTTP-service request-shaping (query/body building, argument coercion, response trimming) and the community-registry manifest validation were also moved to shared, laying the groundwork for mobile to consume the same connector catalog as desktop. Purely internal; no visible change.
- The mobile app now consumes the community connector registry directly: it fetches and caches the same `manifest.json` the desktop uses (validated by the same shared parser), stores installed services/servers and per-tool on/off toggles in a device-global local store, and resolves each connector's secret from the device keychain. Installed HTTP services run through the shared request-shaping core (the same one the desktop uses), so a connector behaves identically on both platforms. The built-in Tavily/Brave web-search code was removed entirely — web search is now just another registry connector (Tavily via MCP, Brave via an HTTP service), so there's a single definition of each instead of hardcoded copies.
- Mobile MCP support reuses the stock `@modelcontextprotocol/sdk` on-device: the streamable-HTTP client transport runs on Hermes with Expo's `fetch` injected (its response body is a real streaming `ReadableStream`, so the SDK's SSE/stream pipeline works unchanged). OAuth uses the same SDK `auth()` orchestrator as desktop, but — since a phone can't run desktop's loopback redirect listener — sign-in goes through a small hosted https redirect page that forwards to the app's `cairn://` deep link (via an in-app browser session), with a `crypto.subtle`/`getRandomValues` shim (backed by `expo-crypto`) so the SDK's PKCE works on React Native. Client registration uses Client ID Metadata Documents (CIMD / SEP-991) — a static JSON file describing Cairn as a public PKCE client — falling back to Dynamic Client Registration where CIMD isn't supported. Tool namespacing, tool→OpenAI conversion, result stringification, and the OAuth-callback parser were moved into shared code so desktop and mobile behave identically; discovered MCP tools are cached in the device-global store so the model's tool list stays synchronous while calls reconnect on demand.
